- **Feature: Host as a first-class axis**: The compiler now separates **codespace** (server / client / native: where the solver places and emits code) from **host** (browser, bun, cpython, bare-metal, ...: which runtime executes it and which platform capabilities are in reach). Capability evidence is keyed off the active host kind; `jaclang.jac0core.host` owns the capability table and target-to-host aliases.
- **Feature: BunHost sv services**: Microservice routes and standalone server modules can run on the **bun** host. The builder emits a `Bun.serve` artifact at `.jac/server/<module>.mjs`; stateless `def:pub` endpoints serve over HTTP, and root-touching walkers persist through **BunStore** (Postgres via `Bun.sql`). Select the host with a built artifact, `JAC_SV_<MODULE>_HOST=bun`, or `[scale.microservices.services.<name>.host]`.
- **Feature: `jac install --npm --server`**: Initializes and syncs the Bun server npm root at `.jac/server/` (private `package.json` plus `bun install`) so Bun-hosted services resolve npm dependencies without a system Node install.
- **Feature: P3 Host registry rows**: `web-worker`, `service-worker`, `edge`, and `cli-js` register on the Host registry with NPM and JS_GLOBALS capabilities and target aliases (`worker`, `sw`, `cloudflare-workers`, `cli_js`, ...). Build, dev, and start for these targets are reserved for a later phase; registration enables capability resolution and alias lookup today.
