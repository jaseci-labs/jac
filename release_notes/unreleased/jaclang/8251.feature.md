- **Native: jac decodes its own string literals, so `lit_value` lowers**: `String.lit_value` used to hand prefixed literals to CPython `eval` with an `isinstance(str_field, bytes)` narrowing, which made literal decoding a Python-only seam and shipped `String.lit_value` / `MultiString.lit_value` as abort stubs in `unitree`'s native artifact. `unitree.decode_string_literal` replaces it with one implementation both lanes run: quote-form and `r`/`b` prefix parsing, CPython's `str` escape set, and a separate byte-wise path for `b`/`rb`/`br` literals that masks octal escapes and refuses non-ASCII source the way CPython does. Uppercase prefixes stop being mishandled: `R"x"` used to fall past every branch and hand back its own source text, quotes and all. Malformed `\x` / `\u` / `\U` escapes now refuse instead of surviving as literal text, matching CPython. `\N{name}` is refused, because resolving a character name needs the Unicode name database the compiler cannot carry: the lexer reports the new `E0108` on the escape itself and points at `\uXXXX` / `\UXXXXXXXX`, and `\N` stays an ordinary backslash in raw and bytes literals exactly as in CPython. `tests/compiler/test_literal_decoding.jac` generates its corpus from the lexer and the parser rather than listing one, then differential-tests 12758 generated plus 61137 harvested literal forms against `eval`. Both seam waivers are gone from the unitree coverage tables.
