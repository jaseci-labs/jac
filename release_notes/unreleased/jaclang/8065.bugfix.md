- **`js-package` placement honors the project kind on every compile path**: `jac tool jac2js` (and any bare compile such as `jac check` or the language server) ran full-stack placement inference inside `kind = "js-package"` projects, so a `pub` function with no npm-import or JSX evidence was placed server-side and silently dropped from the emitted JavaScript, leaving only RPC-endpoint metadata for a server the kind declares can never exist; in the motivating VS Code extension the vanished export was `deactivate`, so cleanup never ran and nothing reported it. Only `jac build --as npm` was correct, because the npm builder forced the client codespace from the outside. The compiler now reads `[project] kind` itself: each kind carries a codespace roster entry (`js-package` maps to client), resolved per source file and applied after an explicit `force_codespace` but before inference, so tool and build agree by construction. The kind also joins the JIR module cache key, so editing `kind` in jac.toml correctly invalidates cached modules. Full-stack kinds keep endpoint inference unchanged.
