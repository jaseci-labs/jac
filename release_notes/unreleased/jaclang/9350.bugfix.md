- **Fix: `jac scale deploy` stops instead of shipping a literal `${VAR}`** (#8773): an unset environment variable in a `[scale.secrets]` or `[scale.kubernetes]` value was swallowed at config load and deployed as the literal text, so pods booted with `${OPENAI_API_KEY}` as their key and failed later inside the application, pointing at the provider rather than the deploy. Config loading now records every reference it could not resolve, and the deploy refuses to proceed when one of those values is about to be written into a Secret or a target setting, naming the setting that needs the variable. The check reads the values it is about to ship rather than a list of sections, so a variable that reaches a setting through `[apps.<name>]` or an active profile is caught the same way. Every other command keeps the `${...}` text and says nothing, so `jac check` and `jac fmt` never need deploy-time variables exported.
