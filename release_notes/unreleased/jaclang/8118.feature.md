- **Feature: a client test can mock an npm module**: Client tests run under bun in a temp dir with no `node_modules`, and every bare specifier was rewritten to a single self-returning Proxy, so a test could assert nothing about a dependency's behaviour. Each specifier now resolves through ordered tiers -- an explicit mock, then a `@jac/*` virtual module, then the Proxy -- materialized as a generated `tsconfig.json` that bun honours natively, so the emitted JavaScript is never rewritten and every import form resolves, including side-effect `import "pkg/theme.css"`, `export ... from "pkg"`, and a deferred `import("pkg")`. A mock is a file in `tests/__mocks__/` named for the spec it stands in for, or a `[test.client.mocks]` entry that overrides the convention; a JavaScript mock may keep helpers of its own, which are staged into the harness with it. Mocks may be written in Jac or JavaScript.
- **Feature: stubbing is reported instead of silent**: A specifier that reaches the Proxy makes assertions against it vacuous, so the run now names the specs it stubbed. `[test.client] on_stub` chooses `note` (default), `warn`, or `error` -- the last turns an accidentally unmocked dependency into a failure rather than a test that passes without checking anything. A bare `export * from` through a stub is called out separately, since a Proxy cannot forward names it does not know. `node:` and `bun:` builtins are left for bun to resolve and are never reported.
- **Fix: a profile no longer replaces a typed config section**: `apply_profile` assigned a profile's raw table straight onto the attribute, so `[environments.<name>.test.client]` swapped `test.client` from a `ClientTestConfig` to a plain dict and every consumer reading through it raised `AttributeError`. A table landing on a typed child is now applied key by key; attributes that are genuinely dicts are still replaced whole. `[build] native` had the same latent defect and is fixed by the same change.
