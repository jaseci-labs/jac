- **A syntax error is no longer reported once per import path** (#7960): a module that failed to parse was dropped before it reached `program.mod.hub`, so it was never cached the way a healthy module is. Every path that reached it in the same build -- the import walk, the type checker, the placement solver, the client-bundle interop worklist -- missed the cache, re-parsed the file from scratch, and appended another full copy of its alerts to the shared `errors_had`. One missing brace surfaced as N identical diagnostics in the dev-server error overlay, in `/__build_status`, and in editor diagnostics, with N tracking how many paths reached the module rather than being a fixed doubling; a client module importing a broken one reported 12 errors for a 6-error failure, and 18 on a cold cache. A partial module is now published to the hub under the same key a clean one gets, and the program records the failure so the client-bundle worklist stops asking a broken module for interop facts it can never produce -- previously "no facts yet" was indistinguishable from "cannot have facts", which sent the module back through the compiler on every pass. The entry is mtime-stamped and the record is cleared by `invalidate_module`, so a long-lived program -- the language server, or `jac start --dev` across an HMR reload -- still recompiles the moment the file is corrected. The duplication had been intermittent because a `.jir` written for the broken module served later reaches from disk and masked it until the next edit changed the content key.
- **HMR reloads no longer report a syntax error once per reload** (#7960): `errors_had` is append-only, so a long-lived program accumulated a full copy of a module’s alerts on every compile — a broken module reported 2 errors on the first HMR reload, 4 on the second, 6 on the third, because `meta_importer._module_scoped_alerts` scans the whole list. The HMR reloader now evicts a module through `invalidate_module` and drops its stale alerts before re-importing, so each reload reports the module as it currently stands. Eviction happens between builds rather than inside one, because several callers mark `len(errors_had)`, compile, and read back `errors_had[mark:]` — shrinking the list under that slice would make a failed compile report an empty error message. Boot-time duplication from a module compiled once for the server and again for the client bundle is not addressed here; it needs diagnostics owned per module rather than a shared append-only list.
