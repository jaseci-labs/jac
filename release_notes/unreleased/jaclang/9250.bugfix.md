- A static `@schedule` task never runs alongside an earlier run of itself: a tick that arrives while the task is still running is skipped, logged once, and left unclaimed for another replica, where before every tick started another copy (a 7 second task on a 3 second interval ran three at once). A server that is shutting down starts no new static runs once draining begins, and waits for the runs already going within what is left of `[serve.timeouts] drain`, naming any it has to abandon, instead of cutting every run in flight off as the worker exits.
