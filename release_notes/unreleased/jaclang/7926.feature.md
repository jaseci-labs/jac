- **Feature: GraphMend detection and graph-native trap lowering (`jac run --graphmend`)**: A new opt-in `--graphmend` / `-g` flag on `jac run` eliminates PyTorch 2 FX graph breaks at compile time. TorchDynamo falls back to eager execution whenever traced code forces a Python-level decision on tensor data, and each such break splits the compiled region. GraphMend detects the fixable break patterns under `torch.compile` entry points (decorated functions and classes, or call-site wraps like `torch.compile(Model())`, resolved through the symbol table) and lowers data-dependent validation guards: `if not mask.all(): raise ValueError(msg)` becomes a graph-native `torch._assert_async`, and `torch.equal` guards are rebuilt as tensor ops behind a static shape/dtype precheck, keeping the forward pass a single contiguous FX graph. Because a graph-native assert fails asynchronously at the call boundary, outside the traced region where no in-source `except` can reach it, the original exception type and message are folded into a compile-time marker and restored by an eager boundary decorator, so a failing guard still raises the exception the source declared. The passes run immediately before Python code generation, so the JavaScript and native backends see the original tree, and each pass self-gates on the flag, leaving normal compiles untouched. While the flag is active, bytecode caches are bypassed so transformed output can never be served to a normal run. Detection matches structurally rather than against unparsed text, so it works on plain `.py` model source (`jac run model.py -g`) as well as `.jac`. See [GraphMend internals](../../internals/graphmend.md) for the specification and the legality argument behind each rewrite.
