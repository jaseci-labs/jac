- **Fix: comparing a variable to a string literal narrows it**: `if v == "node" { ... }` with `v: str | None` no longer reports an error on using `v` as a `str` inside the guard, matching how `5`, `1.5` and `True` have always behaved.
- **Fix: `!=` against a literal no longer discards the whole type**: `if v != 5 { ... }` with `v: int | None` typed `v` as `None` over a real `int`. It now keeps `int | None`, and the same holds on the `else` branch of `==`.
