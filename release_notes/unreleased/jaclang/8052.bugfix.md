- **TypeCheck: an assignment whose RHS is a ternary or a short-circuit chain is visible to flow narrowing again** (issue #8059): `value = a if c else b;` at the end of a block (an `if` arm, an `elif` arm, a `while` body, a `try` body) never reached the statement after that block, so the write was invisible to the narrowing walk and every later `is not None` guard resolved against the pre-block view of the symbol. The symptom was E1053 on the guarded variable *inside its own guard*, reporting the declared union with `| NoneType` still in it. The cause is the CFG, not the walk: `exit_if_else_expr` and `exit_bool_expr` hang the sub-expression graph of a ternary or a short-circuit chain off the statement that holds it, so such a statement carries a `bb_out` whose every edge lands back inside itself (the ternary's arms are dead ends). `_connect_tails`, which carries a block's tail statement to whatever follows the block, tested for *any* outgoing edge and read that as "already wired". It now tests for an edge that **leaves** the statement, and emits the fall-through otherwise. Conditional statements keep the old test: `if a and b { ... }` links only to the short-circuit chain's entry, steering through exactly such an inward edge, and its arms are connected by `_connect_tails`' own recursion.
- **TypeCheck: unions assigned in an unreachable arm are checked again**: the same missing edge silently dropped diagnostics. Where one arm of an `if`/`else` ended in a ternary assignment, that arm's write never reached the join, so the walk saw only the other arm's type and a genuinely bad use of the union checked clean. Those uses are now reported, against the narrowed union.
- **TypeCheck: a typed declaration inside a block keeps its annotation** (issue #8060): Jac locals are function-scoped, but only bare assignments were bound that way; a typed declaration inside a `while`, `if`, `for`, or `try` body was inserted into that block's symbol table instead. One variable therefore became two symbols -- the declaration on the block, and a second one on the function created by whichever assignment rebound the name first -- so `item: (A | B | None) = None;` in a loop body followed by `item = pa(c);` / `item = pb(c);` in the arms of an inner `if` rejected the second arm with `E1001: Cannot assign B | NoneType to A | NoneType`, the first arm's type. The declaration now lands in the enclosing function scope, the same scope the assignments bind in, so every rebind is checked against the declared annotation and hoisting the declaration out of the block is no longer a workaround. Assignments the annotation does not admit are still reported, and module and archetype bodies keep their block scopes so version-guarded stub declarations continue to resolve per branch.
- **Newly diagnosed by the above (both were silently accepted before)**: a block-scoped declaration's annotation now holds *after* its block, since the name was always live there and only its type was being lost (`if c { z: int = 1; }` then `z = "oops";` is `E1001`); and two sibling blocks that each declare the same name are one variable, so the second declaration is checked against the first (`if c { v: (A | None) = A(); } else { v: (B | None) = B(); }` is `E1001`). The second shape is a redeclaration, which the language reference specifies as `E0064` ("a typed declaration after the name has already been bound in that scope"); `E0064`'s trigger is still limited to names that rebind an *outer* binding, so today it surfaces as an assignment failure at the second declaration. Give each variable its own name, or hoist a single declaration above the blocks.
- **Parser: `parse_assignment_with_target` returns `Assignment`**: the declared return was `CodeBlockStmt` while the single return path builds an `Assignment`, which is what `IterForStmt.count_by` requires. The over-wide signature only surfaced once the `step_assign: Assignment;` declaration in `parse_iter_for` stopped being stranded on its block. The generated `jac.spec` is byte-identical.
- **Native: `isinstance` against an imported class no longer demotes** (issue #8061): candidate vtables were enumerated from the archetypes the module being compiled defines, and every vtable global was emitted with `private` linkage, so a check against a class owned by another module found nothing to compare against and the whole call site fell back with `E5092`. Candidates now come from the layout registry's program-wide class hierarchy, an imported candidate's vtable is referenced as an external global sized from its defining module's layout, and the defining module's vtable global is externally visible so the reference resolves at link time. Object construction takes the same route, so an imported class instantiated by the importer now stores its vtable pointer instead of leaving the slot null, and the `match` class-pattern check shares the same candidate lookup. Method indices are deliberately not recorded for an imported class, so cross-module dispatch is unchanged. Measured on the `parser.jac` closure: 46 native seams down to 27, with every `isinstance` seam gone.
- **Native: a demotion names its cause instead of every read downstream of it** (issue #8062): when the right-hand side of an assignment could not be lowered, the native emitter reported that failure and then reported every later mention of the name it never bound as a fresh `E5092` -- once per read, each blaming a different expression kind (`Name`, `CompareExpr`, `IfElseExpr`, `UnaryExpr`, `BinaryExpr`). A single un-lowerable call therefore produced up to five diagnostics across four subsystems, and the demotion report a sealed build prints named symptoms rather than the one line to fix; the same noise put three of the epic's remaining seal blockers in front of the wrong backend surface. A failed binding now records the names it left slotless (walking tuple targets, and propagating through any binding that reads one of them), and a read of such a name is attributed to the binding instead of re-reported. On the `jac0core/parser/parser.jac` seal closure this takes the `E5092` sites from 167 to 154 with the set of demoted methods unchanged: every removed site was a consequence, and none of them was a lowering gap. Reads whose name a later binding did give a slot are untouched, so a genuine failure elsewhere in the function still reports.
- **Native: union-typed slot reads, comparisons and selects are pinned by value**: `is`/`is not None`, truthiness in condition position, and `a if c else b` over a slot holding a union all lower today, but nothing checked what they *produce*, and an unbox or select that drops the payload compiles cleanly and returns the wrong value. The new `union_slot_ops` suite exercises all three forms over both storages the union rule can pick -- a boxed `jacval` for a mixed member set, the first member's pointer layout for an all-pointer one, and `JacOpt` for `T | None` -- and reads the payload back on every path: the int member as itself, the str member as its negated length, a field off the object on the far side of a `x if isinstance(x, T) else None` select. Truthiness is checked against the falsy payloads (`0`, `""`, `[]`) that distinguish it from a none-tag test, and every function is additionally compared against the sv/bytecode result of the same fixture.
- **Native: `isinstance` against an enum class never lowered over a union** (issue #8067): an enum member boxes as its ordinal, so the check lowers to a jacval tag compare exactly when the operand's static union gives that enum sole ownership of the int tag. `_enum_union_tags` decided that by asking each union member `m.is_enum_class` -- the *uncalled* method (`ClassType.is_enum_class` is declared at `types.jac:172`; the same-named `is_enum_class` at `types.jac:139` is a field of the shared details struct). A bound method is always truthy, so every member classified as an enum owning tag 0, the sole-ownership test found a clash in every union of two or more members, and the tag path never fired on a union -- the only shape it exists for. A non-union operand produces a single row with nothing to clash against, which is why it read as working. A second gap fell out of the same loop: a union arm assigned an enum *literal* carries an `EnumMemberType` rather than the enum `ClassType`, and the loop bailed on the first non-`ClassType` member; classification now goes through `EnumMemberType.enum_class`, since both box as the ordinal. `isinstance(spec, Access)` over `Access | AccessNode | None` (and over `Access | bool`, where bool owns tag 7) now lowers and answers correctly for every arm, while `Access | int`, where `int` claims tag 0 as well, is still refused rather than answered with a tag compare that would report `True` for a plain int. The front end feels this directly: `unitree.jac` resolves symbol access with exactly this shape, and its native coverage drops from 47 seams to 17, taking the sealed parser's whole closure from 93 to 63.
- **Native: accessor (`{ getter; setter; }`) fields read a data slot nothing ever wrote** (issue #8074): a property has no instance storage -- Python's `property` is a class attribute, and Jac's own convention puts any backing store in a separately declared `has` (`_gen` behind `gen`, `_sym` behind `sym`) -- but the native backend gave one a data slot anyway and never emitted the accessor bodies at all. `nd.loc.orig_src` compiled to a load of the field's layout index, which on the sealed parser dereferences garbage and on an ordinary object returns a plausible, well-typed wrong value. An accessor-only `has` now contributes method slots (`<field>.__get__`, `.__set__`, `.__del__`) rather than a data slot, in the same central `LayoutRegistry` every unit reads, so the struct body, the exported marshalling layout and the rc trace functions move together; `impl Cls.field.getter` bodies lower like any method, including from an impl annex and for archetypes imported from another unit; and reads, writes and `del` route through the accessor, virtually where the class dispatches virtually, so an overridden property answers on the runtime class. A bare `getter;` names no signature, so the field's declared type stands in for the result and for a setter's implicit `value`, matching what the bytecode backend emits for the same declaration. Sealing the parser now surfaces 24 properties in `unitree` whose bodies are Python-only or hit a known backend gap -- they were invisible before because nothing lowered them -- each enumerated with its cause in `test_unitree_seal_baseline.jac`, and each shown unreachable from the sealed entry points by `test_sealed_seam_reachability.jac` rather than assumed so. Sealed-parser parity is still blocked, now on a single named defect (#8086): a field access through a reference typed as a non-primary base uses that base's slot offsets, so `AstSymbolNode._init_symbol` writes `self.name_spec.name_of` at `NameAtom`'s offset inside a `Name`. That write previously landed in one of the dead accessor slots this change removes, which is why it was survivable.
- **Native: every marshalled field of a class with a vtable read its neighbour** (issue #8084): `build_ctypes_classes` mirrored a native struct by appending the layout's named fields in order, never consulting `NativeFieldInfo.index`. The named fields do not cover every slot -- `LayoutPass._build_layout` reserves slot 0 for a vtable pointer on any class that has a parent, is a parent, or is an `isinstance` target, and a second slot for an OSP archetype's type tag -- so the first named field of such a class carries `index == 1` (or `2`), while the mirror placed it at byte 0. Every field of every such struct came back one machine word low: a Python caller reading `obj.x` got the vtable pointer, `obj.y` got `x`, and so on down the struct, as a well-typed wrong value that nothing diagnosed. Slots no `has` names are now mirrored by a pointer-sized filler, so a field's byte offset matches its layout slot. Classes with neither a vtable nor an OSP tag were unaffected, which is why the existing marshal fixtures never caught it. Surfaced while sealing the native parser, where `Module._in_mod_nodes` read `__sub_node_tab` and a parse of an empty module reported 0 nodes against the bytecode parser's 2.
- **Native: an explicit `return` in a `-> None` callable produced unparseable IR** (issue #8085): `-> None` lowers to an LLVM function returning `void`, but `_codegen_return` coerced the returned expression to the function's return type and emitted `builder.ret(val)` regardless, so `return None` became `ret i8* null` inside a `define void`. LLVM refuses to parse that, and the failure is module-wide: the whole compilation unit falls back to the server codespace with `E5020: LLVM IR parsing error`, so nothing in it lowers. Falling off the end of a `-> None` method was always fine, which is why only an explicit `return` with an expression hit it. A void function now emits `ret void`, with the expression still evaluated first so a `return some_void_call()` keeps its side effect.
- **Native: a method's receiver is a borrow, so `return self` now hands back a reference of its own** (issue #8088): `self` was bound as a plain named local and left out of `param_vars`, the set that marks the slots a frame does not own. Every emitter site that decides "this named local owns its value, so returning it moves that reference out" therefore said yes for the receiver, which owns nothing: `return self` (and `return (self, ...)`, which the return-tuple path treats the same way) skipped its retain and handed the caller a borrow where the calling convention promises +1. The caller's release of that "owned" result then dropped a reference nobody had taken. It reads as a container bug because a container is where it lands: `self.kid = [x.set_parent(self) for x in self.kid]` in `UniNode.postinit` retains each element into the new list and releases the call result, which nets zero when the call returned a borrow, so the rebuilt list held nodes it did not own and they were freed at the parse function's scope exit -- use-after-free reads whose victim moved with the heap layout. The receiver now joins `param_vars` at every binding site (plain methods, signature-less methods, event abilities), which is where the walker's `here`/`visitor` receiver already sat, and the two move-out sites retain like they do for any other parameter. In the parser's `JAC_RC_DEBUG_CODEGEN` ledger the same `Token` that used to reach `RC DOUBLE-FREE` at the end of its parse now settles at the count the tree implies.
- **Native: set and dict comprehension elements of archetype type get a pointer slot**: both comprehensions picked their element storage class off the *syntax* of the element expression -- a constructor call, a tuple, a field read -- and fell back to a raw `i64` for anything else, including a method call and the loop variable itself. A raw slot takes no reference, so `{x.self_ref(owner) for x in src}` and `{x.tag: x.self_ref(owner) for x in src}` stored their elements as bare integers and every element died with the source list. Both now widen to a pointer slot whenever the element expression's static type is an archetype, matching the list comprehension, which already consults the static element type first.
- **Native: constructing a class now runs its inherited postinit chain** (issue #8090): the constructor's postinit lookup only matched a method the class declared itself, so a class inheriting its postinit (unitree's `ElseIf(IfStmt)` shape, or any imported class whose postinit lives on an ancestor) silently skipped the chain -- `ElseIf.loc` stayed null and any `elif`/`else` parse on the sealed native parser aborted in `IfStmt.postinit`. The constructor now decides between explicit-init and generated-init semantics the way the bytecode runtime does (the first MRO class carrying its own `init` or its own has-fields decides; an explicit init owns its whole chain), and a generated construction dispatches the MRO-nearest `__post_init__` through the class-routed path that receiver-specializes the body when the owner is not layout-prefix-compatible.
- **Native: an optional payload inside a returned tuple segfaulted at the read, or refused to compile** (issue #8091): a tuple slot declared `T | None` is a JacOpt (presence tag plus payload) in the boxed tuple's layout, but the constructor boxed the value tuple with the layout its elements arrived in -- the bare payload pointer -- and bitcast the box to the declared type. Every later read decoded the declared layout against that memory: the payload pointer's low byte became the presence tag and the neighbouring slot became the payload, so a present payload was a garbage pointer by the time `__rc_retain` touched it (the repro faults at `0x1 - 16`, the bool slot read back as a pointer), and the box's destructor released slot 0 as a plain pointer besides. The same shear had a compile-time face: a value tuple that already carried a JacOpt element (`return (x, Box(...))` with `x: Box | None`) matched no boxing rule at all, so the raw value struct reached `ret` and failed LLVM verification. `_coerce_type_inner` now runs a value tuple through `_coerce_tuple_to_struct` against the declared pointee before boxing, so the box, its destructor, its trace fn, and every slot read agree on what each slot holds; element coercion is the existing JacOpt machinery, so a null payload wraps to the None form and ownership flags ride through unchanged. This is the sealed parser's `parse_from_path -> from_loc` shape: `import from x { y }` aborted the sealed parser before and parses at full node-count parity now.
- **Native marshalling: accessor fields are reachable through the bridge** (issue #8092): after #8074 removed accessor-only fields' data slots, a Python-side read of a `{ getter; }` field on a marshalled native object raised `AttributeError: 'CodeLocInfo' has no field 'mod_path'` -- the bridge only resolved names against the struct layout, so `unparse_module` on a sealed parse's Module could not even read its location. The layout now advertises, per class, the accessor symbol its dispatch binds (the same body the vtable slot holds), the seal exports those symbols from the artifact and proves each resolves in its load canary, and `NativeStructView` routes reads through the emitted `Cls.field.__get__` body -- marshalling the result exactly as a data field of that type would, including archetype-returning, str-returning, and optional accessors -- and stores through `Cls.field.__set__`. Dispatch is virtual: a vtabled receiver is re-keyed to its runtime class via the class-name constant in vtable slot 0, so an overridden accessor (e.g. `sym_name` on `NameAtom` vs `AstSymbolNode`) runs the right body even through a base-typed view. An accessor whose body ships as a waived abort stub is dropped from the advertised table, so reading it keeps raising the same `AttributeError` instead of aborting the process, and genuinely unknown names keep the existing error shape. Plain data-field reads pay nothing new.
- **Native: marshalled views read what the layout could not describe** (issue #8093): three metadata gaps left Python-side consumers of native trees reading wrong shapes. The layout's element keys did not survive optional (`(list[X] | None)`) or union-element (`list[(A | B)]`) annotations -- and even present keys were dropped at the optional unwrap -- so such list fields marshalled their elements as bare ints; an opaque generic slot (`has held: T`) decoded its object pointer as text instead of resolving it through the rc header's class-name stamp, the same authority `get_struct_view` re-keys views with; and the view's `keys()`/`items()` mapping helpers shadowed real node fields (`Import.items`) while having no consumers, so they are gone (`["field"]` and `in` remain). The pointer-store test also catches up with the marshalling rework's landed semantics: a store to a known pointer field still raises, while an unknown name lands on the view's Python overlay as annotation state instead of raising.
