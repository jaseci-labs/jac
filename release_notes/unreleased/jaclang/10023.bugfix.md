- **Fix: the Ops Console no longer grants its rights to every pod in the namespace**: with `ops_console = true` and no `service_account_name`, the console's Role was bound to the namespace's `default` ServiceAccount, so any pod that names no account of its own inherited it. The Role is now bound to a dedicated `<app>-ops` ServiceAccount that only the gateway runs as, and microservice pods keep `service_account_name` or the namespace default. Redeploying rolls the gateway once, and a gateway that relied on `service_account_name` for a cloud identity must pre-create `<app>-ops` with those annotations (see the Ops Console ServiceAccount section of the Kubernetes reference).
