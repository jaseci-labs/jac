- **Native: sealed native apps that call into Python now build and dispatch correctly (na->sv interop)**: `BoundaryAnalysisPass` computed `pinned_server` only for client-context callers, so a native-pinned module importing from a server-pinned provider never formed an na->sv binding -- the pin path now admits `InteropContext.NATIVE`. The module's native verdict is stamped once (`gen.native_codespace`) and every boundary consumer reads that single fact instead of re-deriving a narrower test, so stamping and analysis can no longer disagree under `aot_mode` with a native default codespace.
  **Breaking change**: with na->sv bindings now forming, the E5093 scalar checks enforce on them for the first time. `list`, `dict`, and other non-wire-typed parameters or returns on native->server signatures that previously compiled unchecked now fail the native build at compile time -- same-module `na{}` code reports E5093 as a hard error, and native-pinned modules demote to the server codespace with a diagnostic naming the offending signature. Retype the parameters/returns to ctypes-wire-compatible scalar types (or route through an explicit marshaling boundary). Non-callable imports of server-pinned types (`obj`/`enum`/`node`/`edge`) register as type bindings -- no fabricated callback signature -- and the app still refuses the standalone exe while the dependency on the server module exists.
