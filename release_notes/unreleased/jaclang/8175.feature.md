- **Static assets: `public/` is served at the web root, one URL law across every run mode**: a project's `public/` directory now resolves at the web root -- `public/brand/logo.png` is reachable at `/brand/logo.png` -- in vite dev, monolith `jac serve`, local `jac start`, and `--scale`, matching how Vite and Next.js serve it (#6876). Resolution used to be hand-rolled four separate ways (the monolith `serve_static_file`/`serve_root_asset`, the `--scale` gateway `serve_static`/`serve_project_static`/`serve_extra_static`, the embedded gateway `_serve_static`, and the admin console), so the same asset URL returned different bytes -- or a different 404 -- depending on the run mode. All of them now consume one shared resolver (`jaclang.runtimelib.serving.static_assets`: `asset_root_table` / `resolve_asset` / `asset_response`) that resolves a URL to a file against an ordered root table and builds the response through the existing `FileResponse` primitive, so a given asset URL returns the same bytes (or the same honest 404) everywhere, `static_mounts` keep their exclusive-ownership semantics, and the `/static/*` space (#6872) is unchanged. There is no longer an extension allowlist, so `.webmanifest`, `.wasm`, and any other file inside a declared root just work. Under `jac start -d` the Vite dev server now points `publicDir` at the project's `public/` so dev serves the same files natively; the build config still leaves `publicDir` disabled because the runtime serves `public/` from source rather than copying it into the client dist.
