- **Fix: a sealed aarch64 artifact carries the outline-atomics helpers its C floor calls**: The aarch64 C floor is built with `-moutline-atomics`, so every atomic in the vendored `libcrypto`/`libpython` compiles to a call into the LSE dispatch family, which lives only in a static libgcc/compiler-rt -- `libgcc_s.so.1` exports none of it. Nothing in the floor set defined those hundred symbols, so a sealed shared library linked clean and then failed its load canary with `undefined symbol: __aarch64_ldadd4_relax`. Our own codegen was never the source (LLVM lowers `atomicrmw` to inline `ldxr`/`stxr` under the emitter's target machine), and the vendored `libcompiler_rt.a` defines them only inside a single 1.9 MB object that also redefines `strlen`/`memset`/`memcmp`. The family is now emitted as module-level assembly instead -- about 2.4 KB, weak and hidden, always LL/SC -- which is assembly rather than IR because callers may assume only x0, x1, x15, x16, x17 and the flags are clobbered and no calling convention expresses that. The shared-library emitter also now initializes the assembly parser, without which any module asm segfaults the emitter outright.
- **Fix: a native abort no longer destroys its own diagnostic**: The uncaught-exception path printed `Uncaught exception: ...` with `printf` and then called `abort()`, which does not flush stdio. On a terminal the message survived; through a pipe it was block-buffered and died with the process, so the diagnostic vanished exactly where it was needed most -- under CI, once the seal moved to a worker process whose output is captured. It now flushes first, matching the nogc-enforced abort beside it. The seal's parent also decodes the worker's exit signal, so `-6` reads as `SIGABRT` and says that a missing result file means the worker died in native code.
