- **Native: C pointers, C-layout structs, views of C memory and pinned payloads**: A C library import can now describe the pointer patterns C APIs are built on. A foreign struct is stored in its C layout, with nested structs embedded by value, so it reaches C with no copying; reading a nested struct as a value copies it, while `cam.position.x = 1.0` writes in place. A clib parameter typed `&T` or `&mut T` lends C the address of the argument for the call, which gives out-parameters and in-place mutation for structs and scalars (`UpdateCamera(&mut cam)`, `SDL_GetWindowSize(w, &mut x, &mut y)`). `ptr[T]` (bare `ptr` is `void*`) holds a C address in locals, fields and containers, with `is_null()`, equality and the `ptr[T](p)` cast. A bodiless `obj sqlite3;` declares an opaque type usable only as `ptr[sqlite3]`, and `&mut ptr[T]` out-parameters fill it in. `p.view(n)` is a bounds-checked view of C memory that may not outlive its scope. `pin(value)` makes a `Pinned[T]` whose payload address never moves, for C APIs that keep a pointer (`rlSetRenderBatchActive(&mut batch)`). New diagnostics E1150-E1152 reject foreign struct fields that are not C plain data, by-value uses of opaque types, and payloads with no C layout. The same program also runs on the Python backend (`jac run --backend python`), which lowers the import through `ctypes` with identical output. The documented but never implemented `c_void` type is removed; use `ptr` (or `-> None` for a void return).
