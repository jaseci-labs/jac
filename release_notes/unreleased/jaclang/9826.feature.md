- **`jac update --self`: the binary updates itself**: running `jac update --self` resolves the newest GitHub release (or a pinned `--release <tag>`), downloads this platform's `jac` binary, verifies the published sha256, and atomically replaces the running launcher -- already-running processes keep their version and new invocations pick up the update, no reinstall script needed. It refuses the cases it must not touch: plain interpreter sessions, linked dev binaries (`zig build -Ddev`), jacup-managed installs (`metadata.json` beside the launcher marks jacup ownership; run `jacup update` there), JacPython installs (the channel only ships the default CPython build, so an update would silently downgrade them), unwritable install locations, and hosts no release ships. A downloaded artifact that matches the published sha256 but is not a valid `jac` binary (no runtime trailer) is discarded and the installed version kept.
