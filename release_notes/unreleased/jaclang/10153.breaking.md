- **Breaking: `archwire.jac` is the single source of a directory's imports**: under an `archwire.jac`, a module no longer writes imports of the modules below it at the top of a module or function body; a written one is `E1144` (or `E2094` in a function), with the message saying whether to delete it or which wire to add. Wires now come in two kinds: `provider ++> consumer { names }` injects the import, and `provider --> consumer { names }` declares one the consumer writes in place because it must run there (inside an `if`, `try`, loop or `with` block, or after other statements), checked both ways (`E1147`). Rules keep `-->`. A block's scope (`graph import core { ... }`) now applies to both sides of its wires and rules. A provider feeding several consumers is written once as a list, `p ++> [c1 { a }, c2 { b }]`, and `jac fmt` renders every `archwire.jac` in one canonical layout. A wired name its consumer never reads is `E1146` (names in `__all__` count as used); wiring that names no module (`E2097`) and rule patterns that match nothing (`E2098`) are errors instead of the `W2084` and `W2083` warnings; comments and docstrings in `archwire.jac` are `E2089`; `W3052` is gone. `jac arch sync --prune` removes unused wires. The jaclang package follows the same rule, with its bootstrap compiler weaving `archwire.jac` too.
