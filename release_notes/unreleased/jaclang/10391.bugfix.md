- **The checker no longer lets a numeric container widen into its mutable supertype**: `list[int]` flowed into a `list[float]` parameter because element compatibility was plain covariant subtyping and `int` widens to `float`; the native backend then stored the appended float in an int-typed element slot and reading it back printed raw float bits as an integer (#8580). Assignments and calls now also require the element relation to hold in reverse when both element types are numeric class instances, so `list[int]` into `list[float]`, `dict[str, int]` into `dict[str, float]` and a `Box[int]` subclass into `Box[float]` are rejected with E1053. Non-numeric elements, generic inference and literal widening keep their covariant behavior: `list[int]` still passes where `list[object]` is expected.
