- **Fix: Client imports of walkers, functions and types a service entry re-imports or includes**: Client code can now import a `:pub` / `:protect` walker or function, or an `obj` / `enum` type, through a service app's entry even when the entry re-imports it (under its own name or an alias) or pulls it in with `include` instead of declaring it. Calls and walker spawns bridge to the entry's app and always target the declared name, and exposure is read from the declaration (a re-imported private element is still `E5106`). Previously the client build failed with an empty `Failed to compile ... for client bundle:` message. That message now always gives a reason.
