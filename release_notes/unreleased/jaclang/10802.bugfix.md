- **Fix: a Kubernetes deploy that can't read the cluster's node architectures stops instead of shipping the host arch**: when the deploy credentials can't list the cluster's nodes (a namespace-scoped Role gets 403 on the cluster-scoped node list), `jac scale deploy` used to fall back silently to the deploying machine's architecture, so deploying from an arm64 machine to x86_64 nodes shipped an aarch64 runtime whose pods crash-looped after the full build and rollout. The deploy now stops at the runtime check, before anything is built, with the API error and the fix: set `JAC_NODE_ARCH` to `x86_64` or `aarch64`, or grant `list` on `nodes`. When the nodes report several architectures or none, the warning now names the architecture the deploy picked.
