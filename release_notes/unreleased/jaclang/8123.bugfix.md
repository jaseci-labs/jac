- **Client: a lambda returning a dict literal no longer breaks the production bundle**: the ES emitter printed an expression-bodied arrow whose body is an object literal as `kind => {"color": ...}`, which JS parses as a function block, so the generated module was a syntax error. `jac check` and the lazy `vite dev` server never parse the emitted JS, so the failure only surfaced when `vite build` ran at bundle or deploy time. The unparser had a paren guard for this shape, but it was keyed on the ESTree `expression` flag that the lambda codegen never set, and it only wrapped a body that was directly an object literal. The unparser now derives expression-bodiedness from the body node type and parenthesises any non-block body whose emit starts with `{`, which also covers bodies like `{"a": 1}[k]`, and lambda arrows now set `expression=True` so the emitted ESTree is well-formed.
