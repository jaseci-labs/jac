- **Fix: a scaled-to-zero app wakes in about 12 seconds instead of about two minutes**: on a KEDA HTTP Add-on wake every cold pod ran `jac install` and pip-installed all of the bundle's vendored wheels again, then imported litellm (8 to 9 s) because byllm and jac-scale's LLM telemetry both loaded it at startup, even for services that never call a model. The venv that `jac scale deploy` seals into the bundle was meant to skip that install, but `jac install` replayed the `jac.lock` pins first, missed the seal's marker, and deleted the interpreter-less sealed venv as corrupt; it now checks the marker against the declared dependencies before the lock replay, so a pod with a sealed venv installs nothing; byllm loads litellm and openai on first use and the telemetry logger attaches when litellm loads. Pods also start faster: the startup probe checks every second, `readiness_initial_delay` defaults to 0, the shipped toolchain is not unpacked when the image already carries the same jac binary, the bundle unpacks inside `jac-bootstrap` instead of a separate init container, and `wait_image` defaults to `busybox:1.36` so kubelet stops re-pulling `latest`. An HTTP-activated app without an explicit `http_forward_timeout` or `rpc_timeout` now waits at least 300 s, so a cold request through the gateway is served instead of timing out.
- **Fix: a redeploy no longer keeps init containers the new manifest dropped**: Deployments were updated with a strategic-merge PATCH, which merges `initContainers` by name, so a removed init container stayed in the pod template and kept running its old image. The PATCH now replaces the list.
- **Fix: the jaclang Docker image builds again**: the image's seed project listed `setuptools` under `[dependencies]`, which now holds Jac packages only; it is declared under `[dependencies.pypi]`.
- **Fix: the gateway answers a forward timeout with 504**: a request whose service did not answer within the forward deadline returned `GATEWAY_TIMEOUT` on HTTP 502, the same response as an unreachable service. A timeout now returns `GATEWAY_TIMEOUT` on 504, and a service the gateway cannot reach returns `BAD_GATEWAY` on 502.
