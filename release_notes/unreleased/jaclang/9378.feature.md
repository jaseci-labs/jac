- **Feature: native `math` becomes a bundled `na_stdlib` module**: The native codespace's `math` support moved from compiler intercepts to a pure-Jac `na_stdlib/math.jac` surface over an `_math_native` libm FFI floor, providing roughly fifty functions whose results and error messages match CPython 3.14 (including ports of CPython's own `gamma`/`lgamma`, `hypot`, `fsum`, and `sumprod` algorithms). `gcd`, `lcm`, and `hypot` take any number of arguments, the reducers accept any iterable, and `import from math { ... }` works alongside `import math`.
- **Feature: native `cmath` bundled module and complex arithmetic**: The native codespace gains `na_stdlib/cmath.jac`, a pure-Jac port of CPython's `cmathmodule.c` algorithms (special-value tables included), and complex operators that follow CPython 3.14's `complexobject.c`: mixed `complex`/real arithmetic under C99 Annex G rules, infinity recovery in `*` and `/`, and `**` with CPython's `ZeroDivisionError`/`OverflowError` behavior.
- **Fix: native calls no longer confuse same-named functions across modules**: A C-library extern declared in one module no longer rewrites the result of a same-named Jac function called from another (`math.floor(3.7)` printed `3.0` natively), and a function skipped in one bundled module no longer blocks a same-named function in another on cold builds (`cmath.sqrt` beside `math.sqrt`). Native `for` loops also iterate `range` values held in variables.
