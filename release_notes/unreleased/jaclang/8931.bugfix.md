- Native codegen now lowers an untyped lambda parameter to what the type evaluator actually inferred (e.g. `str` from a `Callable[[str], str]` call site) instead of silently defaulting to `i64`. An untyped lambda parameter's inferred type used to be laid out as `i64` in the emitted IR with no diagnostic, mis-typing anything wider than an integer at the call boundary. As a side effect, a lambda parameter whose inferred type genuinely can't be lowered to native IR now correctly falls back to the server codespace via the existing unlowerable-type diagnostic, instead of silently staying native as `i64`.
