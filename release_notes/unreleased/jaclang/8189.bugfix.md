- **Native: a leading `*` spread of a list of tuples no longer makes a set hash its members as C strings** (issue #8182): a native list registers one instantiation per storage flavour and every pointer-element list shares `List.ptr`, whose element slot is erased to a byte pointer on purpose, while a set carries a `tupleN` flavour that hashes and compares the N bytes behind the pointer instead. `_codegen_set_val` seeded a leading spread's element flavour from the source container's lowered element type, so `{*set_of_tuples}` was fine but `{*list_of_tuples}` got the erased byte pointer back, recovered no tuple layout from it, and fell to the plain pointer flavour -- which the hash core reads as a string key, hashing with FNV over NUL-terminated bytes and comparing with a strcmp, over the boxed tuple's own payload. Two int pairs sharing a first component read as the same one-byte key, so `{*[(1, 2), (1, 3)]}` had length 1, `(1, 9) in {*[(1, 2)]}` answered True, and three pairs beginning with `0` collapsed to one because a leading zero byte ends the key; `{*[(1, 2), (3, 4)]}` came out right, which is what made it easy to miss. Nothing reached stderr in any of these cases. The layout is decidable at compile time -- the operand's static type is `list[tuple[int, int]]`, and `_elem_storage_llvm` already lowers that element to the pointer-to-literal-struct the `tupleN` flavour needs, the same type the `set` arm of `_lower_type` derives `tupleN` from -- so the flavour now comes from there, and only when it names a tuple layout, leaving a `list[str]` spread on the genuine C-string keys it always had and a scalar list untouched. The spread operand usually carries no type of its own, since `exit_name` only evaluates a name whose symbol is unresolved and the evaluator has no `*` case, so the declared type is reached through the symbol: the declaration's own type for a local or module-level binding and the enclosing `ParamVar`'s for a parameter, the same hop closure capture already makes. A source that names no element type at all is refused with `E5092` and demotes rather than silently selecting a hash that is wrong for everything except strings.
