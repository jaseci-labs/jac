- **Perf: list `append` growth no longer bloats the caller's hot loop**: The native backend emitted the list grow path (malloc/memcpy/free) inline inside `__list_append_*`, so after LLVM inlined two appends into a user loop, ~10 live values crossed the inlined allocator calls, the register allocator spilled per iteration, and the header fields were reloaded from memory every append. Counter profiling (100M-iter list churn) showed 29 instructions and 6.0 cycles per iteration with 3.0 cycles/iter of store-buffer stalls, versus 14 instructions and 2.0 cycles for equivalent C. Growth is now emitted once per element type into a `private noinline nounwind @__list_grow_<elem>` helper that `append` calls from its (cold) grow block, cutting the churn loop to 26 instructions / 5.0 cycles (-17%) and lifting decode-DSB residency ~24x. Verified with a `perf_event_open`-based harness (`scripts/native_profile.py` + `scripts/miniperf.c`); function-local lists with inline (alloca) headers are the follow-up with the larger measured win (-55%). The noinline/cold-helper emission is centralized as `NaIRGenPass._emit_slow_path_helper` and applied to the audited growth paths: dict/set rehash and order-compaction helpers, plus a new `@__bytearray_grow` outlined from `__bytearray_reserve`; cheap checks and hot paths (reserve's capacity test, hash find/insert, retain/release, get/set/len) stay inlineable.
- **Perf: outline native hot-path slow machinery**: String/list repetition,
  list concatenation/comparison/membership, list and stepped-string slicing,
  cycle-root buffer growth, and dictionary/set order compaction now keep their
  allocation or scan loops in private `noinline cold nounwind` helpers. Fixed
  runtime accessors and iteration helpers also carry `nounwind` where they
  do not invoke user callbacks.
