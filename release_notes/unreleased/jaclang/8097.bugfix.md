- **`--scale` deploys honor `.jacignore`**: the bundle staging walked the project tree through a hardcoded exclude list of its own (VCS and build dirs, `.env`, key material) and nothing in the toolchain ever read `.jacignore`, so trees a project parks with it shipped to the bundle PVC anyway, the in-pod boot compile compiled them, and one stale or intentionally excluded file anywhere crash-looped the whole fleet; `.jacignore` is documented as the project-level "excluded from compilation and analysis" list, but the only thing that reached it was a CI shell step grepping it into `jac check --ignore`. It now has a canonical loader beside `path_matches_exclude`, the matcher `jac check` and `jac fmt --lintfix` already share, and the deploy reads one declared source filter built from it, so the seal stage copy, the `.jab` source members, and the nested `jac.toml` enumeration agree on what belongs to the bundle instead of each deciding for itself. The file itself still ships, so its bytes sit inside the content address that gates the re-ship: editing `.jacignore` moves the digest and the deploy re-ships rather than hitting the content-addressed seed skip. The hardcoded excludes stay as the floor, and the built client artifacts (`.jac/client/dist`, `.jac/admin`, `.jac/serve_manifest.json`) still win over every exclude, so a project cannot park them by accident. A `.jacignore` that parks the project's own entry module now fails the pack with a message naming the file, instead of shipping a bundle with nothing to boot.
