- **Type-position constructs erase natively instead of demoting the module**: `typing.cast`, a module-scope `glob T = TypeVar(...)` and an `abc.ABC` base are directives to a type checker, not values a program computes, but each one used to demote the module that wrote it and, through the import closure, every module reaching it. The shared cause was the native module-import gate reading a base-class expression as a run-time use of a Python name; a base the native lane erases is never loaded at run time, so those now join annotations and return types as compile-time positions. The boundary is drawn at erased rather than at base: an ordinary Python base is a run-time dependency an archetype cannot mean what it says without, so it still refuses, as does a name the program would actually have to call. On that gate sit the three erasures: `cast(T, value)` lowers to `value`, which is what `typing.cast` returns in Python too, so the lanes agree by construction; `typing` joins the compile-time stdlib table so the `TypeVar` import stops blocking a declaration native glob lowering already skipped; and an `ABC` base leaves the native parent list, where it had been registering a phantom ancestor and forcing a vtable pointer onto every instance of a class with nothing to dispatch. The Python lane is untouched, so an abstract archetype still refuses to instantiate, and `abstractmethod`, `ABCMeta` and a bare `import abc` still refuse to cross into native.
