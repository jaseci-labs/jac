- **Fix: `jac scale destroy --component application` keeps the database and monitoring Services**: The sweep that removes the application's Services, PodDisruptionBudgets and Ingresses selected everything labelled `managed=jac-scale`, so it also deleted the postgres, Prometheus, Grafana, Loki, Tempo and kube-state-metrics Services. Their pods kept running but could no longer be reached by name, for example at `{app}-postgres-service`, until the next deploy recreated the Service. Services and PodDisruptionBudgets now carry `jac-scale.role` like Deployments do, and those sweeps select on it, so only the application's own objects are removed. A Service or PodDisruptionBudget created before this change has no role label; destroy still removes it when it is labelled `managed=jac-scale` and its `app` label names one of the fleet's Deployments. One whose Deployment is already gone is left for the next deploy to relabel, or to delete by hand.
