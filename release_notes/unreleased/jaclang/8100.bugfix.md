- **Fix: `consume()` on the Postgres event stream honors `start_from`, and brokers can no longer diverge from the interface**: `EventStreamBroker` declares `consume(topic, group, max_messages, timeout_seconds=5.0, start_from="latest")` and `LocalEventStream` implemented exactly that, but `PgEventStream.consume` omitted `start_from` and defaulted `timeout_seconds` to `0.0`, so every caller written against the documented interface raised `TypeError: unexpected keyword argument 'start_from'` on Postgres only. Consumers wrap `consume()` in a try/except so a broker hiccup cannot kill the stream, which turned the type error into a transient-looking warning per poll and left the consumer reporting no events forever: in the reporting migration a publisher wrote 423 rows to `jac_events` while the consumer delivered 0 across a 12-minute turn, with a frozen UI and a healthy-looking app. `PgEventStream` now positions a brand-new consumer group through one shared helper used by both `consume()` and `register_handler()` (`earliest` seeds the offset at 0, anything else seeds it at the topic's current `max(id)`), so a new group asking for `earliest` replays everything retained, the cursor still advances, a second group replays independently, and `latest` skips what was already published. `timeout_seconds` now defaults to `5.0` as the interface declares, so a caller relying on the documented blocking default no longer gets a silent non-blocking poll. Closing the class of bug, `EventStreamBroker` now checks each implementation's method signatures against its own declarations when the subclass is defined: dropping a parameter, changing a default, reordering parameters, or adding a required one raises `TypeError` at import instead of on a call against one backend, while widening with defaulted parameters stays allowed. The well-known positions are available as the `StreamPosition` enum and both brokers decide "replay from the beginning" through one shared predicate that accepts either the enum member or its string value, so the two backends cannot drift apart on what a position token means; `start_from` stays a plain `str` for existing callers.
