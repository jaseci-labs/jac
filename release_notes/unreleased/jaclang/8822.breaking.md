- **Breaking: the admin portal is now disabled by default and never ships a default password**: every deployment previously served `/admin` and provisioned an `admin` / `changeme` account on first boot, and the forced password reset that was supposed to contain it was only enforced in the browser, so the login token worked on every admin API. `[scale.admin] enabled` now defaults to `false`, `default_password` has no default, is required to provision the account, and refuses the historical placeholder `changeme`, and a token for an account with a pending reset is rejected server-side everywhere except `/admin/reset-password`. Deployments that use the portal must set `[scale.admin] enabled = true` plus `default_password`, or the new `JAC_ADMIN_ENABLED` and `JAC_ADMIN_PASSWORD` environment variables, which let the credential be injected at deploy time instead of committed to `jac.toml`. Two upgrade behaviours follow: an `admin` account bootstrapped by an earlier release still carries its pending reset, so it can log in but gets 403 on every other admin route until it rotates once through `/admin/reset-password`; and a deployment that relied on the old defaults now boots without `/admin`, logging an INFO line for the disabled portal and a WARNING when a dormant admin account is found in the identity store.
