- **Breaking: the admin portal is disabled by default and ships no default password**: `[scale.admin] enabled` now defaults to `false`, `default_password` has no default and refuses the historical `changeme`, and a token for an account with a pending password reset is rejected server-side everywhere except `/admin/reset-password`. Deployments that use the portal must set `[scale.admin] enabled = true` plus `default_password`, or the new `JAC_ADMIN_ENABLED` and `JAC_ADMIN_PASSWORD` environment variables, which inject the credential at deploy time instead of committing it to `jac.toml`. Two upgrade behaviours follow: an `admin` account bootstrapped by an earlier release still carries its pending reset, so it can log in but gets 403 on every other admin route until it rotates once through `/admin/reset-password`; and a deployment that relied on the old defaults now boots without `/admin`, logging an INFO line for the disabled portal and a WARNING when a dormant admin account is found.
