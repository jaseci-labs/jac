- **Fix: an external database URL is re-scoped for the target namespace, or the deploy fails instead of shipping a pod that cannot start**: external mode passed the connection string through verbatim, so a deployed pod could receive a namespace-relative bare service name while running in another namespace. The deploy reported success and emitted a manifest that failed at startup with `socket.gaierror: [Errno -3] Temporary failure in name resolution` (#8137). A bare single-label host is now qualified to `<service>.<namespace>.svc.cluster.local` using `[scale.kubernetes].database_namespace`, or the deploying pod's own namespace read from `POD_NAMESPACE` or the ServiceAccount namespace file. When neither is known the deploy raises with a message naming the host, the target namespace, and both fixes, rather than reporting a successful deploy. Requesting `database_mode = "external"` with no URL configured is likewise an error and never silently falls back to the deployer's environment.
