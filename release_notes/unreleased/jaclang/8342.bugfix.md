- **Fix: a Mach-O relocation resolves the symbol it names, not the last object that reused the name**: The Mach-O linker built a relocation-index-to-placement map and never read it, resolving every relocation by symbol *name* through one flat dict written last-wins over the main object and every merged floor-archive member. Module-local constant labels are not unique across objects -- clang names C string literals `l_.str`, `l_.str.1`, ... per object, and so does our own emitter -- so when the seal merged libcrypto's members into a sealed artifact, each `l_.str.N` the member defined overwrote ours and our references to those string constants resolved into the member's data. On macos-aarch64 that put 361 of the 943 address computations in the sealed `diagnostics.jac` module initializer inside libcrypto's object-name table, so the diagnostic registry saw a code registered twice, raised, and aborted the seal worker inside `__jac_shared_init` with nothing but a signal number to show for it -- the last red release leg. Defined symbols now resolve by relocation index, name lookup is left to symbols with no definition in the link, and a local definition can no longer overwrite an external one. The linker also refuses a relocation whose type it does not implement or whose patch site it never placed, instead of leaving the instruction unpatched and reporting success; and a macOS release leg that dies in native code now prints the OS crash report, replays the artifact load under lldb, and uploads the reports, symbol dumps and failing artifact, while a failed seal worker's whole transcript reaches the log instead of only its stderr.
