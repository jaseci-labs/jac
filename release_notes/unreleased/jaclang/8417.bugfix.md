- **Fix: a module that fails native lowering now actually leaves the native lane, everywhere**: the demotion fallback printed "compiled in the server codespace" but recorded the failure only in a memo that almost nothing consulted, while every placement decision kept reading the raw `[placement.pins]` entry. The importer-facing verdicts kept classifying the module as a cl->na edge, so client bundles bound its names through `__na_bind` against a wasm module that was never built and died in the browser while `jac check` and `jac build` stayed green. The module's own retry re-read the pin, coerced native again, failed again, and leaked the native-only error into `jac check`; element-level pin resolution then re-stamped each element native from inside the server compile, so the retry could never come out clean, and the fallback's error truncation could swallow genuine non-native errors along the way. Importers compiled before the failure additionally kept stale emitted ES and NATIVE manifest bindings. The demotion memo now lives in placement ground and every pin consumer reads an effective pin that a demotion blanks (module-level and element-level), the fallback resets each importer's emitted ES through the same shared walk the client-pull demotion uses and drops the NATIVE bindings naming the demoted module, and the reset reports a warning if it fails instead of failing silently. After a demotion the module genuinely compiles in the server codespace with a truthful note, importers re-lower against its real placement (plain client code, RPC bridge, or an honest E5082), and previously swallowed errors surface again.
