- **Scale: the monitoring stack pins Prometheus and Grafana**: The Kubernetes monitoring stack deploys seven images, five of which already carried an explicit tag; Prometheus and Grafana were still on `:latest`. A floating tag makes the deployed version a function of when a given node last pulled rather than of the commit being deployed, so two clusters rolled out from the same commit could run different Prometheus builds, and an ordinary pod restart could carry a running cluster across a major version with no change on our side (2.x to 3.x was exactly such a boundary, and it moved defaults). Both images are now pinned to the tag their `:latest` resolved to at the time of the change, confirmed by comparing manifest digests rather than by reading version numbers, so this freezes the behavior clusters already had instead of quietly upgrading them. No configuration key is introduced: the config loader's image keys cover the database, Python and wait images and none covers monitoring, so a literal pin matching the file's existing convention is the smaller change.
