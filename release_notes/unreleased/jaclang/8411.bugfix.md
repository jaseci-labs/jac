- **Scale: a configured `entry-point` stops silently becoming `main.jac`**: `get_config()` returns a `JacConfig`, which declares no `entry_point`; the field lives on its `project` member. Two sites read it off the top-level object instead: `ensure_main_service` in `scale/runtime/routing.jac`, which names the file the gateway registers the main service against, and the client entry resolution in the scale config loader. Both reads raised `AttributeError`, and both sit inside an `except Exception` whose fallback is the literal `main.jac`, so a project that set `entry-point = "app.jac"` in its `jac.toml` had that value discarded without a warning: the fallback is indistinguishable from an unconfigured project, so nothing logged and the deploy went out pointing at a file the project does not contain. `scale/injector/bundle.jac` already read `config.project.entry_point` correctly, so the two sites now match the read that was always right, and each is written so the checker can see the `None` case rather than leaning on the surrounding `except`. The `os.path.basename` at the routing site is deliberately kept: the Kubernetes realizer passes an already-basenamed filename and the orchestrator defaults to `f"{name}.jac"`, so a bare filename is the contract on both consumers and stripping it would split local behavior from pod behavior in the other direction. The regression test builds a real project directory, seeds the real config cache through `get_config(start_path=..., force_discover=True)` rather than `chdir` (the cache is a module global, which would make a chdir-based test order-dependent), and resets it in `finally`.
