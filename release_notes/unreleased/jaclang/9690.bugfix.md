- **Fix: a pipe expression's operands keep it as their parent**: Type checking or emitting `a |> f` (and `:>`, `<|`, `<:`) built a temporary call over the pipe's operands and left it linked to them, so an operand's `parent` read as that temporary call until a cycle collection reclaimed it. Passes that read the tree in between saw a parent that depended on collector timing, which made `synthetic pipe calls preserve the source graph after lowering` fail intermittently in CI. The checker and the Python backend now unlink the temporary once it has been used.
