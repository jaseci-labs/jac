- **Fix: `CREATE DATABASE` no longer races between parallel workers**: `PgRuntime._ensure_database` checked `pg_database` and then created, with no lock between the two. The precompile step forks a pool of workers that all provision the same scratch database at startup, so on a parallel build two of them could see no row, both issue `CREATE DATABASE`, and the loser fail the whole seal with `duplicate key value violates unique constraint "pg_database_datname_index"`. The error blamed whichever module the losing worker held, so it named a different file each run while the database name stayed the same. A duplicate-name failure is now treated as the intended outcome, with reaping left to the worker that created the database. (#8815)
