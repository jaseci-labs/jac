- **Fix: a managed borrow is no longer rejected over a container append**: a `&`/`&mut` borrow of a place reached from managed data (`head: &memo | None = &p.tokens[0].memo_head`) must not have the fields on its path written while it is live, and every builtin container mutator counted as writing the elements (`[]`) that the path's subscript step also names, so an `append`, `insert`, `extend`, `add` or `sort` on any container in the borrow's live range was `E1322`. These calls are now judged per method, as an inferred borrow already judged them: `append`, `insert` and `reverse` add or move elements and release none, so they write nothing; `extend`, `add`, `setdefault` and `sort` write nothing when their receiver and arguments are plain expressions; `pop`, `remove`, `discard`, `update`, `clear` and `popitem` release elements and still count as writing `[]`; a call whose arguments the checker cannot see through still counts as writing anything.
