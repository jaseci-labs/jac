- **Fix: `jac start --scale` reported "Fleet ready" while the old pods were still serving**: on a re-deploy the readiness gate counted replicas from the previous revision, so the command returned success before the new pods had started, and a rollout that stalled past its progress deadline waited out the full timeout with no explanation. Readiness is now measured against the revision this deploy applied, a stall that persists across polls fails with the reason and per-pod diagnosis, the ops deploy view reports the same verdict as the deploy itself, and `jac start --scale --wait full` (or `rollout_wait = "full"` under `[scale.kubernetes]`, bounded by the new `rollout_timeout`) holds until every replica of every service is available for pipelines that need full capacity before cutting traffic.
