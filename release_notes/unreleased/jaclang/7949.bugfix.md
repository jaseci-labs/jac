- **Fix: `jac start --scale` reported "Fleet ready" while the old pods were still serving**: on a re-deploy the readiness gate counted replicas from the previous revision, so the command returned success before the new pods had started, and a rollout that stalled past its progress deadline waited out the full timeout with no explanation. Readiness is now measured against the revision this deploy applied, a stalled rollout fails with the reason and per-pod diagnosis as soon as the verdict belongs to this deploy rather than a previous one, deployment status and the ops deploy view report that same verdict, and `jac start --scale --wait full` (or `rollout_wait = "full"` under `[scale.kubernetes]`, bounded by the new `rollout_timeout`) holds until every replica of every service is available for pipelines that need full capacity before cutting traffic.
