- **Fix: unknown `[scale.*]` keys in jac.toml now warn instead of vanishing**: configuration was deep-merged over the defaults with no validation, so a misspelled key or section (`[scale.microservice]`, `cpu_limits`) silently fell back to defaults with no trace in the CLI, the dry run or the logs, the same failure class as the historical `[plugins.scale.*]` regression. The declared config schema, previously dead code with zero callers, has been completed to cover every section and key the runtime reads (including the seven undeclared sections, ~40 kubernetes keys, the documented microservices boot knobs and `client.static_mounts`, and the install-time capability surfaces) and is now enforced at load time: `get_scale_config()` validates the raw table once per process and logs each unknown key with a nearest-neighbour suggestion, `jac start --scale --dry-run` surfaces the same findings under Global findings, and `JAC_SCALE_CONFIG_STRICT=1` turns them into a hard error. A section named by `[scale.deploy] target` is treated as owned by that deploy-target plugin, free-form tables (`secrets`, `env`, `labels`, `deployment_overlay`) stay open, and two drift-lock tests keep the schema and the runtime defaults from diverging again. The microservices normalizer also passes the documented `boot_health_timeout` / `boot_max_wait` / `health_monitor_interval` and `client.static_mounts` keys through instead of stripping them, so those documented settings take effect from jac.toml. One layer deeper, `JacConfig` itself now warns when jac.toml still carries a legacy `[plugins.*]` table, which was previously dropped wholesale before any per-feature validation could see it, so the original regression's exact shape can no longer reproduce silently; the two remaining readers of that dead namespace (the compile-time service cut and `jac scale split`) were deleted, so a legacy project can no longer have its service cut half-applied. Validation itself lives with the `get_config_schema()` convention on `PluginConfigBase` rather than in the scale package, so any plugin declaring a schema opts in by overriding one method, and the deploy-target sections it accepts come from `DeploymentTargetFactory.known_targets()` instead of a hand-kept list, which also means a misspelled `[scale.deploy] target` is now reported rather than silently whitelisting its own section.
