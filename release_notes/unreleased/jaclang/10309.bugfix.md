- **Fix: a `Final` field is set only once, and a bare `Final` needs a value**: A `Final` field with no default could be written more than once while its object was built: twice in `init`, in `init` and again in `postinit`, inside a loop in `init`, in an `except` after the `try` had already set it, or in `postinit` after the caller had already passed it. Every write after the first is now reported with `E1135`. One write on each branch of an `if`/`else` is still allowed, and so is a fallback write in `except` when the `try` failed before setting the field. Writing `Final` with neither a type nor a value, such as `has x: Final;`, left the field untyped, so any value was accepted for it; this is now reported with the new `E1161`. Write the type, as in `Final[int]`, or give the field a value.
