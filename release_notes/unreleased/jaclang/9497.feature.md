- **New: `Autoscaler.watch_scale_targets` streams deduplicated scale transitions**: knowing a KEDA-scaled app had woken up meant calling `get_runtime_status` on a timer, so a control plane tracking many preview environments polled every one of them forever and still learned about a wake a poll-interval late. `watch_scale_targets(namespace, label_selector=None)` now yields `AutoscalerTransition` values from a Kubernetes watch, carrying the previous and current `ResourceStatus`, the `observed_at` this observer saw it and the source `resourceVersion`. It watches the ScaledObject rather than the Deployment because the trigger and scaler conditions are the half a Deployment cannot express: a scaler that cannot reach its metric endpoint never changes the Deployment, so watching the workload alone reports nothing for exactly the failure this exists to surface; a pod becoming ready without the ScaledObject changing is the reverse gap and needs a second watch. The opening list seeds the cache and emits nothing, because an observer that has just started has witnessed no transition and reporting current state as one invents history and floods every restart, and a `410 Gone` relists while keeping that cache so targets whose state did not move stay silent. Watch cardinality is the caller's: one call opens a bounded number of watches for one namespace and nothing is shared between callers, so a consumer tracking many targets makes one call and fans out in its own process. Part of #7405.
