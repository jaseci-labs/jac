- **One signature annotation the backend cannot lower demotes its callable instead of its module** (#8285): a free function's signature was resolved when the ability was declared, which is before any body opens a demotion window, so a parameter or return type with no native layout had no owning callable to absorb it and the E5092 stayed in the module's error list -- costing the whole module its IR, and every importer that compiled it as a dependency along with it. The declaration now owns that window: the failures are bracketed around signature resolution, spent on the ability that carries them through the same `_demote_method_if_unlowerable` path every other seam takes, and the diagnostic names the shape as a `signature type` so coverage can tell a signature refusal from a body's. The demoted symbol is renamed and abort-stubbed like any other demotion, so it is visible to `seal_demotion_report` and waiver-eligible with no new category. The method declaration path is bracketed the same way for the annotations its erasure cannot absorb. `enum_utils.jac` and `operations.jac` are the first beneficiaries: both were refused whole for taking `TypeEvaluator` as a parameter, and both lower now with a seam per evaluator-typed callable and every other body native.
