- **Breaking: static-asset resolution is one jailed law; bare project-root files, `src/`, and basename-flattened URLs are no longer served**: the monolith's web-root handler (`serve_root_asset`) resolved an asset by walking a candidate ladder that included the bare project root (`base_path / <path>`) and `src/`, so `/package.json` and arbitrary source files under `src/` were downloadable at the web root -- a source-exposure hole -- and each server carried its own copy of the lookup. Every server now routes through one shared, jailed resolver (`Path.resolve()` + `is_relative_to()` on every root, exact-path only), which closes the exposure and removes the drift. Consequences for URLs, all now returning 404: files that only ever resolved because they sat at the bare project root or under `src/` (the security fix -- there is no supported way to serve a project source file directly; put assets under `public/` or `assets/`); URLs that only resolved via basename flattening, where `/some/dir/logo.png` found `assets/logo.png` by filename -- put the file at its exact relative path instead; and assets served from a project-root `dist/` directory, which is not an asset root anymore (`.jac/client/dist`, the vite build output, is) because `dist/` is excluded from the `--scale` bundle and so returned 200 locally but 404 in Kubernetes -- a cross-mode parity trap. The blanket one-year `Cache-Control` on root assets is also gone, replaced by a single `public, max-age=3600, must-revalidate` for now; the immutable/hashed long-cache split is tracked in #8126. Nothing changes for the documented conventions: put static files under `public/` (served at the web root) or `assets/` (served under `/static/`), and `static_mounts` are untouched.
- **Breaking: `/static/*` no longer falls through to `public/`, a project-root `dist/`, or `.jac/client/compiled[/assets]`**: the old `serve_project_static` ladder tried `assets`, `dist`, `public`, `.jac/client/dist`, and `.jac/client/compiled[/assets]` under the project root for anything under `/static/`, so e.g. `/static/brand/logo.png` could resolve from `public/brand/logo.png`. The new `/static` root table only has two entries -- `static` -> `.jac/client/dist` and `static/assets` -> project `assets/` -- because `/static/*` and the web root (where `public/` is served) are meant to be disjoint URL spaces. A URL that only ever resolved through one of the removed fallback roots now 404s; move the file under `assets/` (served at `/static/assets/...`) or `public/` (served at the web root) to match its intended URL space.
- **Breaking: symlinked asset directories that point outside their root no longer resolve**: the shared resolver's jail (`Path.resolve()` + `is_relative_to()`) requires the fully resolved target to stay inside the resolved asset root, so a symlink under `public/` or `assets/` whose target sits outside that root now 404s where it previously served. This is a consequence of the jail, not a separate opt-in check, and it isn't going to change -- if you relied on symlinking a shared assets directory into `public/` or `assets/`, copy or bind-mount the files into the root instead.
