- **Fix: Native field access through a secondary-base-narrowed reference**: Archetype layouts are flattened in MRO order, so a field declared on a class's second or later base sits at a different slot in a derived class than in the base's own struct. Reading or writing that field through a reference narrowed to the secondary base (for example `if isinstance(x, SecondBase) { x.field; }`) resolved the base's slot index against the derived layout, which named a neighbouring field instead. The native backend now selects the slot from the runtime class.
