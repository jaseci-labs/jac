- **Fix: the gateway routes builtin passthrough traffic by ownership instead of replaying request bodies across services**: builtin passthrough (`/walker`, `/function`, `/webhook`, `/user`, `/sso`, `/api-key`, `/graph`, `/jobs`, `/cl`) used to forward a buffered request body to every service in registration order until one stopped answering 404, so a non-idempotent request was delivered, and for the replicated identity endpoints executed, more than once. Builtin families are now classified as data in `routing.jac`: *replicated* families (`/user`, `/sso`, `/api-key`, `/graph`) run the same handler on every service against the shared identity store and are delivered exactly once; *service-owned* families (`/walker`, `/function`, `/webhook`, `/ws`) are forwarded once to the service whose published `/openapi.json` declares the route, for every HTTP method; only the *discovery* families (`/jobs`, whose create-404 fires before any scheduling side effect, and `/cl` pages, which are GET-only) keep the try-each-service probe. The route table now records, per service, when it last received a definitive spec answer, so a miss re-asks only services that were never asked, that changed url or health status, or whose answer is older than `[scale.microservices] route_refresh_seconds` (default 30s), in parallel, coalesced across concurrent requests, and bounded to one second per service so a healthy but unresponsive service costs a miss one second rather than the full spec-fetch timeout; a newly registered service, a locally started service turning healthy, or a pod that was unreachable on the previous crawl is learned on the very next miss instead of after the refresh window. When no learned service declares a service-owned path the body is probed only against services whose routes are unknown (unreachable or publishing no spec, e.g. `docs_enabled = false`), and 404s without being delivered anywhere once every service has published its routes; a walker added to an already-learned service can therefore 404 for up to `route_refresh_seconds` after its redeploy. A service's own `/user`, `/sso`, `/api-key`, `/graph`, `/jobs` and `/cl` paths are no longer learned as owned routes, which also stops the per-crawl clash warnings for the replicated auth surface. Learned owners are addressed through the same `service_base_url` resolution the proxy uses, and an owner-routed or replicated request to a dead backend now returns the proxy's 502 rather than the probe's 503.
