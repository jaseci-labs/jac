- **A server restart no longer re-runs the schema DDL** (#9160): since 0.37.5 a booting server computed two different schema fingerprints, one before and one after `jaclang.server.outbox` was imported, because the outbox registered its tables with the store as an import-time schema extension. Each boot rewrote the schema stamp twice, so the `ensure_schema` fast path never matched on a restart and every replica re-ran the DDL under the other replicas' open transactions: a 5s lock stall per promoted field, or `SessionConflictError` against a TCP database. The outbox tables (`jac_outbox`, `jac_outbox_seen`) are now part of the store's base schema, the import-time extension registry is gone, and the fingerprint is a pure function of the schema definition and the promotions. A boot applies the DDL at most once, a restart against an unchanged schema runs none, and the first boot after upgrading runs it once to adopt the new fingerprint.
