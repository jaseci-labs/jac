- **Feature: GraphMend graph-break elimination (`jac run --graphmend`)**: A new opt-in `--graphmend` / `-g` flag on `jac run` eliminates PyTorch 2 FX graph breaks at compile time. TorchDynamo falls back to eager execution whenever traced code forces a Python-level decision on tensor data, and each such break splits the compiled region. GraphMend detects the fixable break patterns under `torch.compile` entry points (decorated functions and classes, or call-site wraps like `torch.compile(Model())`, resolved through the symbol table) and rewrites them so the forward pass stays a single contiguous FX graph. Data-dependent validation guards lower to graph-native `torch._assert_async`, with the original exception type and message folded into a compile-time marker and restored by an eager boundary decorator. Data-dependent `if`/`else` branches are predicated into `torch.where` selections, or `torch.cond` when a branch value contains a call; multi-statement branches hoist their setup only when each statement is provably effect-neutral on the untaken path. Side-effecting calls are deferred: `print` calls buffer and replay in program order after the graph runs, and logger calls go through an integer slot registry flushed by a forward hook, since TorchDynamo cannot trace a `Logger` method at all; an eager boundary guard drains the buffer even on exceptional exits. A companion `--graphmend-scope` flag extends the transforms to imported `.py` model code (for example Hugging Face modules) by claiming scoped modules in the import system and compiling them whole-module. The passes run immediately before Python code generation, self-gate on the flag, and bypass bytecode caches while active, so normal compiles and other backends are untouched. Detection matches structurally rather than against unparsed text, so it works on plain `.py` model source (`jac run model.py -g`) as well as `.jac`. See [GraphMend internals](../../internals/graphmend.md) for the specification and the legality argument behind each rewrite.
