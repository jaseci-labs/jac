- **Fix: concurrent find-or-create no longer creates duplicates on Postgres**: after a serialization failure the session rolled back and sent the same writes again in a new transaction, which dropped the reads they were computed from, so a conflict Postgres had detected still committed: three concurrent calls of a check-then-create walker left three nodes. A serialization failure at `COMMIT`, in a graph read, or one a caller swallowed now re-runs the walker (or function) from fresh reads through the conflict loop, so it finds the winner's node, as the persistence docs describe. Such a failure now uses one `conflict_max_attempts` attempt, and `on_conflict = "fail"` answers it with `409 write_conflict`.
