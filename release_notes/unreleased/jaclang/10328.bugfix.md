- **Fix: a process's memory peak no longer includes its parent's** (#10328): on Linux, `execve` carries the spawning process's high-water mark into the new program's `ru_maxrss`, so a compiler process spawned by a large parent read its peak as the parent's. The unit collector's growth trigger stayed silent until real usage passed that inherited figure, and `test_selfhost_rebuild` failed whenever an earlier test in the same pooled worker had grown it (reporting 6.8 GB for a rebuild that peaks near 2 GB). Both now read the process's own `VmHWM` on Linux.
