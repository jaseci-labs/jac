- **`jac hack` (hack mode)**: a compiler-backed terminal workspace for working on a Jac codebase with coding agents. The project is loaded into a graph of packages, modules, archetypes, abilities and impls joined by the archwire wiring, with users, uses and walker traversals linked; the navigator and the wiring view (providers, consumers, rules, and the violations a wire causes) browse it, the architecture map shows the wiring a package level at a time (a matrix of wire counts between sub-packages in provider-first order, layers that light up what feeds and what is fed by a group, and the backward wires, cycles and rule violations that keep a level from being layered), higher-level readings of the wiring answer how the codebase is organized (module roles such as foundations and hubs, a package's real interface, the rules against the wires they admit, the slice and blast radius of a module or name split into import-time and on-demand, natural clusters against the declared packages, a generated onboarding tour, and the architecture diff of a branch against its merge base), and the code view adds semantic highlighting, hover, definitions, references, diagnostics and inferred types. Select modules, symbols and wires into a context tray and hand them to any ACP agent (Claude Code, Codex, Gemini CLI, your own) or the built-in byLLM agent, each started with `jac mcp` and hack mode's own MCP tools (`studio_selection`, `studio_focus`, `studio_graph`, `studio_insight`, `studio_link_plan`, ...). Every file an agent writes is held while the compiler checks it: the approval sheet shows the verdict, per-symbol changes, new diagnostics and architecture changes, lets you accept part of an edit symbol by symbol, sends the findings back on rejection, and requires a separate approval for wiring changes. Sessions persist on a root graph and can be resumed and forked; `jac hack model`, `graph`, `roles`, `interface`, `rules`, `slice`, `blast`, `clusters`, `tour`, `diff`, `ask`, `agents` and `sessions` work without the UI. See the [hack mode reference](../../reference/hack.md). Osprey, the Jac TUI framework hack mode is built on, now lives in the repository at `jac/jaclang/osprey`.
- **Native `signal` on macOS**: `signal` now has a macOS variant with the platform's signal numbers and messages. Osprey, now inside `jaclang`, resolves on the native pathway like any library, so programs built with `jac build --native` can use its types.
