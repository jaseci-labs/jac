- **Feature: the native compiler kernel compiles and checks every program**: a kernel compile returns each module's products (its JCIR, its client JavaScript and their metadata) as a record that the host assembles into bytecode. When a kernel is present it is no longer optional: a module compile, `jac check`, and the preparation of an application without client code (`jac run`) go through it, and a compile the kernel cannot finish is an error instead of a quiet host compile. An application prepares from one kernel session that emits a unit for every project module. `JAC_COMPILER_LIB=off` is refused outside a kernel build, and `JAC_KERNEL_COMPILE` no longer turns kernel compiles off. Three things still compile on the host: an application with client code or pages, a module placed in the native codespace, and a module whose analysis needs an integer past 64 bits. Tools that read syntax trees (the language server, `jac fmt`, lint) still parse in the kernel and receive a materialized tree. Native code also resolves module-qualified class references (`lib.Circle(...)`, `isinstance(x, lib.Shape)`), class patterns over imported archetypes (`case Circle():`), and classes an importer sees through a precompiled interface, which previously failed to lower.
- **Fix: static Linux native builds call libcrypto safely**: the vendored musl runtime now carries the glibc large-file entry points (`fopen64`, `pread64`, `stat64`, ...) that the floor archives call, so `hashlib` and other OpenSSL-backed code no longer jump to address 0 in a `jac build --native` executable.
- **Fix: native method calls that cannot be lowered fail loudly**: a call the native backend had no lowering for (for example `x.append(v)` on an `any` receiver) used to compile to nothing; it now reports E5092 and the function falls back to its Python implementation. Native `bytes.hex`, `bytes.fromhex`, `upper`, `lower`, `strip`, `lstrip`, `rstrip`, `split`, `replace` and `join` now lower, and static methods on primitive types (`int.from_bytes`, `bytes.fromhex`) share one dispatch path.
- **Fix: native locals first bound to `None` keep their type**: an unannotated local assigned `None` and later an object no longer loses the object's type, which made the value read back as a string when stored in an `any` container. A method defined on a generic base (`Registry[int]`) is now callable natively through a subclass.
- **Fix: native methods no longer release their receiver**: a method that copied `self` into a local and then reassigned that local (`nd = self; ... nd = nd.parent`) released a reference to `self` it never held, because the implicit receiver was classified as an ordinary local and the copy was compiled as a move. Each call dropped the receiver's reference count by one until a still-reachable object was freed; in the native compiler this crashed `jac check` on files that assign globals inside `with entry`. The receiver is now classified as a parameter, so it is never moved.
- **Fix: native `and`/`or` return an operand when the operand types differ**: `a or b` over a union and a plain object (or any two values the backend stores differently) used to evaluate to its truth value, so `cast(T, x or default)` produced the integer 1 instead of an object. Such operands now meet as a boxed value, and a pair that cannot be boxed fails to lower with E5092 instead of silently becoming a bool. `cast(T, x)` also keeps `x`'s ownership, so reading a field through it no longer releases the local.
- **Fix: native overrides called through a generic base return their value**: when a subclass overrode a method of a generic base and the two lowered to different return shapes (for example `(V | None)` on the base and `(str | None)` on a `str` subclass), a call through the base read the override's optional wrapper as the value itself and got the address 1. Each vtable slot now has the signature of the class that introduced it, and an override that lowers differently is called through an adapter.
- **Fix: a native function returning the same local twice in a tuple keeps it alive**: `return (x, x, name)` handed the tuple two references to `x` while holding only one, so releasing the tuple freed `x` under the caller and later allocations overwrote it. Each repeated slot now takes its own reference.
- **Fix: native `int()` parses strings the way CPython does**: `int(text)` and `int(text, base)` in native code now accept surrounding whitespace, a sign, `0x`/`0o`/`0b` prefixes, single underscores between digits and bases 2 to 36, and raise `ValueError` with CPython's message on anything else.
- **Fix: native loops over `enumerate` and `zip` unpack tuple elements**: `for (i, (a, b)) in enumerate(pairs)` and `for (pair, tag) in zip(pairs, tags)` read a tuple taken out of a list as a tuple, where they used to read its pointer as the first field.
- **Fix: a container converted out of an owned `any` belongs to the caller**: returning a list or dict read through an `any` that the function owned freed the container under the caller.
- **Fix: the stub catalog carries empty package stubs**: `import urllib.error` and the other stdlib packages whose `__init__.pyi` is empty resolve from the catalog instead of being parsed again.
- **Fix: a native conditional expression over objects keeps the object on both branches**: in `a.field if isinstance(a, T) else a`, with `a` drawn from a list of a union of archetypes, the two branches met as a boxed value in which one was tagged as a string, so every later `isinstance` on the result was false. When the expression's type is an object, the branches now meet as the object pointer they both are.
- **Fix: native `and`/`or` over an object and a container tests the container's length**: `if obj and items` was true for an empty `items`, because the pair met as one bare pointer whose truth is only whether it is null. A container met with another kind of pointer now meets as a boxed value that keeps its tag.
- **Fix: a native builtin called in a loop no longer grows the stack**: `os.path.realpath`, `os.getcwd`, the `stat`-backed `os.path` calls, `str.strip`/`split`, `input`, `random.seed`, OSP edge predicates and parallel-`for` setup each allocated their scratch space where the call was emitted, so a loop kept every iteration's copy until the function returned and a few hundred `realpath` calls overflowed the stack. The scratch space is now one slot per function.
- **Fix: native tuple unpacking of `str.partition` and `str.rpartition`**: `(head, sep, tail) = text.partition(",")` crashed in native code, because the call hands back a list of three strings while unpacking read the value as a tuple. Unpacking now reads the value it is given. Folding `partition` on a constant took the compiler kernel down the same way.
- **Fix: `import from pkg { Name }` on a case-insensitive filesystem**: on macOS, importing a class from a package that also holds a module spelled the same in another case (`ExecutionEngine` beside `executionengine.jac`) bound the name to the module in a kernel compile. An import item is matched against the directory by the name as written.
- **Fix: an app image no longer carries a link into its own packages**: compiling a module inside a vendored package linked the package into itself (`.jac/packages/<scope>/<name>/.jac/packages/<scope>/<name>`), and the image then failed to unpack with `AbsoluteLinkError`. A package that already sits in a mounts directory is found there.
- **Fix: a module wired by `arch.jac` to another app is not compiled into this one**: preparing an application in the kernel emitted every module the project's wiring names, so `jac build web` compiled the `cli` app's modules under the web app's lint settings. Only the modules the entry reaches are emitted.
- **Fix: generated call arguments rewritten in place are kept**: narrowing a filter's argument and rebinding a C cell edited a copy of the argument list in a kernel compile, which produced `name '_jac_ccell1' is not defined` and filters that matched nothing.
- **Perf: the kernel's host snapshot no longer parses every compiler module a program reaches**: a cold compile of a large application parsed each interface-served `jaclang` module to learn its imports, which took minutes. Those modules are linked by path, so only the ones the project imports directly are scanned.
- **The kernel's host snapshot answers what it missed**: when a kernel compile or check reports an answer its snapshot lacked (an import resolution inside a `jaclang` module it had to read from source, a path's workspace), the host answers that question and the kernel runs again, instead of failing the module with "the kernel lacked host answers".
- **Perf: the services of a client application prepare with it**: `jac run` on a web app prepared the app on the host and each of its service apps through its own kernel session, which more than doubled the time to a ready dev server. An application with a client now prepares on the host as a whole.
- **Perf: `jac scale deploy` no longer compiles a helper script to bake serving metadata**: the seal step wrote a small Jac script that imported the compiler's own packaging modules and ran it, which cost a full cold compile of that script on every first deploy. The step runs the same calls directly.
