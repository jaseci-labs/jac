- **Fix: Writes made inside an HTTP SSE stream are committed**: A function or walker that streams its result over HTTP (SSE) used to lose every write its stream body made, in both colocated and fleet deployments, because the request scope closed when the response was returned, before the body ran. The response body now owns its request scope: the stream's writes commit when the producer is exhausted (before the terminal `end` event, so a write conflict at that commit arrives as an `error` event instead) and roll back when the producer raises or the client disconnects mid-stream. A stream holds one open transaction for as long as it runs: its first graph read or write opens it and the commit at its end closes it, so the database's idle-in-transaction timeout (300 s on the Postgres `jac` starts) bounds how long a stream may go without touching the graph. A stream that runs inside another open unit, such as a same-app bridge call, leaves commit and rollback to that unit however it ends.
