- **byLLM: a configurable timeout for non-streaming `by llm()` calls**: `[byllm.call_params] timeout` bounds a single non-streaming request, in seconds, and is overridable per `Model(timeout=...)` and per `by llm(timeout=...)`. It defaults to `600.0`, matching the limit LiteLLM was already applying, so nothing changes until a project lowers it; `0` drops the bound entirely. A request that outlives it raises the new `LLMTimeout`, importable from `byllm.lib`. Because `LLMTimeout` also subclasses `litellm.Timeout`, byLLM's own retries still treat it as transient and an existing `except litellm.Timeout` keeps catching it. It bounds one request, not one turn: retries and ReAct iterations both multiply it. See [Request Timeout](../../reference/plugins/byllm.md#request-timeout).
- **byLLM: the `http_client` transport honors the request timeout**: it hardcoded a 60s `httpx` client and posted its parameter dict verbatim, so a resolved timeout was both ignored and serialised into the JSON request body as a stray field. This also fixes the streaming `http_client` path, which forwarded a non-serialisable `httpx.Timeout` object in that body and so raised before the request was sent; a stream over that transport now gets its intended per-phase connect, read, write and pool bounds instead of a flat 60s.
