- **Native: an assertion's computed message is what its error says**: `assert cond, <message>` carried its message into the `AssertionError` only when the message was a string literal; one that was worked out (a concatenation, an f-string) was dropped and the error said only `assertion failed at <file>:<line>`. The message is now evaluated when the assertion fails, and only then, and raised with the place appended as a literal message has it. A message that is `None` or not a string still says `assertion failed`, and the message is freed once the error is handled.
