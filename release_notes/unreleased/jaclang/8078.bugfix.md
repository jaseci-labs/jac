- **f-string literal text survives the trip to JavaScript**: ECMAScript codegen re-derived each literal chunk of an f-string from the raw token text, stripping a leading and trailing character whenever the chunk happened to start with a quote, so `f'x "{a}" y'` compiled to `` `x "${a} ` `` and `f'"{x}"'` lost both quotes; the corruption was silent, and a shell command built as `f'{jac} {cmd} "{file}"'` shipped without its closing quote. It was never about the outer quote style: any literal chunk beginning with `"` or `'` was clipped, in double-quoted and triple-quoted f-strings alike. Chunks now come from the same `lit_value` accessor the native backend uses, which knows that an f-string's pieces carry no delimiters and decodes escapes (so `rf"\d+ {x}"` keeps its backslash instead of emitting a bare `d`). The emitted text is also escaped for its template-literal context, which it never was: a backtick, a `${`, or a backslash in the literal part of an f-string previously produced invalid or wrong JavaScript.
