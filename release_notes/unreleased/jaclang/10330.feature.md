- **Performance: freeing a candidate cycle root no longer searches the root buffer**: under the default `managed` profile, an object that a release leaves alive goes into the cycle collector's root buffer. When such an object was freed later, the buffer was searched backwards for its slot, so each of those frees cost time proportional to the buffer, which holds 1000 entries or more. The object's slot is now recorded in its header when it is buffered, and freeing it clears that slot directly. Dropping lists of 900 such nodes runs 83% fewer instructions per node (0.26 s instead of 1.28 s for 9 M nodes), and binary-trees under `managed` runs 33% fewer instructions (4.19 s instead of 5.09 s).
