- **The parser and the sealed prefix cross once, and the flip goes live**: `parse_and_run_prefix` is the entry the default-routing driver has been asking for -- one call into the sealed artifact parses the source and runs the claimed prefix passes over the native tree, and the driver drops what ran from the staged schedule. The frontend maps the claimed schedule onto the sealed prefix order, finishes the parse through the same `_finish_parse` the staged route uses, and replays the crossing's alert rows through `deliver_alerts` with `from_pass` resolved from the claimed name; rows carry a pass ordinal so a row attributed to the wrong pass is a seal failure rather than cosmetic drift. `serves_prefix()` keeps an older sealed artifact declining quietly as `prefix-entry-absent` instead of arming and exploding. The native frontier is seat one (`ASTValidationPass`) -- the pass proven to execute natively -- and later seats run staged until each is proven, with the decline naming itself. A new seal canary compares native against staged on three corpora: executed-vs-frontier, the alert stream field by field, unparse-exact trees, and post-pass symbol fingerprints. Running sealed passes over native trees for the first time exposed a train of real backend defects, each fixed at its mechanism: the pass tier was silently no-oping because method devirtualization was decided from state that filled in emission order; a union receiver addressed the base of its first member rather than the one its members share; the field dispatcher now serves fields the anchor class never declared; the materializer carries a non-empty string set across instead of returning a null handle; `str` over a boxed `any` rendered the box tag instead of the value; diagnostic templates fill by substitution so both tiers render the same message; and a void value boxes into `any` as `None` rather than refusing.
