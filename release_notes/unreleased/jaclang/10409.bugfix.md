- **Fix: the semver gate catches a `has` field change that moves a constructor argument**: an archetype's constructor binds positional arguments to `has` fields in declaration order, inherited fields first, so inserting a field before an existing one, reordering fields, or adding a field to a base class changes what an unchanged positional construction builds (`Foo(7)` against `obj Foo { has b: int = 2; has a: int = 1; }` sets `b`, where it set `a`). The API diff called these minor or no change, so `jac publish` and index verification accepted them as `1.4.0 -> 1.5.0` or `1.4.1`. They are now major, as is a required field that a base class adds, which every existing construction of a subclass must now pass, even when that base is private. A field appended after the existing ones is still minor, and an archetype with its own `init` is compared through that `init`. The exported API format is now 2; packages published with format 1 still verify, and the order check is skipped against them.
