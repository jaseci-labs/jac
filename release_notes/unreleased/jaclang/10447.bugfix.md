- **`@effects` declarations are recognised again when the native kernel compiles the app**: since 0.38, an endpoint calling a helper declared with `@effects(reads=[...], writes=[])` was served as `unknown: true, writes: ["*"]` whenever the helper's body did more than a plain `visit`/`report`, so the client RPC cache stopped caching it and every call flushed the cached readers. The kernel loads `jaclang.lib.effects` from the stub catalog, where `effects` has no function node, and the decorator check only accepted a function node. It now recognises the decorator by where `effects` is defined, so declared readers are cacheable again with a `Declared effects of ...` assumption.
