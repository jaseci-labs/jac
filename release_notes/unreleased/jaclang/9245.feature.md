- **Desktop apps build and run on macOS**: `jac run`, `jac build` and `jac run --dev` on a desktop app now work on a Mac with only the Xcode Command Line Tools installed (`xcode-select --install`). The native host renders in WKWebView through the same pinned webview binding Linux uses with WebKitGTK, and `jac build` ships the app as a `<Name>.app` bundle: the executable and `libwebview.dylib` under `Contents/MacOS`, the sealed image and client bundle under `Contents/Resources`, and an `Info.plist` filled from `[desktop] name`, `identifier` and `version`. A new `[desktop] icon` option names a `.icns` or `.png` for the bundle. A macOS app keeps its graph and session under `~/Library/Application Support/<identifier>` (Linux keeps them beside the binary; `JAC_DATA_PATH` overrides both). Hosts without a webview backend, such as Windows, are refused by name instead of with the Linux message.
