- **Importing an ambient typing name is a hard error, and the repo drops the imports**: the seventeen names `typing_ambient.pyi` provides in every module's scope (`Callable`, `Sequence`, `TypeVar`, `ClassVar`, `Literal`, `Protocol`, `Generic`, ...) no longer accept an explicit `import from typing { ... }` or `import from collections.abc { ... }` -- the W1103 advisory escalates to `E1125`, which names the remedy in the message and blocks codegen. The escalation waited on a per-name identity audit (`test_ambient_identity_audit.jac`): every name certifies IDENTICAL across spellings -- same canonical declaration (both import sources funnel to the typeshed `typing.pyi` symbol), same assignability verdicts, same diagnostic stream -- so dropping the import changes no type anywhere. What it can change is placement: a `typing`-sourced import whose names are not all native-erased is itself what held such a module off the native pathway (`native_default_verdict`: "unresolved import 'typing'"), so removing it lets the module go native where it otherwise lowers -- the direction the pathway wants, now visible instead of silently forfeited. Aliased imports (`Callable as Cb`) stay legal: the ambient set cannot provide a chosen local name. Bootstrap-compiled modules (`jaclang/jac0core/`) keep the W1103 advisory instead, because `jac0.py` resolves names solely through real imports and the remedy is not available there. Optional/Union are not ambient and their imports stay legal; their PEP-604 rewrite (`X | None` / `X | Y`) remains a style matter, audited identical at the checker tier.
