- **Fix: a type is read as a type everywhere** (#9267): whether a name sits in a *type position* -- an annotation, a return type, an `as` cast, a `type` alias, a generic bound, an `edge A --> B` endpoint -- was decided separately by five passes, and four of them knew a different part of the language. A native module whose only mention of a Python module was an `as` cast type or a `type` alias was refused for importing it at run time (E5090). An unresolved type inside an `as` cast, or nested more than eight nodes deep in an annotation, dropped from an error (E2018) to a warning and demoted the function to a Python seam instead of naming the type. A bare Python import used only in an `as` cast inside client code was reported as a client value use (E5084). A `comptime import` named in an annotation was reported as a compile-time value used at run time (E0033), although the checker had just resolved it. All five now share one answer, and a position added to the language reaches every pass at once.
