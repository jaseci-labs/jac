- **Feature: Sessions no longer start the database machinery until first use**: Constructing a `Session` (or asking `data_location()`/`repr()`, or committing/closing a never-used session) no longer builds the embedded-Postgres lease, store objects, or spawns the engine -- the store boots lazily, exactly once, on the first access that needs database truth or has work to persist. `data_location` answers from lease computation alone, so status probes stay spawn-free.
- **Feature: `jac db` probes no longer boot a stopped cluster**: `jac db status` on an initialized-but-stopped cluster printed `running: False` and then started the engine anyway -- running the start sweep and even creating the project database -- just to report row counts. Status now reports `stopped` (or `no database yet` when the project database has never been created) without touching the engine, and `jac db list`/`jac db drop` report the stopped cluster instead of dying on a raw connection error.
