- **Fix: Native void lambdas and calls through `any` values**: A `-> None` lambda with a single-expression body (`lambda (x: int) -> None { seen.append(x); }`) no longer fails native builds with E5020 (`ret i64 0` in a void function); it evaluates the expression and returns. A call through a value whose type carries no call signature (an `any`, or a `Callable` without a parameter list) no longer lowers to nothing on the native backend, silently dropping the call and its result: it reports E5092 and its function runs in the server codespace. Annotate such values `Callable[[...], R]` to keep them native. One such call was in the Python runtime itself: an ordering comparison between unorderable types (`1 < "a"`) raised its `TypeError` with an empty message, and now names the operator and both operand types.
