- **Fix: Native void lambdas and calls through `any` values**: A `-> None` lambda with a single-expression body (`lambda (x: int) -> None { seen.append(x); }`) no longer fails native builds with E5020 (`ret i64 0` in a void function); it evaluates the expression and returns. A statement call through an `any`-typed field (`self.on_event(x);`) no longer lowers to nothing on the native backend, silently dropping the call: it reports E5092 and its method runs in the server codespace, as an `any`-typed local call already did. Annotate such fields `Callable[[...], R]` to keep them native.
