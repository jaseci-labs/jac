- **jaclang.org ships as a desktop app, and the desktop target is workspace-native**: `jac run desktop` in `jac/examples/jaclang_org` opens the site in an OS webview backed by jaclang.org itself. `[apps.<name>.desktop]` overlays `[desktop]` per app (every plugin section now reads through the app-effective config), each desktop app builds under its own `.jac/client/<app>/desktop`, and the new `[desktop] backend` is either `"embedded"` or the URL of the server the app talks to.
- **The desktop host runs the one Jac server**: the desktop shell no longer copies loose sources into the bundle, runs a hand-rolled `http.server`, or routes walker calls through a native bind. It seals the program into an app image with the same `build_jab` as `jac build`, boots `JacAPIServer` on a loopback port serving the built bundle (`[serve] client_dist`) with the workspace's service apps colocated, and registers the desktop broker (`/__jac/*`: health, SSO session, OAuth start and callback, plugin events and invocation) as a `ServerExtension`. Walker and function calls are ordinary HTTP like in the browser, so workspace bridges route correctly and a remote backend is reachable.
- **Server assembly outside the CLI**: `JacAPIServer.serve_background()` runs the transport on a background thread with an ephemeral or fixed port; `[serve] client_dist` names the client bundle to serve; colocation of a workspace's service apps lives in `jaclang/server/assembly.jac` and applies to in-process servers too; and the served app is mounted under its own `/api/<name>` route alongside the root, so a client built for a sibling app can reach a web-app's walkers.
- **`jac build` seals the app it was asked for, through `jaclang/dist/seal.jac`**: sealing and jab packing move out of the CLI command into `build_jab`, and the seal receives the app name as one argument, so `jac build cli` in a workspace no longer stamps the default app's manifest.
- **`jac check` roots every module an app owns**: the workspace gate compiled one program per app and swept only the files no app reached, so a module an app imports was never body-checked. Every app-owned module is now its own check unit; a real `E1114` in the site's cli app that `jac build web` refused at the seal step surfaced and is fixed.
- **A workspace's apps can share one assets directory**: `[client.assets] dir` names the directory (relative to the project root) whose files are served at `/static/assets/<path>` and compiled into the bundle, instead of each app's own `assets/`. The static server resolves nested asset paths from source, and the `assets` section joins the merged client config so per-app overlays apply to it too.
