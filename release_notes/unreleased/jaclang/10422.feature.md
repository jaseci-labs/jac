- **Static assets: one shared resolver, and `public/` served at the web root by `jac serve` and vite dev**: a new core module, `jaclang.server.serving.static_assets` (`asset_root_table` / `resolve_asset` / `asset_cache_policy`), resolves an asset URL to a file against one ordered, jailed table of roots: `/static/*` from the client dist, `/static/assets/*` from the project `assets/`, and the web root from the client dist, then `public/`, then `assets/`. The monolith's `/static/*` and web-root handlers now resolve through it and answer through the existing `file_response` primitive, so cached assets get `ETag`, 304 and Range handling and a single cache policy (`no-cache` for HTML shells, `public, max-age=3600, must-revalidate` otherwise). There is no extension allowlist, so `.webmanifest`, `.wasm` and any other file inside a declared root are served. Under `jac start -d` the Vite dev server now points `publicDir` at the project's `public/`, so `public/brand/logo.png` is reachable at `/brand/logo.png` in dev too; the build config keeps `publicDir` disabled because the runtime serves `public/` from source. The `--scale` and local `jac start` gateways move onto the same resolver in a follow-up.
