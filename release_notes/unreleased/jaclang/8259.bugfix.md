- **Fix: a warm module cache no longer degrades a module's codespace** (issue #8257): on a warm cache every client-codespace probe raised `ImportError: cannot import name 'collect_assigned_symbols' from partially initialized module 'jaclang.compiler.symbol_utils'` and each module quietly became a server module (cold 0 failures, warm 37, deterministic). Three faults compounded, and each is fixed at its own root. **A pass reached a compiler module for the first time during a compile.** `get_ir_gen_sched` pre-imports the modules its passes import at run time -- `symbol_utils`, `layout_pass`, `type_registry`, `intrinsic_registry` -- inside the `_ir_sched_loading` window, precisely so any compile those imports trigger uses the reduced bootstrap pipelines. `get_symtab_ir_sched` kept no such window although it schedules `PlacementApplyPass`, which imports `jaclang.compiler.symbol_utils` at pass-run time (`placement.jac`, `placement_solver.jac`). So a symtab-only compile could be the first thing to import `symbol_utils`, and that import compiled `symbol_utils.jac` through the *full* pipeline, whose `CFGBuildPass.enter_node` and `EsastGenPass.exit_module` import names from `symbol_utils` -- re-entering a module Python was still executing. The symtab-IR schedule now keeps the same pre-import discipline, which closes the cycle rather than recovering from it, and a compile that still manages to re-enter the module being imported now raises `CompilerSourceError` naming the module and the rule instead of degrading. **The cache key was not a function of the module.** `_project_env_fingerprint` folds in `_module_codespace_mode`, which reads the *ambient* default codespace -- the ContextVar that whatever compile scope is in flight sets and restores -- so a compiler-source entry written under one scope (`cs=server`) was rejected under another (`cs=native`) with its source bytes unchanged, and every warm run recompiled it. The ambient codespace cannot reach such a module in the first place, since `parse_str` excludes the internal program from placement inference, so compiler-source modules now key as `internal` while a user module keeps the ambient value that does decide its placement. **The degradation was silent.** `module_is_client` answered "server" for any probe failure, so a compiler-source `ImportError` read as a codespace verdict. A failure whose origin is the compiler's own source now raises `CompilerSourceError` naming the probed file and the offending module instead of answering, while a failure in the probed source keeps the note and the server fallback it always had.
