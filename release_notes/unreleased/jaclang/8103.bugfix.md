- **Fix: internal work no longer mints permanent databases in the shared Postgres cluster**: the runtime creates one database per absolute project path in the machine-wide cluster at `~/.cache/jac/pg/main`, and nothing ever dropped one, so anything that ran from a throwaway path leaked 8 MB of empty catalog forever. The test harness minted a fresh temp base path for every collected file and every test item, which made a `jac test` invocation cost roughly one database per test (measured: 9 databases for a 3-test file with 2 workers; a developer machine reached 31,617 databases and 241 GB). Deploy bundling did the same once per attempt, because its precompile stage lives under a `mkdtemp` path that never repeats. Work that needs no persistence across invocations now opens a scratch store instead: one process-scoped database, wiped when the scratch base changes so per-test isolation is unchanged, and dropped when the process exits. A `jac test` invocation now leaves zero databases behind, a deploy attempt leaves zero, and steady state is genuinely one database per real project. A cluster start also reaps scratch databases whose process is gone, so a crashed run self-heals. Deploy staging directories under `/tmp` now carry their owning pid, are removed when bundling exits, and stale ones from dead processes are reaped before a new stage is written.
