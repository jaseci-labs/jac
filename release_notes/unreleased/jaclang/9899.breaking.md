- **Breaking: auth has a declared policy, with new password defaults and moved config keys**: `[serve.auth]` now says which identifiers an account needs (`[serve.auth.identifiers] username` / `email` = `"required"`, `"optional"` or `"off"`, both `"optional"` by default so an account registers with either, plus `login_with`), how strong a password must be (`[serve.auth.password]`: `min_length`, `max_length`, `require`, `reject_common`, `reject_identifiers`, `breached_check`, `history`, `max_age_days`), whether email must be verified (`[serve.auth.email] verification` = `"none"`, `"optional"` or `"required"`, and `allowed_domains`), whether self-registration is open (`[serve.auth.registration] enabled`) and how many failed logins are allowed (`[serve.auth.lockout]`, 10 per 15 minutes per source address and identity by default). One module checks every write path (register, password change and reset, add-identity, rename, admin create) and answers `400 POLICY_VIOLATION` with every violated rule in the error `details`. Clients read the active rules from the public `GET /user/auth-policy`. What changes for an existing app: a new or changed password needs at least 8 characters and may not be on the bundled common-password list; a new username may not contain `@`; the bootstrap admin no longer defaults to `changeme` (unset, a dev server mints a one-time password and logs it once, and a cluster needs `[scale.admin] default_password` or `JAC_SCALE_ADMIN_PASSWORD`); `[scale.auth]` is removed and its keys live in `[serve.auth.email]`; `[serve.auth] password_hash_cost` is `[serve.auth.password] hash_cost` and the `registration_*` keys are `[serve.auth.registration] challenge` / `attempts_per_hour` / `challenges_per_10_minutes`. A leftover old key stops the server at startup with a message naming the new one. Existing accounts are never locked out by a policy change, because rules apply when a value is written. Also fixed on the way: an SSO login into an account with a verified second factor now gets the same challenge a password login does, a rejected password no longer consumes a reset token, and `[serve] public_origin`, `[serve.auth] session_cookie` and `[serve.auth.second_factor]` can be set in `jac.toml` as well as by environment variable.
