- **Fix: Same-named archetypes in different modules build natively**: Two modules that each define a `node`, `edge`, `obj` or `walker` of the same name no longer collide in native builds (`native struct name collision`, then an internal error, a fallback to the server codespace or a silent miscompile). Each archetype's native identity is now scoped by its defining module, so constructors, field access, `[?:T]` and edge filters, walker entry dispatch, `isinstance` and `spawn` each reach their own module's type, while `__name__` and diagnostics keep the source name. The scope is derived from the module's path within its package or project root, so a relocated package keeps the same identities, and a unit's native interface record and the `<artifact>.layout.json` sidecar name archetypes by source name (the sidecar keys two linked modules' same-named classes by their scoped identities).
