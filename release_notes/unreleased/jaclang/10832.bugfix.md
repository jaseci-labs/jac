- **Fix: A 401 from another app no longer leaves the page half signed in**: When a walker or function call to another app (`opts["app"]`) came back 401, the client runtime removed `jac_token` without resetting the page, so components already on screen stayed signed in while new ones rendered signed out. The runtime now resets the page whenever it removes a rejected token, whichever app answered (a reload on the web, the `/login` screen on native), and the call still raises `BridgeRejected`. A 401 for a call that sent no token no longer resets the page. With desktop profiles, where the host puts a fresh token back on every load, a profile gets one such reset, so a server that keeps rejecting its token cannot reload the app forever.
