- **Fix: A 401 from another app no longer leaves the page half signed in**: When a walker or function call to another app (`opts["app"]`) came back 401, the client runtime removed `jac_token` without resetting the page, so components already on screen stayed signed in while new ones rendered signed out. A rejected token now resets the page whichever app answered (a reload on the web, the `/login` screen on native), as it already did for the page's own app, and the call still raises `BridgeRejected`. With desktop profiles, where the host puts a fresh token back on every load, a profile gets one such reset, so a server that keeps rejecting its token cannot reload the app forever.
