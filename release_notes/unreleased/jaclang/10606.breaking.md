- **Breaking: The request binder checks JSON values instead of reshaping them**: A served walker or function used to convert a JSON value to fit the declared type, so `19.99` became `19` for an `int`, an object became its repr for a `str`, and `""` became `False` for a `bool`, all with a 200. A JSON value of the wrong type now answers 422 naming the field. That includes `"12"` for an `int`, `1` for a `bool` and `5` for a `str`, so a client sending a browser input value to a numeric field needs `int(e.target.value)`. Only conversions that lose nothing stay allowed: `3.0` for an `int` and `3` for a `float`. A float too large to be an exact integer, such as `1e300`, is refused for an `int`, and so are JSON object keys that parse to the same value for a `dict[int, str]`. Query, path, header and form values are still parsed, because they are always text, but `" 12 "`, `"1_000"`, `nan` and `inf` are refused, and a repeated value on a field that takes one value answers 422 instead of using the first. `Literal`, tuple length, including `tuple[()]`, and sized integer ranges are now enforced, and an enum takes its member values under the same rules, so `true` no longer matches a member whose value is `1` and `?p=1` now does. Validation errors for these rules no longer repeat the value that was sent. `datetime`, `date`, `time` and `UUID` fields, which could not be set over HTTP, now take a string. A file field no longer accepts a value that isn't an upload, so `5` for `UploadFile | str` answers 422. A repeated query value now reaches every collection field, including `list[T] | None`. OpenAPI shows `datetime`, `date`, `time` and `UUID` as strings rather than object references, and sized integers as integers, which can change generated clients. In microservice mode, a call from one service to another goes through the same checks, so a wrong JSON type there now answers 422, while monolith mode calls the function directly and still accepts it.
