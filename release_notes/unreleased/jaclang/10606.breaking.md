- **Breaking: The request binder checks JSON values instead of reshaping them**: A served walker or function used to convert a JSON value to fit the declared type, so `19.99` became `19` for an `int`, an object became its repr for a `str`, and `""` became `False` for a `bool`, all with a 200. A JSON value of the wrong type now answers 422 naming the field. That includes `"12"` for an `int`, `1` for a `bool` and `5` for a `str`, so a client sending a browser input value to a numeric field needs `int(e.target.value)`. Only conversions that lose nothing stay allowed: `3.0` for an `int` and `3` for a `float`. Query, path, header and form values are still parsed, because they are always text, but `" 12 "`, `"1_000"`, `nan` and `inf` are refused, and a repeated value on a field that takes one value answers 422 instead of using the first. `Literal`, tuple length and sized integer ranges are now enforced. `datetime`, `date`, `time`, `UUID`, `Decimal` and `Path` fields, which could not be set over HTTP, now take a string, and `Decimal` also takes a number. A repeated query value now reaches every collection field, including `list[T] | None`. OpenAPI describes these types as they are accepted, so enums and `datetime` appear inline rather than as object references, which can change generated clients.
