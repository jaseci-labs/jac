- **Breaking: The request binder checks JSON values instead of reshaping them**: A served walker or function used to convert a JSON value to fit the declared type, so `19.99` became `19` for an `int`, an object became its repr for a `str`, and `""` became `False` for a `bool`, all with a 200. A JSON value of the wrong type now answers 422 naming the field. That includes `"12"` for an `int`, `1` for a `bool` and `5` for a `str`, so a client sending a browser input value to a numeric field needs `int(e.target.value)`. Only conversions that lose nothing stay allowed: `3.0` for an `int` and `3` for a `float`. Query, path, header and form values are still parsed, because they are always text; a repeated form value for a `str` field now answers 422 instead of storing the list's repr. In microservice mode, a call from one service to another goes through the same checks, so a wrong JSON type there now answers 422, while monolith mode calls the function directly and still accepts it.
