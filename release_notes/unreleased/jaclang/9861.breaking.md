- **One set of typing rules for every codespace; native placement is decided after analysis**: a module that prefers native used to be type-checked in a native context first, with native-only rules and with its standard-library imports typed against the native reimplementations, and was analyzed a second time for the server when that failed. Every module is now parsed and type-checked once by the same rules. What only matters natively (an un-narrowed optional operand, a membership test over an untyped operand, a standard-library member or parameter the native library lacks) is recorded on the typed module and read by the placement step, which stamps the module native only if nothing refuses it. A function that hits a native gap runs on its Python implementation; a module that cannot be native simply stays on the server, with no second analysis and no remembered verdict. `jac check` computes the same placement. **Breaking:** `open`, `iter` and `next` are typed by the Python stubs in native code, and `File` / `BinaryFile` are no longer ambient names (annotate with `TextIO` / `BinaryIO`). `swap`, `take`, `managed`, `Region` and `region_of` resolve in every module and require native placement: using one in code that cannot be placed native is error `E5090`. Native standard-library modules must conform to the Python interface (`E5114`); `urllib.request.urlopen` now returns an `http.client.HTTPResponse` read with `read()` and `getheader()` instead of an object with public `body`, `body_length` and header lists. A module pinned native, or native by its own C imports, that cannot lower is an error rather than a silent fallback. `[build] native_closure_cap` no longer has an effect.
