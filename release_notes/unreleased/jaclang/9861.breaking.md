- **One set of typing rules for every codespace; placement is decided once, after analysis, per element**: a module used to be stamped with a codespace before it was type-checked, and the checker applied different rules in native and client code. A module that preferred native and could not have it was analyzed a second time for the server. Every module is now parsed and type-checked once by the same rules, and nothing is stamped at parse time. What only one codespace has (a browser global, a native-only builtin, an `awaiting` clause) records a requirement; what a codespace lacks (a native standard-library member or parameter, a client or native capability) records a refusal. A single placement pass reads those facts per top-level element: an element with a requirement goes where it must, any other element goes to the project's default codespace unless something refuses it, and a reference between elements placed apart is allowed when the callee's signature can cross that boundary. A required codespace that is refused is an error; any other refusal just leaves the element where it can run. `jac check` computes the same placement. **Breaking:** `open`, `iter` and `next` are typed by the Python stubs in native code, and `File` / `BinaryFile` are no longer ambient names (annotate with `TextIO` / `BinaryIO`). Browser globals no longer shadow Python builtins in client code. `swap`, `take`, `managed`, `Region` and `region_of` resolve in every module and require native placement (`E5090` if the code cannot be placed there). A module declares an archetype name once; a second declaration per codespace is `E0077`. Native standard-library modules must conform to the Python interface and each platform variant must expose the same public surface (`E5114`); `urllib.request.urlopen` returns an `http.client.HTTPResponse` read with `read()` and `getheader()`. A pinned, forced or C-importing native element that cannot lower is an error rather than a silent fallback. The ownership rules run on every module and are errors only where the headerless runtime is required. `[build] native_closure_cap` no longer has an effect.
