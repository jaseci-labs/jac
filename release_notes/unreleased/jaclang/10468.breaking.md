- **Breaking: a local must be assigned on every path before it is read**: Reading a local that some path leaves unassigned is now error `E1006` on every backend, as in Java, C#, Swift and Rust. Python allows these reads and raises `UnboundLocalError` when the path runs; the native backend instead read a zero or a null and could crash with no output. The check follows the control-flow graph, so an assignment in every branch of an `if`/`else`, a `match` that covers its subject, or a `try`/`except`, a `while True` loop left by `break`, and a walrus in the true branch of `and` all count. A loop-carried read such as `if i > 0 { use(last); }` before `last = ...` in the same body is now rejected; assign the variable before the loop. The control-flow graph was rebuilt around one rule for where each statement continues, which removes a spurious edge from a `try` header past its body, a false exit from `while True`, the fall-through out of an exhaustive `match`, and adds missing `break` edges for a loop that ends an `if` body.
- **Breaking: defaults are evaluated on each call, in the function's own scope**: A default can read the parameters declared before it and is evaluated every time the parameter is omitted, so `def f(xs: list[int] = [])` gets a fresh list per call and `def f(a: int, b: int = a)` works on every backend. A default that reads its own or a later parameter is `E1007`. On the Python backend a non-constant default appears as `CALL_DEFAULT` in `inspect.signature`; passing that value explicitly behaves like omitting the argument. The `mutable-default` lint (`W3036`) is removed, since a `[]` or `{}` default is no longer shared between calls.
- **Breaking: one constructor rule for every backend**: An `obj` without its own `init` uses the first hand-written `init` in its method resolution order, or a generated `init` over every field (in reversed method-resolution order) when there is none, even when it declares no fields itself. Inheriting a hand-written `init` that would leave a field unset is `E1009`, and one that would never run the class's `postinit` is `E1012`; define an `init` in either case.
- **Breaking: stricter class and import checks**: An inconsistent class hierarchy is `E1008` from the checker instead of a native layout error. An override whose signature or field type is incompatible with what it overrides is `E1013`, and an override that changes an inherited default is `E1014`. Importing a name that a Jac module does not define is `E1145` on every backend.
- **Fix: checker soundness**: Arithmetic and other operators on an operand that may be `None` are `E1011` instead of passing as the non-`None` type, subscripting an Optional container is `E1040`, `E1004` (missing return) follows the control-flow graph and now covers `impl` bodies, and a read in one loop no longer resolves to a variable of the same name bound by another loop's `for`. A method on a diamond hierarchy dispatches to the class C3 puts first, and an inherited default override is seen through an intermediate class, on the native backend as well.
- **Fix: a bare assignment rebinds a `glob` declared anywhere in the module**: A function that assigns a name declared by a module `glob` rebinds that glob even when the `glob` comes later in the file. Before, such a function created a local on the Python backend and rebound the glob on the native backend.
