- **Fix: aarch64 conditional branches link, and the sealed build's arm legs build again**: The in-house ELF linker's aarch64 relocation table knew the unconditional branches and the page-relative `ADRP` forms but none of the conditional family, so any object carrying a `B.cond`, `CBZ`/`CBNZ`, `TBZ`/`TBNZ`, `LDR`-literal or non-page `ADR` was unlinkable on aarch64 -- a hole compiler-emitted code rarely hits and hand-written assembly hits constantly. It surfaced once a sealed root's closure grew far enough to pull the poly1305 core out of the bundled `libcrypto`, as `ELF shared linker: no handler for relocation type 280 (symbol 'poly1305_emit')`. `R_AARCH64_CONDBR19`, `R_AARCH64_TSTBR14`, `R_AARCH64_LD_PREL_LO19`, `R_AARCH64_ADR_PREL_LO21` and `R_AARCH64_ADR_PREL_PG_HI21_NC` are now handled, and a displacement too wide for its field is refused rather than masked into a branch to the wrong address -- the linker plants no range-extension veneers, so a truncated branch would be the only other outcome.
- **Fix: the native seal sizes its worker pool on macOS instead of reading every Mac as having no memory**: `seal_mem_available_gib` probed `/proc/meminfo` and `SC_AVPHYS_PAGES`, neither of which exists on Darwin, so it answered `0.0`, the auto-size resolved to one job, and one job routed back to the in-process sequential seal -- the single path whose peak is the sum over every native root rather than one root's high-water mark. That handed the smallest host the most memory-hungry strategy, and a 7 GiB machine is killed by the kernel partway through it, silently. The probe now reads Darwin's `SC_PHYS_PAGES` minus a reserve, and a job count that was *auto-sized* to one runs a pool of one worker process, which still forks per root and still releases each root's stranded native tree. `JAC_SEAL_JOBS=1` remains the explicit escape to the sequential seal: asking for one job and being sized down to one are different requests.
