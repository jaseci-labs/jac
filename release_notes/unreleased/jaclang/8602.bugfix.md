- **Embedded Postgres: initdb provision retries once and wipes partial clusters**: a slow or contended `initdb` (e.g. concurrent cold caches on one disk) blew the hardcoded 120s timeout and left a partial data dir that broke every later startup, since initdb refuses non-empty directories. Provision now resets the dir and retries once; the timeout is tunable via `JAC_PG_INITDB_TIMEOUT`. The retry never wipes a directory in which another process completed provisioning in the meantime (a completed `PG_VERSION` marker aborts the reset), and `serve()` now takes the same cross-process provision lock `ensure()` does, so a foreground serve can no longer race a concurrent cold start into a half-provisioned data dir.
