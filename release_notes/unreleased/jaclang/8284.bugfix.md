- **An `IntEnum` invoked as a constructor validates against its declared members**: `TypeFlags(...)` re-tags a cloned type's flags, and `TypeFlags` is an `IntEnum` rather than an `IntFlag`, so CPython raises `ValueError` for any value no member carries -- a combination of two bits included. Lowering the call to the identity would have dropped that check, so the backend refused the shape entirely. For an int-valued enum the member is the value, so the emitter now tests the argument against the declared member table the layout already carries and raises the same catchable `ValueError` on a miss, in both the `class X(IntEnum)` and `enum X { ... }` spellings. What cannot be lowered says which of two reasons it is: a string-valued enum's runtime form is the member's ordinal, so the lookup is not the identity, and a member declared with `auto()` folds to nothing, so there is no table to validate against -- the latter is now recorded on the enum layout rather than inferred from a member list the builder had already silently pruned.
