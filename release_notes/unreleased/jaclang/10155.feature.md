- **Performance: typed hops read only the edges that reach their node type**: edge rows now record their endpoints' types and the edge indexes carry them, so `[org-->][?:SalesOrder]` reads the edges into sales orders instead of every edge of the org and its node. Existing edges are backfilled at the next schema boot; edges with no recorded type still answer every hop. On Amplify's order list Postgres CPU per request falls 28-31% and throughput rises 15-22%; one org's hop to 150 sales orders among 4,891 edges goes from 21.7 to 1.0 ms.
