- **Persistence: One database per application**: Services now share one application database and automatically share persistent model identities based on application namespace, logical module and type name. Provider sessions retain the application database binding while resolving service-local classes. Rebuild compiled artifacts and explicitly migrate legacy path-derived type names and any previously split service databases. Sealed images and `.jab` bundles load every module through its service namespace, so a service reads stored nodes back as its own classes. Rows naming a runtime module for a type that has a durable identity, including sealed image package names, fail with the identity to alias. A renamed project warns when its old database still holds data.
