- **Fix: concurrent replica boot against a fresh database**: `ensure_schema` serialized its DDL with a process-local lock, but the tables, types and indexes it creates belong to the database every replica shares, so two replicas starting together on an empty database raced and the loser died with `23505 duplicate key` on the Postgres catalog. The critical section is now a session-level `pg_advisory_lock` keyed on the schema namespace, with the schema stamp re-read under the lock. Behind that, each schema statement now treats `23505`, `42P07` and `42710` as "a peer created this object first" and moves on, so a boot that cannot take the lock still converges instead of failing.
