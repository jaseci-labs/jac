- **Fix: A server endpoint used as a client value no longer ships an unbound name**: Client code that referenced a server-placed `def:pub` as a value (a callback argument, a container element, `return f`, a re-export) emitted a bare identifier the bundle never bound, and the module died at load with `ReferenceError`. Only *calls* were bridged. A `def:pub` endpoint reachable from client code is now emitted into the bundle as a real `async` forwarder, so the name works in every position. Calls are unaffected.
- **Fix: `E5086` replaces a runtime `ReferenceError` with a build error**: Before the client bundle is assembled, every module-level name that client-destined code emits must resolve to something the bundle binds. A reference no binding can cover -- an element pinned `"server"`, a glob kept server-side -- now fails the build at the seam that produces the artifact.
- **Fix: `W6009` reports the async result of a client forwarder**: The forwarder calls its endpoint over HTTP, so a value-returning endpoint reached as a value hands the client a `Promise<T>` where the server function hands back `T`. Fine for a command handler, wrong for a sort comparator, so it is now said out loud.
- **Fix: placement diagnostics are no longer silently swallowed**: `_check_placement_warnings` caught every exception and dropped `W6006`, `W6007`, and `E5084` together, with no trace. The swallow is gone. `W6007` also moved onto the same resolver the emitter uses, so `jac check` and `jac build` cannot disagree about what is bound, and it now points at the reference rather than the enclosing statement.
- **Fix: a nested `jac.toml` inherits the enclosing project's `kind`**: Kind resolution stopped at the nearest manifest, so an `extension/jac.toml` without a `kind` shadowed the kind of the project containing it and kind-driven placement never reached that module. An unset `kind` now inherits from the enclosing project root; an explicit nested kind still wins.
