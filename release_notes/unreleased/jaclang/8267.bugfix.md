- **macOS sealed and shared native artifacts resolve process symbols**: The pure-Jac Mach-O linker bound every undefined symbol without an explicit dylib mapping two-level to libSystem, so the first sealed artifact referencing a CPython C-API symbol (`libjac_uni_pass.dylib`, after sealing wave 1) failed its dlopen load canary on macOS with "Symbol not found: _PyDict_New", breaking every macOS dev-binary release build. Unmapped imports in shared objects now bind through the flat namespace (the `-undefined dynamic_lookup` convention for dlopen'd plugins), so they resolve from whatever the host process has loaded, matching how ELF artifacts already resolve on Linux; explicitly mapped symbols keep their two-level ordinal and executables are unchanged.
