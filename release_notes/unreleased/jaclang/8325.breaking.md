- **The deprecated `typing` aliases are a hard error, and the repo writes the builtins**: `List`, `Dict`, `Tuple`, `Set`, `FrozenSet` and `Type` are the PEP 585 aliases of builtins jac already subscripts directly, so carrying them meant a second name for each -- the bargain `Any` struck against `any`, refused now for the same reason. `E1123` follows the `E1122` playbook exactly: it fires at import resolution on every shape that binds the bare name -- plain, mid-list, and the `as` alias -- names the remedy in the message rather than only the help, and blocks codegen. Module form stays legal, as the escape hatch for reflection *over* annotations, which needs the runtime object rather than a type spelling; note that `typing.get_origin` normalizes `List` and `List[int]` alike to `list`, so an `is typing.List` test downstream of it can never fire, and the one such arm in the LSP's `from_dict` is deleted rather than propped up with a module-form import. Measured on the parsed tree across all 3,888 tracked `.jac` files: 10 bound aliases in 6 files, no module-form uses anywhere, and `FrozenSet`/`Type` imported from `typing` zero times -- they are refused prospectively at no migration cost. Five of the ten were imports of a name the file never used, so those import lists just lose a name; the rest become the builtin. `DefaultDict`, `Deque` and `OrderedDict` are deliberately not refused: their twins live in `collections`, not builtins, so they are a different remedy. One pin moved, and it is a spelling: the `import_semicolon` auto-lint fixture imported `List` only to have an `import from` statement to strip a semicolon from, and imports `Optional` now.
