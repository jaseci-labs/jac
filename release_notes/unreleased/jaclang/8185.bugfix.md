- **Fix: the native materializer builds a dict key it can actually build**: the seal-time materializer generator picked one key conversion per dict entry with `kt if kt in _SCALARS else "int"`, so every key type that was not `int`/`bool`/`float`/`str` was marshalled back through `PyLong_FromLongLong`, whose parameter is an `int`. The generated `compiler/native_materialize.jac` is compiled like any other module, so that is a plain type error on the generated source; it was unreachable only while no non-scalar-keyed dict ever reached a layout. `UniNode.__sub_node_tab` is declared `(dict[(type, list[UniNode])] | None)`, and until a `type` gained a native representation the layout pass reported the field as not layout-compatible, so the emitter erased it and the key conversion was never emitted at all. Once the field stopped being foreign the emitter reached it for the first time and the coercion became one hard `E1053` per class inheriting the field, aborting the native artifact build. A dict key now goes through the same dispatch its value already used -- scalars keep their own converter, an enum key routes through the enum emitter, a class key through the node emitter -- and a key type with no materializer declines the whole field rather than guessing, erasing it to `None` exactly as the not-layout-compatible path did before. A dict cannot be rebuilt without its keys, and for this field erasure is also what it wants: it is a derived index whose accessor rebuilds it on demand. Both consequences of the old assumption are fixed together, so a key can no longer type-check as an integer and then be marshalled as one at runtime. An erased field also stops emitting the dead load of its native slot, and the generator's warnings, which were collected and discarded, now reach the seal and print as `NATIVE SEAL:` warnings so an erased slot is never silent.
