- **Fix: a client parameter or local named `type`, `list`, `dict`, `str` or another builtin type reads its own value**: those names lex as type keywords, so every read of such a binding parsed as a builtin type and the JavaScript backend lowered it to `_jac.types.<name>`, the runtime's type object. A component prop named `type` called `.toUpperCase()` on that object and crashed, and a request built from it sent the type object instead of the value; `jac check` passed and the server-side Python was correct. The backend now lowers a read whose name resolves to a variable exactly like any other name, and keeps `_jac.types.<name>` for real type references such as `str(x)`, `isinstance(x, str)` and annotations.
