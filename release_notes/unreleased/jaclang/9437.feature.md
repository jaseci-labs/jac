- **Feature: a module `arch.jac` names is sealed in both directions**: The wiring file now follows one rule: whatever `arch.jac` names, `arch.jac` is the whole truth about. A module is *sealed* once the file names it anywhere, as a wire's provider or consumer, or by matching a rule's source or target pattern (`any` names nothing). A sealed module must write its project-module imports as wires (`E1144`, `W3053`), admits imports of itself only where a rule says, so a provider no rule names now flows nowhere (`E2090` with the rule to add), and may not import a project module inside a function body (`E2094`). Before, only a wire's consumer was covered and only a rule's source was constrained. `[arch] closed = ["*"]` in `jac.toml` (or a pattern list) seals modules the file never names, including packages not yet written, and applies before `arch.jac` exists. `E1144`, `E2090`, `E2091` and `E2094` ignore inline `# jac:ignore`, so loosening a boundary is an edit to `arch.jac` or `jac.toml`.
- **`jac arch` writes the rules a wiring needs**: Every wire now seals its provider, so a file of wires needs rules. `jac arch init` derives one `edge <Pkg>Flows` rule per top-level package from the imports it finds, `jac arch init <package>` wires one package and everything it imports from into an existing `arch.jac`, and `jac arch sync` adds the wires and rules sealed modules are missing. Modules under `[check.lint] exclude` are wired but never stripped, which is how a package a test builds standalone keeps its own imports beside its wires; a written import a wire also provides is bound once, since the generated copy is dropped as the module is parsed.
- **The check policy is part of the module cache identity**: `[check.lint]` select, ignore and exclude and the `[check]` suppress lists now fold into every module's environment fingerprint. Before, editing them replayed diagnostics cached under the old policy until something else invalidated the module.
- **A bootstrap-tier module takes the bootstrap codegen tail**: When the ir-gen schedule falls back to the bootstrap tier because a schedule dependency raised an ImportError mid-bootstrap, codegen for that module now takes the bootstrap tail as well instead of validating the full codegen schedule against facts the head never produced. Before, a cold first-use bootstrap could stop with `scheduling error: pass RcFactsPass requires analysis 'CfgSucc'` depending on which compiler modules the parent process had already cached.
- **A name used before its `import from` statement resolves to the provider's declaration**: `TypeEvaluator.resolve_imported_symbols` returned the consumer's own import binding whenever the module item already carried a symbol, which is always the case after symbol-table build, so a use site type-evaluated before the type checker reached the import statement kept that local binding. Nogc enforcement then read `Spark(x=1)` bound through a wire, or through a hand-written import placed below its use, as a value that is neither fresh nor owned (`E1406`). The evaluator now forces the module item to resolve before it answers, guarded against import cycles.
