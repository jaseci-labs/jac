- **Performance: native string comparisons are inline and check lengths first**: every native string comparison (`==`, `!=`, `<`, `<=`, `>`, `>=`) called an out-of-line helper that ran `memcmp` before looking at the lengths, so `s == "return"` paid a `memcmp` call even when the lengths differed. Comparisons are now generated inline. `==` and `!=` compare the lengths first and compare bytes only when they match, so a comparison against a literal becomes a few inline loads. The orderings compare only as many bytes as the shorter string has, so `c >= "a"` is a single byte compare. Results are unchanged. A lexer-style benchmark (keyword matching and character classes, `jac build --native`) runs 15.5% faster (159.6 ms to 134.8 ms) with 14.7% fewer instructions.
