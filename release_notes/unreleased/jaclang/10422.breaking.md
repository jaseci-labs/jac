- **Breaking: `jac serve` no longer serves `src/` or basename-matched files at the web root**: the monolith's web-root handler searched `src/` among its roots, so source files under `src/` with a servable extension (`.js`, `.css`, `.json`, ...) were downloadable at the web root -- a source-exposure hole. It now resolves only through the shared, jailed resolver (`Path.resolve()` + `is_relative_to()` on every root, exact path only), so those URLs return 404. Also now 404: URLs that only resolved by filename, where `/some/dir/logo.png` found `assets/logo.png` -- put the file at its exact relative path -- and files in a project-root `dist/`, which is no longer an asset root (`.jac/client/dist` is) because `dist/` is excluded from the `--scale` bundle and so returned 200 locally but 404 in Kubernetes. The blanket one-year immutable `Cache-Control` on web-root assets is replaced by `public, max-age=3600, must-revalidate`; the hashed long-cache split is tracked in #8126. Put static files under `public/` (served at the web root) or `assets/` (served at `/static/assets/`).
- **Breaking: `jac serve`'s `/static/*` serves only the client dist and `/static/assets/*`**: the monolith's `/static/` handler also tried a project-root `dist/` and `assets/` under the bare URL, plus basename matches, so `/static/logo.svg` could return `assets/logo.svg`. `/static/<path>` now resolves only from `.jac/client/dist`, and project assets only at their exact path under `/static/assets/<path>`; update URLs that relied on the shorter form.
- **Breaking: symlinked assets that point outside their root no longer resolve**: the resolver's jail requires the fully resolved target to stay inside the resolved asset root, so a symlink under `public/` or `assets/` whose target sits outside that root now returns 404. If you symlinked a shared assets directory into `public/` or `assets/`, copy or bind-mount the files instead.
