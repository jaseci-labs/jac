- **No-GC ownership transfers preserve lifetimes**: Moving an optional owned local clears its source and drops an overwritten destination. Returning a string borrowed from a local container copies its storage before the container is destroyed, preventing use-after-free.
- **Native entry errors remain fatal after symbol qualification**: Unhandled errors in native executables report their diagnostic and exit unsuccessfully in both object and bitcode link modes. Diagnostics are flushed before aborting so redirected output is preserved.
- **Native cache identity follows build settings**: The compiled `flow for` thread default participates in the codegen fingerprint, and unit products retain their target and codegen identity. Native coverage includes units served from the cache.

- Native JIR sections retain separate target and codegen variants, and cache writes lock the complete merge transaction. Concurrent native and bytecode builds no longer evict shared runtime products or lose unrelated sections. Replacing bitcode invalidates its previous optional object. Kernel builds reuse the same bootstrap-safe file-lock primitive.

- **Atomic native output publication**: Linkers replace complete binaries and sidecars on a new file identity, preserving running or open executable images and avoiding stale macOS code-signing state during rebuilds. Module cache entries use the same atomic writer.

- Native unit compiles request a complete source tree.

- Native-to-bytecode cache transitions preserve all stamped native products. New atomic files respect the process umask, and kernel readers verify the artifact hash while libraries and sidecars are replaced. Failed native cache writes report their cause.
- Unit-specific string constructors remove memory-mode-dependent weak definitions. Object and bitcode links traverse units in the same order. Shared native engines use local symbol visibility; sealing rejects Python imports that require a JIT bridge.

- A native interface read from the module cache is accepted only when its body hashes to its recorded digest, and the link plan's staleness checks read that verified digest; a corrupted entry is recompiled instead of trusted. A native write prunes every native section's stamped variants to the compiler digests it carries, so a compiler upgrade no longer accumulates old products. Module cache writes lock through a small pool of lock files under the cache generation directory instead of leaving one lock beside every entry.
- A native unit persisting only its stamped products no longer replaces the interop manifest the bytecode compile wrote, and a Python-lane metadata refresh with stale or changed provenance drops the bytecode, manifest, module IR and client artifact it can no longer vouch for while leaving the self-validating native sections in place.
- A unit's native layout keeps a public function that shares its name with a foreign symbol reaching it from a dependency (cmath's `sqrt` beside libm's), so a consumer links the unit's function instead of routing the call to the foreign extern and failing on its signature.
- A check that only needs a native dependency's interface lowers it without optimizing, emitting or persisting its products.
- A kernel sidecar records the kernel's inputs one by one (compiler digest, codegen identity, target, interpreter and a per-unit digest of source, annexes and wiring), and a checkout accepts the kit's kernel by comparing them, so a rerouted checkout built into the running kit adopts that kernel instead of deriving one on every fresh cache.
- Native products are stamped per unit with the codegen identity every unit shares plus whether the placement policy names that unit, so a kit's sealed products serve consumers without the build's policy; a native pass only lowers a dependency that placement makes native; and native record lookups fall back to the precompiled tree beside the package, sealed or key-validated.
- A module compiled from a string, which has no cache entry of its own, still reads its file-backed dependencies' native records instead of lowering the runtime units it imports for every snippet.
- The kit re-stamps the kernel sidecar's artifact hash when it strips the library, and a checkout adopting the kit's kernel validates the library against the kit manifest and publishes a sidecar carrying that hash, so the first run of a rerouted checkout no longer derives a kernel the kit already carries.
- A native source export internalizes and optimizes the merged program before the C backend translates it, so the exported C holds the functions the entry reaches instead of every unit of the runtime closure.
- Kernel acceptance at process start reaches only the cache-key module (the sidecar's unit paths and per-unit digests live there and the resolver hashes the library itself), so the bootstrap tier no longer imports the link plan while it is still compiling the runtime.
- The floor archive and static runtime lookups a native link consumes moved out of `linker_common` into `static_link`, so an exported project's wasm tooling no longer pulls the runtime, the fused-binary support and the compiler into its vendored closure (492 modules where main vendors 16).
- A client-placement invalidation drops a module's Python-lane products and keeps its stamped native sections, instead of deleting the whole cache entry. A write that relowers a unit without bringing bitcode (a new interface or dependency record) drops the bitcode and object compiled before it, so a stale body is never linked against a newer interface.
- A seal records each native unit's JIR hash after the plan's products are carried into the sealed twin, so a sealed image's manifest verifies against the file it ships.
- A native dependency reference that names no reachable root is looked up under the import path, and one found nowhere reads as missing instead of resolving against the working directory. Two units whose roots share a directory name are refused by the link plan by name rather than merging their private symbols.
- Heap accounting (`jac_heap_size`, `jac_list_heap_size`) links under `gc=none` whenever the units keep allocation headers; only a nogc-enforced, headerless unit is refused, with a message that says so.
- A kernel build child that imports the kernel resolver while compiling it parses with the store parser without raising, and resolves the kernel once the resolver has loaded.
