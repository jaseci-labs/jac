- **Feature: `arch.jac` declares a project's module wiring**: A file named `arch.jac` beside `jac.toml` holds `impl import [scope] { ... }` blocks. A wire `provider --> consumer { names }` (or `provider --> consumer;`) generates that import into the consumer at compile time and covers the consumer: every project-module import it still writes must match a wire, item by item. A matched one is `W3053` with a `jac fmt --lintfix` autofix that removes it; an unmatched one is `E1144`. A rule `edge Name: pattern --> pattern [{ names }]` constrains a provider on mention, whether the import is written or wired: a flow no rule admits is `E2090`, a name a payload rule does not list is `E2091`. Wires connect project modules only, so standard-library, installed, npm and asset imports stay in the module file, while a rule may still name such a provider. Inside `impl import core.docs { graph --> web.main { doc_page } }` the left side is relative to the header and the right side is always absolute. Wires are woven in as annex source aligned to their `arch.jac` lines, so `W1100`, `W1101` and `W2003` point at the wire that caused them, and a module's cache key folds in only its own wires plus the rule set. `jac arch init --strip` writes `arch.jac` from the current imports and strips them from the modules, `jac arch sync` adds the wires a covered module is missing, and `jac arch graph` renders the wiring as mermaid or JSON.
