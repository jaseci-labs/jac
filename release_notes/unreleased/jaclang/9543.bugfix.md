- **Fix: an imported subclass keeps its base's slots after a unit reload**: When a consumer reached an imported subclass (for example `node Pickup(Entity)` with `Entity` from a third module) through a sibling importer before its defining module, it took the sibling's copy of the layout. The link plan had since reloaded the defining module's tree, so base adoption filled in that stale copy while the struct was emitted from the reloaded, unadopted layout. The subclass lost its base's fields, writes to its own fields landed on the base's, and the miscompiled unit was cached for every later JIT link. That showed up as a `jac test` segfault that depended on which tests had run before it. The defining module's layout now replaces any copy that reached the consumer first.
