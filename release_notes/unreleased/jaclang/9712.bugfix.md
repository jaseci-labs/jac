- **Fix: byLLM auto-compaction no longer fails a call with the default `keep_recent_iterations`**: compaction triggers on a token ratio but kept its tail by counting assistant rounds, so with the default of 3 the newest rounds were often the whole history, leaving nothing to summarise. The call then raised `CompactionNotEffectiveError`, or replaced a single message for the cost of a summariser call. The default compactor now keeps the newest rounds that fit a quarter of the context window (`keep_recent_iterations` is the upper bound, and the newest round is always kept), truncates an oversized tool result in what it keeps, and skips a compaction that would summarise 5% of the window or less. When compaction cannot bring the history under the threshold it logs a warning and the call carries on; `CompactionNotEffectiveError` is now raised only when the provider rejects the request as too long and compaction cannot reduce it.
