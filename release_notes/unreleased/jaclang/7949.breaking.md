- **Breaking: `jac start --scale` now waits for the rollout it applied, and deployment status stops reporting `RUNNING` mid-rollout**: on a re-deploy the readiness gate was satisfied by the *previous* revision's pods, so the command returned in seconds against the pods it was about to delete. It now returns only once a replica of the new ReplicaSet is available, which means scheduling, image pull, app boot, the readiness probe and `minReadySeconds`: seconds before, minutes now. Anything that runs `jac start --scale` under its own timeout (CI jobs, deploy wrappers) needs that timeout raised; the wait itself is bounded by the new `rollout_timeout` under `[scale.kubernetes]` (default 1200s), and `--wait full` extends it to every replica of every service. Deployment status now answers to the same definition: `ScaleClient.resource_status()` reports `PENDING` while a rollout is in flight and `RUNNING` only once the new revision is fully available, so a poller that read `RUNNING` as "the new code is live" was being answered off old-revision pods and will now see the rollout it is actually waiting on.
