- **Fix: native ELF hash tables match the dynamic linker's**: the ELF linker computed symbol hashes in unbounded Python ints, so for a name whose hash carries past bit 31 (such as `hxxxxskz`) it filed the symbol in a different bucket than the one glibc searches, and a shared library built by jac failed to resolve that export with `undefined symbol`. The hash now uses glibc's 32-bit arithmetic. Dynamically linked executables also get a real SysV hash table instead of a single bucket: the dynamic linker searches the executable first for every symbol relocation of every library it loads, and with one bucket each lookup walked all of the executable's imports. With 400 imports and libstdc++ loaded, a launch takes 703 µs instead of 2,185 µs, and startup no longer grows with the number of imports. Statically linked executables, the default, are unaffected.
