- **Builtins called in a loop no longer grow the native stack**: `float(s)`, `int(s)`, `str.rpartition` and the set relations, unions, differences and copies reserved their end pointer, cursor or counter with an `alloca` where the call was lowered, so every loop iteration took a fresh stack slot that was only given back when the function returned, and a long loop crashed with SIGSEGV (three million `float()` calls overflowed the 8 MB main-thread stack inside `strtod`). These slots now come from the function's entry block, and a parallel `flow for` gives its run-time-sized thread tables back after its join, so a `flow for` nested in a loop runs in constant stack too.
