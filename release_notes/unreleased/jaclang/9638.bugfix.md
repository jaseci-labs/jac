- **Fix: a native module's Python side binds the C declarations it names**: A module declaring C types or functions (`import from lib { obj S {...} def f(...); }`) and placed native kept no Python binding for them, so its own Python-side code and Python importers of a re-exported C struct failed (`cannot import name 'S'`). The C block is now kept on the Python side whenever that side names one of its declarations, and a Python-side C binding loads its library on the first function call rather than at import.
