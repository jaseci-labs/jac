- **Fix: `type(x) is str` always answered false in compiled JavaScript**: the ES backend lowered `type(x)` to JavaScript's `typeof x`, which yields a string tag like `"string"`, while a bare builtin type name in the same expression lowered to the runtime type object `_jac.types.str`. `is` then compared a string against an object, so `type(x) is <builtin>` was always false and `type(x) is not <builtin>` always true. Nothing errored: `jac check` passed and the emitted JavaScript was valid, so the wrong branch was taken silently; `type(42).__name__` did not even parse, emitting `typeof 42.__name__`. Python targets were unaffected. `type()` now returns the value's type object, the same singleton a bare type name lowers to, which also makes `type(x) is type(y)`, `type(a) is MyClass`, `str(type(x))` and `type(x).__name__` behave. Exact-type semantics are preserved, so `type(True) is int` stays false where `isinstance(True, int)` is true.
- **Fix: `isinstance(d, dict)` was false for every dict in compiled JavaScript**: the runtime's type-name resolver did not know that a dict literal lowers to a plain JS object, so it reported the value's type as `Object` and no dict ever matched `dict`. The polymorphic method dispatcher already classified plain objects correctly for its own use; both now share one definition and cannot drift apart.
