- **Fix: a quoted import of a Jac module compiles like the dotted one**: `import from "..ui.plain" { Plain }` (and `"./plain.jac"`, `".plain"`, or a hyphenated module name, which can only be written quoted) produced a client bundle that threw `TypeError: Class constructor Plain cannot be invoked without 'new'`, while `import from ..ui.plain { Plain }` worked. The checker resolved the quoted path to the project directory instead of the module, so `Plain` was untyped (a misleading `W1101`) and its construction lost `new`; and placement never pulled the module into the client, so `Plain` was inlined as a fields-only wire copy whose methods were missing. A quoted path that names a Jac module is now typed, placed and ES-imported exactly like the dotted form. A quoted `./lib.js` import also picks up its sibling `.d.ts` now, so a declared class constructs with `new` and untyped JS warns `W1102` instead of `W1101`.
