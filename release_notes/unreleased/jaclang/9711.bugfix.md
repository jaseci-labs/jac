- **Fix: a field write made inside a pushed context is charged to the right session** (#9381): A write to a persistent field was recorded against whichever execution context was ambient, so a unit of work that pushes its own context (a background job, a scheduled unit, a cross-application call) had its writes booked against the caller's session. The caller then flushed its own untouched copy of the anchor: before row versioning that silently undid the write, and since versioning it fails with a `WriteConflict` on an anchor the caller never touched. Reads flush too, so a single misattributed write went on to fail later read-only work on the session that every request in a server process shares, and escalated those requests to `SERIALIZABLE`. An anchor is now bound to the session that loads it and a write is charged to that session rather than to the ambient context, which also covers a worker thread that never pushed a context of its own. One consequence to be aware of: a read-tier unit that writes is now correctly seen to have written, so it is retried at `SERIALIZABLE` instead of the write slipping past that guard.
