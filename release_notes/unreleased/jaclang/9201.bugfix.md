- Scheduled tasks and dynamic jobs run each tick at most once across replicas, per service. Interval ticks are now multiples of the interval since the Unix epoch, so replicas booted at different times share them, and a replica runs a tick only after claiming it in the database (`kv_claim_tick`), instead of taking a lease on the task name whose 300 second cap let tasks of 375 seconds or more run once per replica. A dynamic job claims the time its run was scheduled for, so a late or catch-up run cannot repeat one another replica made. The claim is taken before the run, so a replica that stops after claiming spends that tick. A respawned worker recomputes its fire times rather than firing an inherited one, a claim that cannot be made skips the tick instead of firing on every worker, static claims are keyed by service (`JAC_SV_NAME`, else the served module), and job rows record the service that created them: a service restores, reads, changes and deletes only its own jobs, while `GET /jobs` still lists every service's. Interval tasks shift once to the epoch grid on upgrade (`interval=3600` runs on the hour). The per-account job cap (`max_jobs_per_user`) counts the jobs in the service the request reaches, so a job in one service no longer uses up the cap in another.
