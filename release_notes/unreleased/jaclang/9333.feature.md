- **Sealed native jabs gain a host-driven entry-library lane**: sealing an interop-capable app (native code that calls into Python) can no longer pretend to be self-contained -- the seal now compiles once and links the payload as an entry library that also exports a host protocol: `jac_entry`, the `__jac_argc`/`__jac_argv` cells `sys.argv` reads, and a `__jac_bind_<symbol>` dispatch slot per callback. Each callback record keeps its qualified native caller symbol separate from the provider Python function name, plus its ctypes signature, source module, and library sha256, in `<lib>.interop.json`; the sealed manifest stores per-target library and sidecar digests plus interop status under `native_payloads`, separate from the package-level `native` record. `jac run <jab>` verifies the record and library digests before loading; the in-process lane temporarily sets Python `sys.argv` to the app arguments before importing callback providers, loads under `RTLD_NOW`, verifies every recorded slot, writes native argv, registers callbacks, then calls `__jac_shared_init` and `jac_entry`. It refuses loudly on a stale or unreadable record instead of running with dangling callback slots. Self-contained apps keep their standalone binary exe-first, with the entry library as an in-process fallback; once the entry has started, failures abort instead of re-running the image's module-level side effects.
