- **Scale: an external database url now reaches pods through a Secret instead of sitting in every pod spec** (#8452): `_deploy_databases` wired `JAC_DB_URL` two different ways depending on mode. Provisioned Postgres put the connection string in a Secret and gave pods a `valueFrom.secretKeyRef`, while external mode appended the user's url as a literal `value`. That url carries username and password by definition, and the env list is copied verbatim into every service pod spec and every Deployment manifest, so the credential was readable by anyone with `get` on pods or deployments, by the ops-console read Role this surface grants, and by the `--show-yaml` dump. External mode now writes the url into a `{app_name}-external-db` Secret through the existing `create_k8s_secret` and emits the same `secretKeyRef` entry the provisioned branch uses, so the mode difference disappears from the manifest and nothing downstream needs to know which branch produced the value. Because `create_k8s_secret` already creates-or-replaces on a 409, changing `url` in `jac.toml` rotates the secret on the next deploy rather than being silently ignored, and because it stamps `managed: jac-scale`, the existing `destroy` label sweep already removes it.
