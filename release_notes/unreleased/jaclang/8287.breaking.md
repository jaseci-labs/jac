- **Breaking: `jac test` runs on a built-in runner; pytest is gone from the binary**: `jac test` no longer shells into pytest. pytest, pytest-xdist, execnet, pluggy and iniconfig are no longer bundled (about 47,700 lines of Python, ~4.8 MB), and the `pytest11` entry point that let plain `pytest` collect `.jac` tests has been removed along with `pytest.ini` and the repo's `conftest.py` files. Three consequences for existing projects: `import pytest` inside a `.jac` test no longer resolves, `jac test` collects only `.jac` files (a project's `test_*.py` files are ignored), and pytest fixtures/markers have no equivalent. Fixtures were never actually reachable from a Jac test -- `JacTestItem` extended `pytest.Item` rather than `pytest.Function`, so autouse fixtures silently never ran -- and the suite only ever used `pytest.skip`, `pytest.raises` and `pytest.fail`. Those three are now ambient builtins usable in any `test` block with no import: `testskip(reason)`, `testfail(reason)`, and ``with testraises(SomeError, `match="pattern") as ei { ... }`` (`skip` and `match` are Jac keywords, hence the spellings). Execution forks workers from an already-warm parent instead of booting a fresh interpreter per worker: on `jac/tests/project` (294 tests) the suite went from 76s wall / 90m13s CPU under 128 xdist workers to 7.5s wall / 4.8s CPU under 8. The default worker count is now derived from available memory and capped rather than taken from the core count, since `-n auto` on a many-core machine was a standing OOM risk; `JAC_TEST_JOBS` still overrides it, and `JAC_TEST_JOBS=0` or `1` runs everything in one process. A worker that dies mid-file is now reported as a crash naming that file, and `-x`/`--maxfail` stop within a file rather than only between files.
- **Fix: seven ambient builtins were invisible to the type checker**: `managed`, `jref`, `JacListView` and the four `schema_*` rule builders were exported by `jaclang.runtimelib.builtin` (so codegen emitted their imports and they worked at runtime) but missing from the checker's ambient stub, so every use reported `W2001: Name may be undefined` and inferred `Unknown` at the call site -- `y = managed(x)` then failed any downstream type check. `managed` was declared in the stub but left out of its `__all__`, which is what makes a name ambient. All seven are now declared, and a parity test pins the runtime and checker registries to each other so adding a builtin to one without the other fails the suite.
