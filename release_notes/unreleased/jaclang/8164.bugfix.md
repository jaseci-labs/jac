- **Native: `is` / `is not` against an option answered a different question** (issue #8150): `_codegen_compare_link` lowered `KW_IS`/`KW_ISN` only when both operands reached it as pointers, plus a tag test when one side was a literal `None`; everything else fell through to `return self._to_bool(left);`. A `T | None` value is a `JacOpt` -- a presence tag beside the payload -- and not a pointer, so `tab is self` compiled to "is `tab` set?" with the right operand discarded, and `KW_ISN` took the same fallback without negating, making `x is not y` and `x is y` produce the same value. Identity over an option is now emitted directly (both absent, or both present with equal payloads, negated for `is not`; an option against a plain reference matches when the option is present and the payloads agree). This is what broke `UniScopeNode.get_enclosing_captures`, whose guard is `(tab is None) or (tab is self) or not isinstance(tab, (...))`: with `tab is self` collapsing to "tab is set" the guard skipped every symbol, so on the sealed artifact every lambda captured nothing.
- **Analysis: an expression's flow narrow is stamped on the node, so backends can consume it** (issue #8150): `get_type_of_expression` stores the *member's* type on `Expr.type` and returns the narrow to its caller, so a consumer reading only the field never saw it. `Name` is the exception -- a symbol's narrow is folded into the stored type -- which is why local narrowing has always worked natively and nothing else has. The evaluator now records the answer on the new transient `Expr.narrowed_type` (cleared with `Expr.type` when the type system is reset), which makes it an ordinary central fact: the native backend reads the field and never calls back into analysis, so backend purity is preserved. With it, `stmts[0].expr` after `isinstance(stmts[0], ExprStmt)` resolves its receiver against the narrowed class instead of failing the whole `AtomTrailer`, and `self` resolves against the class an enclosing `isinstance` narrowed it to rather than always the declaring archetype. The narrow is consumed for *class and element resolution* only: replacing a checked option unwrap with a blind payload read is deliberately not done for a member reference, because the walk that proves the narrow is intra-procedural and cannot see a callee rebinding the attribute. Two related crashes go with it: `_typed_elem_llvm_of` read `expr.type.private.type_args` unconditionally, and a field read off a *joined* narrow (`item.values` over `TupleVal | ListVal`) is a `UnionType`, which carries no `private`; members that agree on the container shape agree on its element type, so the first member carrying type arguments now answers for the union.
- **Native: a union stored in pointer layout can be narrowed to its container member** (issue #8150): `_apply_flow_narrowing` required a `JacOpt` or a boxed `jacval`, and a union whose members are all pointers keeps the first member's pointer layout instead of boxing, so its narrow was dropped -- `Ex | list[Ex]` narrowed to `list[Ex]` stayed an `Ex*` and `list(...)` / `len(...)` had nothing to lower. Such a narrow is now a bitcast, gated on the analysis having actually stamped a narrow for that occurrence and on the narrowed container naming its element type. Both gates are load-bearing: a bare `dict` or `list` annotation lowers to a default flavour that is not the one the value already carries, so re-typing to it would hand a jacval container the helpers of an integer-keyed one.
- **TypeCheck: `isinstance(x, list)` over a `Sequence[T]` member keeps `T`** (issue #8150): `_filter_union_for_isinstance` keeps the union members the isinstance target is a subtype of, so a member the relation runs the other way for drops out and the narrow falls back to the bare target class. `isinstance(lam_body, list)` over `Expr | Sequence[CodeBlockStmt]` therefore narrowed to bare `list`, with no element type -- enough for the checker to accept a copy, not enough for the native backend to know which list flavour the slot holds. A value that is both a `Sequence[T]` and a `list` is a `list[T]`, so the member's type arguments now carry onto the target class when it declares the same number of parameters; the container protocols are exactly this shape (`list` is a `Sequence`, `dict` a `Mapping`). Narrows whose target is already parameterised, declares no parameters, or takes a different number of them are unchanged. This is the shared evaluator, so the sv/bytecode codespace narrows the same shape the same way.
- **unitree: six workarounds retired** (issue #8150): each of the rewrites #8052 needed to seal `unitree.jac` natively is a receipt for one of the defects above, and all but one is now gone. `get_enclosing_captures` gets its `not isinstance(tab, (Ability, ImplDef, LambdaExpr, Test))` back, `insert` its nested access-resolution ternary, `tail_return_expr` its in-place `stmts[0]` narrowing, `_fix_store_ctx` its single joined `TupleVal | ListVal` arm (and the `_fix_store_items` helper is deleted outright), `codespace` its narrowed-`self` fast path, and `LambdaExpr.postinit` its defensive `list` copy -- the one safety property the dialect had traded away, so a lambda no longer aliases the list its caller handed over. `Archetype._get_impl_resolved_body` keeps its flat body and now says why: the ternary lowers, but `Archetype.body` is the `T` of a generic whose layout is type-erased, so the narrow cannot name the element type and the typed local is what pins it. `unitree`'s native seam coverage is unchanged at its waived set -- no workaround retired here costs a seam, and none of the existing waivers is retired either.
