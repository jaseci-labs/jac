- **Native cache identity follows build settings**: The compiled `flow for` thread default participates in the codegen fingerprint, and unit products retain their target and codegen identity.

- **Compiler session ownership and import reuse**: Programs own mutable syntax and type state while sharing immutable catalog bytes. Python star imports use the dependency-scope loader, avoiding repeated full compilation through import cycles; hydrated imports preserve their lazy type providers. Verification sessions release their temporary analysis state. Bootstrap compilation retains its selected schedule through code generation, and native coverage includes cached units.
- **Native socket portability**: Darwin socket calls use the platform's errno accessor, address layouts and IPv6 family. Module attributes remain accessible when an exported class shares the module's name.
- **Client graph filters**: Chained graph-filter expressions reuse the existing predicate lowering, matching traversal filters.

- Native JIR sections retain separate target and codegen variants, and cache writes lock the complete merge transaction. Concurrent native and bytecode builds no longer evict shared runtime products or lose unrelated sections. Replacing bitcode invalidates its previous optional object. Kernel builds and toolchain installs reuse the same bootstrap-safe file-lock primitive.

- **Atomic native output publication**: Linkers replace complete binaries and sidecars on a new file identity, preserving running or open executable images and avoiding stale macOS code-signing state during rebuilds. Module caches and stub catalogs use the same atomic writer. Toolchain downloads stream into a staging file, verify its checksum, then atomically replace the cached archive.

- Direct compiler-source compilation retains its analysis through nested import eviction. Serve manifests use an owned compilation session without loading native libraries on the build host. Native monotonic clocks use the target libc's clock IDs, including Darwin.

- Automatic test concurrency uses the shared working-set budget independently of the post-file recycling threshold, restoring parallel execution on ordinary CI runners. One-worker pools retain recycling and memory reporting; explicit `jobs=0` remains in-process. Source-heavy suites retain explicit concurrency limits.

- Client boundary audits use their owning program's module hub, restoring client builds, serving, and deployments after compiler-session isolation.

- Cache verification compares fresh interfaces and diagnostics without persisting its temporary compilation results. This avoids redundant dependency interface encoding and preserves the cache being verified.

- Native units request a complete source tree and select native library types before analysis. Client field-access audits also run in native build analysis. Shared runtime modules produce native products even when their analysis cache is warm.

- Interface serialization identifies external scopes, symbols, and classes by declaration path, location, and name, keeping cache digests stable when equivalent dependency types are hydrated or analyzed independently.
- Interface keys normalize source paths, and failed type evaluation cannot publish an incomplete interface. Included symbols retain their source declaration and follow its live binding classification, preserving re-export identity across cold and cached analysis.
- The interface writer retains types while memoizing their identities, preventing recycled object IDs from conflating class and unknown types during serialization.
- Type checking distinguishes special-variable expressions from declaration and attribute names, preserving methods named `root` through cold analysis and interface caching.

- Runtime vendoring for source exports compiles the runtime package in the server codespace unless a module is native by policy, instead of running native placement inference over every runtime module the application reaches; `jac build --as source` no longer attempts to lower the runtime.
- Runtime vendoring compiles the whole closure through one compiler program again instead of a fresh program per module, restoring source-export and publish timing.
- The in-process JIT reuses the optimized whole-program image of an unchanged link plan (keyed by the plan digest under the `jir-jit` cache bucket) instead of merging and re-optimizing every unit on every run. A check that only needs a native dependency's interface lowers it without optimizing, emitting or persisting its products. Source products of modules the running compiler package owns come from the compiler's own program, as they did before the unit model, so a source export of the runtime no longer re-analyzes the package.
- A kernel sidecar records the kernel's inputs one by one (compiler digest, codegen identity, target, interpreter and a per-unit digest of source, annexes and wiring), and a checkout accepts the kit's kernel by comparing them, so a rerouted checkout built into the running kit adopts that kernel instead of deriving one on every fresh cache. Between the compiles of one program the hydrated stub catalog and the native unit interfaces already read stay with the program, as its stub trees do; only the products and the evaluator go.
- A module the running compiler package owns is analyzed canonically for every consumer (no application, codespace or entry from the importer, and an empty cache projection), so a check, test or run reuses the package's precompiled interfaces instead of re-analyzing the runtime and CLI closures per program. Native products are stamped per unit with the codegen identity every unit shares plus whether the placement policy names that unit, so a kit's sealed products serve consumers without the build's policy; a native pass only lowers a dependency that placement makes native; and interface and native record lookups fall back to the precompiled tree beside the package, sealed or key-validated.
- Annex discovery caches each directory's listing by its mtime (skipping listings taken within two seconds of a change), so placement inference and module keys stop rescanning the same runtime directories for every import of every program.
- A package module's cache key ignores the active compilation scope, so a native build session, a consumer's analysis and the compiler's own bootstrap read and write one entry for it instead of re-lowering the runtime's native shims once per process.
