- **Feature: Autoscaler runtime status and a shared scale-transition observer**: `Autoscaler.get_runtime_status(autoscaler_name, scale_target_name, namespace)` answers "is this workload inactive, activating, active, deactivating, or degraded?" for both the HPA and KEDA engines in one normalized shape, instead of callers reaching past the abstraction to read raw `ScaledObject`/`HorizontalPodAutoscaler`/`Deployment` objects themselves. For live updates, `AutoscalerObserverRegistry.get_or_create(namespace, cluster_key)` hands back one shared watcher per `(cluster, namespace)` that any number of callers can subscribe to -- no code path opens its own Kubernetes watch per target. Subscribers get deduplicated `AutoscalerTransition` events (previous state, new state, when it was observed) through a bounded, backpressure-aware queue per subscription, and the watcher recovers from any connection interruption by relisting rather than losing or duplicating transitions. A workload idled to zero replicas via KEDA scale-to-zero is reported as the intentional `inactive` state, not an error.
