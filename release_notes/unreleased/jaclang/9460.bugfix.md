- **Fix: a partially initialised project config no longer crashes the wiring pass**: `_closed_patterns_for` already treats a config it cannot read as "no closed patterns", but the import that reaches the config sat above the `try`, so an `ImportError` raised by that import escaped the handler written for exactly that case. The wiring pass runs during module compilation, and when the module being compiled is on `jaclang.project.config`'s own import chain that module is still initialising, so the import fails and the compile dies instead of falling back. The import moves inside the `try`.
