- **Breaking: a walker on the wire is its reports**: a walker spawn now answers with an empty `result` beside its `reports`, and a walker nested anywhere in a response serialises to `{}`. The old echo repeated the report list inside `result` (half of every list response was that copy) and carried the walker's `has` fields plus `_jac_type` / `_jac_id` / `_jac_archetype`, none of which generated clients read. Raw REST consumers that read fields out of `data.result` on a walker spawn must switch to `report`. Consumer-side instances of sv-to-sv walker spawns are now built from the caller's own arguments plus the provider's reports.
- **Breaking: `report` outside a walker is a compile-time error (E1135)**: a function answers with `return`; the only reports beside a function's result are those produced by walkers it spawned.
