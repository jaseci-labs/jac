- **Breaking: a walker on the wire is its reports**: a walker spawn now answers with an empty `result` beside its `reports`, and a walker nested anywhere in a response serialises to `{}`. The old echo repeated the report list inside `result` (half of every list response was that copy) and carried the walker's `has` fields plus `_jac_type` / `_jac_id` / `_jac_archetype`, none of which generated clients read. Raw REST consumers that read fields out of `data.result` on a walker spawn must switch to `report`. The embedded gateway's walker proxy now forwards that same `{result, reports}` payload instead of wrapping the walker under `result`.
- **Breaking: `report` outside a walker, node, or edge is a compile-time error (E1135)**: `report` is valid anywhere inside a walker, node, or edge archetype, including their methods, nested defs, nested objs and `impl` bodies, since those are the archetypes a walk runs through. A plain function, an `obj` method, or module-level code cannot report; a function answers with `return`, and a streaming function returns its generator (`return stream();` where `report stream();` was accepted before). A `def:pub` whose declared return type is a walker now gets W6010, since its typed consumers receive an empty object.
- **sv-to-sv walker spawns hydrate from the caller's side**: the consumer-side instance is built from the arguments the caller passed (deep-copied), the provider's literal `has` defaults for anything left out, and the provider's `reports`. Field state the provider's walk mutated no longer crosses the wire. `sv_client.hydrate_walker_envelope` and `sv_client.function_result` are the one pair of envelope decoders both the core runtime and jac-scale use (a non-ok envelope raises `BridgeError` on either path), and a custom transport should finish with them.
