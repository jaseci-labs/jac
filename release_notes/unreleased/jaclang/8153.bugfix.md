- **Native: a call result iterated straight from a `for` header is owned by the frame, so leaving the loop early gives it back** (issue #8147): a call is +1 by the calling convention, so `for part in t.mangle().split("|")` hands the loop a reference the frame owns -- but `_codegen_for_indexed` kept it in an SSA register and released it in exactly one place, the block it positions the builder at after the loop. Every exit that does not pass through that block therefore abandoned the whole collection: an early `return`, an exception unwinding past the loop, and the outer loop of a nested pair whose inner loop returns. `break` was fine, because `break` branches to precisely that block, which is why the shape read as healthy and why the answer was never wrong -- the leak is invisible to the value. Binding the same expression to a local first was already correct, and that is the entire difference: a named local has a frame slot, and `_emit_scope_cleanup` releases what the frame owns by walking `local_vars` on every exit. The header temporary now gets the same slot, under a synthetic name no source identifier can spell, and the loop's exit reads it back, releases, and nulls it so the two release sites cannot both fire. Entry allocas already zero-initialise (#8052), so a loop that never runs cleans up as a null release, and the slot is deliberately kept out of `param_vars` (#8088), which marks the slots a frame does *not* own. `_try_iter_protocol_for` had the same single-release-after-the-loop shape for the iterator it owns, plus one gap of its own: a list iterator stores its collection with `ptrtoint` and takes no reference, so an adapter built over a header call (`for (i, x) in enumerate(mk(n))`) leaked the source list on every path, not only the early ones -- the loop now holds that source in the same kind of slot for its duration. Measured on a fixture whose `drop` hook counts destructions: an early `return` out of `for nd in mk_nodes(3)` went from 0 destructions to 3, a `raise` past the loop from 0 to 3, nested header loops from 3 to 9, and an `enumerate` adapter from 1 to 3, with every plain value still equal to the sv/bytecode result of the same fixture.
- **Front end: `Ability.event_trigger_type_names` is one statement again**: #8063 had to split `for part in t.mangle().split("|")` into a local plus a loop to dodge the leak above. The method's seal waiver is unchanged and unchanged in reason (`TypeBase.mangle` is Python-only), so this is readability, not coverage movement.
