- **Fix: a KEDA workload idled to zero is no longer reported as degraded**: `get_runtime_status` read the generated HPA's `ScalingActive: False` as a scaler failure, but KEDA's HPA reports that whenever its target sits at zero replicas because there are no pods to compute a metric from. For a workload whose replica floor is zero that is the resting state, so every idle scale-to-zero target read `degraded`, which is the defect one verdict removed from the Deployment reintroduced one layer up from the HPA. The condition is now read in context: at a floor of zero it is expected, and above the floor it is still the genuine failure to scale it has always been. The reported reason also named the wrong condition, because `Ready` was preferred whenever it carried a message, so an HPA-side failure surfaced with KEDA's success reason `ScaledObjectReady`; it now names whichever condition actually reports `False`, which fixes the message a caller sees for a real scaler failure too. Found by the real-cluster observer e2e, which recorded two spurious `inactive -> degraded` transitions during an otherwise healthy cycle and passed anyway; that e2e now asserts a healthy cycle emits no `degraded` at all, and the HPA unit test covers `ScalingActive: False` at zero replicas rather than only a genuine metric failure. Fixes #9501.
