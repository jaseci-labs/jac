- **Plain-int arithmetic that would wrap 64 bits now raises `OverflowError` instead of silently wrapping**: on the native tier, integer pow, unary negation, abs, left/right shifts and augmented assignment on plain ints lowered to raw wrapping i64 operations unless a sized type was involved, so `10**30` printed `5076944270305263616` (the low 64 bits) where CPython prints the exact integer, a wrong answer with exit 0. Where a 64-bit result would diverge from Python and the divergence is cheaply detectable, the op now lowers to `llvm.*.with.overflow` and raises `OverflowError` at the exact operation that overflows; in-range operations take one extra branch and stay exact. Integer pow checks each partial product, which never rejects a representable power because partial results grow monotonically. Augmented assignment lowers through the same checked helpers for locals, module globals and fields, including `//=`, `**=`, `<<=` and `>>=` on globals, which previously stored the right-hand side unchanged, and global `%=` now uses Python floor-mod semantics with a zero check instead of raw `srem`. Sized types (`i8` through `u64`) keep their existing checked-arithmetic contract and raise `OverflowError` when an operation exceeds the type range. Also, an uncaught exception in a native program printed its message to stdout and called `abort()`; it now prints to stderr and exits with status 1, matching what the tier census reads back.
