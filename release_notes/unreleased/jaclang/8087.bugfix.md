- **Fix: a failed client-bundle build is retried instead of disabling every page until restart**: the serving core builds the client bundle at boot for any app with client exports, and when that build fails it warns and keeps serving. `ModuleIntrospector.ensure_bundle` had already cached the reason and re-raised it on every later call, with nothing ever clearing it, so the process could not serve a client page again: requests came back 503 in under 150ms because no rebuild was attempted, and only a restart recovered. A failure is now scoped to the attempt that produced it, so callers queued behind a failing build share its outcome while a caller arriving afterwards builds again and the process self-heals once the cause is gone. The build is also serialized behind a lock, since nothing guarded entry to the memo and callers arriving before the first build finished each ran their own build into the same client tree. A failure whose underlying error stringifies to nothing now reports the exception type, so a bundle 500 can no longer reach the browser as a bare `{"error": ""}`.
