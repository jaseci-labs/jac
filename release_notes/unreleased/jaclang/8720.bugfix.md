- **Loop `else` clauses finally run** (#8629): `for i in xs { ... } else { ... }` and the same form on `while` loops parsed cleanly but the else body never executed when the loop exhausted normally; every codegen backend dropped it. The native backend now routes each loop's exhaustion edge into a dedicated else block (a `break` still bypasses it, matching Python semantics) across all loop forms: `while`, C-style iter-for, indexed range/list/dict/set/str loops, iterator-protocol loops and chunked loops. The JavaScript backend recovers the same semantics with a labeled block: exhaustion falls through into the else statements while breaks inside the loop are rewritten to labeled breaks. Labels appear only when a break could actually bypass an else.
