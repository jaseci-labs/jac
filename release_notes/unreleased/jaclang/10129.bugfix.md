- **Fix: `jac scale destroy` deletes the namespace on the configured cluster**: with a `kube_context` or `kubeconfig` configured, destroy tore down resources on that cluster and then deleted the namespace through the default kubeconfig, so a same-named namespace on whichever cluster kubectl currently pointed at was deleted instead and the configured one was left standing. The reload also repointed the process-wide Kubernetes client at that ambient cluster. The namespace delete now goes through the client destroy loaded for the configured context and loads no cluster config of its own.
