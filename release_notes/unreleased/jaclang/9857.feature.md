- **Native placement is decided from recorded legality facts, not by trying and falling back**: a module that prefers native (the default under `[placement] default = "native"`) used to be compiled natively and, on any error or any exception, compiled a second time for the server. A new analysis pass, `NativeLegalityPass`, now applies the static native-capability rules and follows them through the module's own calls: a function that calls a function which cannot lower is placed on its Python implementation up front, and a module whose top-level code reaches one is placed on the server during analysis, so the native backend never runs for it. A refusal that only the backend can see is recorded as a fact on the same table and re-places the module once. `jac check --native-coverage` reports how many seams the static rules decided and how many were found while lowering. **Behaviour change:** an exception raised inside the native backend, or native IR that fails verification, used to be absorbed as a silent fallback to the server codespace; it is now a compile error (`E5092` / `E5020`) that says it is a compiler bug. Pin the module to `server` under `[placement.pins]` in `jac.toml` to keep working until the bug is fixed.
