- **The pass base chain stops being generic**: `BaseTransform[T_in, T_out]` and `Transform[T: UniNode, R: UniNode]` used their parameters on exactly one line each and nowhere else in the tree. Thirty-eight of the thirty-nine pass subclasses instantiated them at `Module -> Module`, the thirty-ninth at a type that is a `UniNode` anyway, ten already redeclared `ir_in` concretely, and `run_pass` takes `(type, any)` and returns `any` -- so the parameters bought neither checker precision nor driver precision. They cost the native lane a real thing: a slot typed by a class type parameter lowers to a bare erased pointer, which is why `BaseTransform.postinit`'s field load demoted and `Transform.__post_init__` -- the constructor of every compiler pass -- could not lower. `ir_in` and `ir_out` are `UniNode` on the base, and `ModuleCodegenPass` -- the seat every `UniPass` descends from -- redeclares `ir_in` as `Module` again; with that one redeclaration the checker's diagnostics over fourteen pass sources are byte-identical to before, and the pass constructor lowers.
