- **Scale: a request whose asserted identity cannot be resolved is now refused instead of continuing on the system root** (#8348): `request_context_middleware` caught the `ValueError` out of `aset_user_root`, warned, and let the request proceed on the execution context's existing root, which is the system root. That root is treated as `AccessLevel.WRITE` for any anchor and causes the post-materialization ACL filter to be skipped, so a request whose caller could not be identified continued as the most privileged principal in the system. It did not become a cross-tenant read only because a second, unguarded bind further in raised and turned it into a 500, which means the boundary was held by redundancy rather than by decision, and any request path not routed through that second bind inherited the swallow with nothing behind it. The swallow was wider than it read, too: `MissingAnchorError` extends `ValueError`, so a well-formed UUID resolving to no anchor arrived through the same arm as a malformed one. Such a request now gets a deliberate 401 with code `IDENTITY_UNRESOLVABLE`, carrying the underlying diagnostic (for example that the data store was reset or migrated out from under the users db) as the detail rather than burying it in a traceback. A database outage still propagates as itself rather than being relabelled an auth failure.
