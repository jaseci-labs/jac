- **Scale: the Kubernetes service registry reads `JAC_SV_<PEER>_URL`**: jac-scale injects a `JAC_SV_<PEER>_URL` env var into every pod for each of its peers, but in Kubernetes mode the registry derived every peer URL from the route name and never read them, so the injected values were dead and a pod's routing could not be redirected without editing jac-scale-owned Services. The registry now takes the env value when it is set and non-empty, and falls back to the derived URL otherwise. Existing deploys are unaffected, since the injected value is the derived value. The key format is defined once in `sv_client.peer_url_env_key` and shared by the writers and the reader, so the two cannot drift: the env key keeps the raw route name (`orders_app` gives `JAC_SV_ORDERS_APP_URL`) while Kubernetes object names are RFC1123-safe (`orders-app-service`).
