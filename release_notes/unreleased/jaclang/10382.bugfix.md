- **kube-state-metrics no longer reads every Secret and ConfigMap in the cluster**: enabling `[scale.monitoring]` gave the per-app kube-state-metrics ServiceAccount a ClusterRole with `list`/`watch` on `secrets` and `configmaps` in every namespace, with its token mounted in the pod, and a LIST returns the objects' data, so that token could read every tenant's credentials. Both types are dropped from the role, and kube-state-metrics now gets a `--resources` list built from the same grant, so it also stops retrying the Ingress, Lease, NetworkPolicy, CSR and webhook types it was never allowed to list. No shipped dashboard used `kube_secret_*` or `kube_configmap_*`. The ClusterRole is still created only when missing, so an existing cluster keeps the old grant until it is applied on redeploy.
