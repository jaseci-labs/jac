- **Fix: Kubernetes fat bundles now vendor compiled dependencies**: `jac start --scale` vendored the app's Python wheels with `pip download --platform manylinux_2_36_<arch>`, a tag pip matches literally, so any dependency shipping compiled wheels (`cryptography`, `grpcio`, `bcrypt`, `watchdog`, `pydantic-core`) failed to resolve and every such deploy silently fell back to a thin bundle whose pods installed from PyPI at boot. The deploy now asks pip for every tag the pod accepts (`manylinux2014_<arch>` and the `manylinux_2_17` through `manylinux_2_36` ladder, with the pod's CPython version) so wheels resolve as they would on the pod itself. A dependency that publishes no wheel at all (`http-ece` behind `pywebpush`) is built from source on the deploy host and shipped when the result fits the pod, which a pure-Python wheel always does; this also restores the source build for `jac build --fat`. When a package still has no usable wheel, the thin-bundle warning and the `[scale] fat_bundle = true` failure name it.
- **Fix: source distributions now build through the sealed `jac` runtime**: pip run as `jac -m pip` could not build any sdist (`BackendUnavailable: Cannot import 'setuptools.build_meta'`) because the launcher ignores `PYTHONPATH`, which is how pip hands its isolated build environment to the build hook. Fat-bundle vendoring, `jac build --fat`, `jac install --global` and on-demand capability installs now drive pip with the runtime's bundled CPython, the same interpreter `jac install` already uses for project venvs, so packages that publish only a source distribution install and vendor from a sealed runtime.

Preserve pip resolver diagnostics and dependency constraints during source fallback, reject host builds from newer or unknown libc environments, bound fallback retries, and keep vendoring compatible with older seal scripts. Bundled pip ignores inherited Python paths and user site packages while retaining isolated source builds.
