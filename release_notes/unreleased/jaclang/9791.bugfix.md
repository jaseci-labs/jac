- **Fix: the server refuses to start when its system user cannot be provisioned**: Scheduled jobs and webhooks run as the internal `__system__` user. If creating it failed quietly (an identity that was taken but unreadable, or a role that could not be stored), the server still booted and the scheduler fell back to the literal id `__system__`, which resolves to the super root without any such user existing. Boot now reads the system user back and fails with an error naming it unless it exists with the `system` role, and the scheduler no longer substitutes the literal when the lookup comes back empty.
