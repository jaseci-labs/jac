- **Native: a `dict` keyed by `type` has a layout, so `UniNode`'s sub-node index lowers** (issue #8068): a `type` had no native representation at all -- `_lower_class_type` fell through to `None` for it -- so a dict keyed by one had no key storage either: the layout pass reported the field as not layout-compatible (`W5032`) and the codegen pass refused the type outright (`E5092`), demoting every method that read or built the table. `UniNode.__sub_node_tab` is exactly that dict, the per-node index behind `UniPass.get_all_sub_nodes`, so this one gap shipped `UniNode._construct_sub_node_tab` and `FuncSignature.is_in_py_class` as `abort()` stubs inside the sealed parser artifact and forced two more `UniScopeNode` methods to be hand-rewritten around it. The backend already carried one program-wide name for a class: the NUL-terminated class-name constant in vtable slot 0, which `__name__` reads off a vtabled receiver, which `get_struct_view` re-keys marshalled views with, and which the layout registry keys its hierarchy on. `type` (and every `type[T]`) now lowers to that pointer, which makes a `type` key an `i8*` key -- the hash core already hashes and compares those by content, so the identity survives a module boundary where a per-module pointer would not, and stays exact per class rather than per subtree. Three value forms feed it, through one emitter: `type(x)` resolves the receiver's vtable slot 0 when its class has a vtable, so a base-typed slot keys its *runtime* class, and falls back to the static constant when it has none; a bare class name in value position emits that same constant (an enum class still means its members, so iterating one is untouched); and `type(x).__name__` / `x.__class__.__name__` now route through the shared emitter rather than a copy of it. `type` is layout-compatible as a scalar without joining `LAYOUT_COMPATIBLE_PRIMITIVES`, which keeps that list meaning "scalar", and the acyclicity walk skips a class reference: it is a name, never an edge that can close a cycle.
- **Native: a class carried in a value is a usable `type`, not just a spelling**: with a representation to carry, three things that only ever saw class *literals* now accept a class *value*. `type[T]` unifies against a class reference during monomorphization, so a generic `def f[T](typ: type[T])` solves `T` from its argument instead of failing with "could not solve this call's type arguments" and demoting. `isinstance(x, typ)` against such a value lowers to `__jac_isa`, a program-wide subtype table built from the layout registry's MRO for every class, so it answers by the hierarchy (an `AlphaLeaf` is an `Alpha`) rather than by class identity -- the literal-target path, which resolves to a vtable compare, is unchanged and still preferred. Both are what `UniPass.get_all_sub_nodes`' `typ in nd._sub_node_tab` / `isinstance(i, typ)` pair needs to lower at all.
- **Native: an optional container answers membership and subscript through its payload**: `k in d` and `d[k]` where `d` is `dict[K, V] | None` refused to lower -- the container spec was resolved from the union's mangled name, which starts with neither `dict[` nor the payload's, so the dict path was never entered and the expression reported `E5092`. A sole-non-`None` union now resolves to its member for spec purposes and the read unwraps the `JacOpt` payload, the same unwrap `len` already did on one. This was not a `type` problem: `dict[str, V] | None` failed identically. It is the second half of `_construct_sub_node_tab`, whose table is declared `(dict[(type, list[UniNode])] | None)` and narrowed nowhere.
- **Front end: `UniNode` owns its own sub-node lookups**: `UniNode.get_all_sub_nodes` and `find_parent_of_type` held the loop bodies that `UniPass`' same-named statics used to hold, and the statics now delegate to them. Behaviour is identical (`find_parent_of_type` still starts at the parent and still stops at a node with none), but the tree no longer reaches out of its own native closure to walk itself: the two methods called `UniPass` through a function-local import, and `jac0core/passes/uni_pass.jac` can never share a native unit with `unitree`. Both retired workarounds are downstream of this -- `UniScopeNode.lookup` goes back to `find_parent_of_type(ImplDef)` instead of an open-coded parent walk, and `get_enclosing_captures` back to `get_all_sub_nodes(Name)` with its stand-in `_capture_names` collector deleted. With the two `abort()` waivers also gone from `_UNITREE_SEAM_WAIVERS` and the seal coverage, `unitree`'s closure is down to 26 waived seams, none of them `type`-shaped.
