- **Breaking: the deploying process's `JAC_DB_URL` no longer decides the deployed app's database**: `KubernetesPostgresProvider` picked provision-vs-external from `get_database_config()`, which resolves `JAC_DB_URL` ahead of `[scale.database].url`. Any process with `JAC_DB_URL` set therefore handed its own database address to every app it deployed and provisioned nothing, and `[scale.kubernetes].postgres_enabled` could not ask for provisioning back because a boolean cannot express a tri-state (#8137). `JAC_DB_URL` now means only "the database this process connects to" and the deploy path cannot read it: `config_loader` gained `get_deploy_database_config()`, a jac.toml-only view, and no deploy module may call the env-reading `get_database_config()`. Deployment intent moved onto `KubernetesConfig` as `[scale.kubernetes]` `database_mode` (`"auto"` / `"provision"` / `"external"` / `"none"`), `database_url`, and `database_namespace`, scoped to one deploy instead of read from process-global state. Precedence, highest first: explicit `database_mode` / `database_url`, then `[scale.database].url` from the app's own jac.toml, then provision a per-app Postgres. **If you relied on ambient `JAC_DB_URL` during a deploy, that app now gets its own provisioned Postgres.** To keep pointing it at the old database, say so explicitly: add `database_mode = "external"` and `database_url = "postgresql://..."` under `[scale.kubernetes]` in the app's jac.toml (or set them on the `KubernetesConfig` you pass to `KubernetesTarget`). `postgres_enabled` is deprecated but still accepted: `false` maps to `database_mode = "none"`, and `true` is ignored.
