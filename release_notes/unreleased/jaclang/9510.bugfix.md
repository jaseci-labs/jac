- **Fix: `ScaleClient`'s autoscaler methods reach KEDA instead of always resolving to HPA**: `autoscaler_status` and `watch_autoscaler_transitions` took the scaling engine from configuration, which on the bare spec these calls build is always the `"hpa"` default. So watching raised `NotImplementedError` for every app, and status on a KEDA target looked for a plain HPA and fell back to a replica count with no trigger or scaler information, which is the answer the method exists to improve on. The engine is now read off the target's own resources, so a ScaledObject under either of KEDA's names selects KEDA and its confirmed absence selects HPA. A probe that could not be read, for example when RBAC denies `keda.sh`, is reported as KEDA with a warning rather than being treated as proof of a plain HPA target. These calls also load the cluster configuration first, so `ScaleClient(kube_context=...)` is no longer ignored.
