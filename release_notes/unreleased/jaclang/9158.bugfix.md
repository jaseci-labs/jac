- **Fix: native `sorted()`/`.sort()` key comparisons now use the canonical comparison path**: The native list-sort comparator used a private `icmp`/`strcmp` chain that mishandled most key types: `str` keys crashed LLVM verification (`E5020`), `bool` keys sorted in reverse (`True` before `False`), and tuple/list keys compared raw memory instead of their contents. `emit_sort` now delegates to the shared comparison emitter (`NaIRGenPass._emit_comparison`), so `str` keys compare length-aware and NUL-safe, `bool` keys order `False < True`, tuple and list keys compare element-wise, and bytes/set keys order correctly. Orderability is now decided from the key's semantic return type, so sorting with an object-returning key (e.g. a `Node`) reports `E5092` at compile time instead of sorting object pointers as strings, and unsigned integer keys (`u8`-`u64`) order correctly for named key functions, not just lambdas. `bool`-vs-`bool` ordering operators (`<`, `>`, `<=`, `>=`) get the same `False < True` correction.
