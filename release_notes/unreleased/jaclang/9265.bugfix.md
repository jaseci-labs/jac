- The native Python compiler (`JACPYTHON=1` builds) no longer leaks and compiles far faster. Every `compile()` / `ast.parse()` call used to retain 0.3 MB to 1.9 MB, because locals holding a value of type `any`, string descriptors, tuple targets, comparison operands, `bytes`/`str` receivers, optional payloads and container temporaries were never released; they are now released at scope exit, loop-iteration end and last use. The replacement object is also emitted through the LLVM module pipeline it previously skipped, nested scopes are found by key instead of a quadratic sibling scan, and compiled results are handed to CPython as objects rather than marshalled and read back. Measured against stock CPython 3.14.6: compiling a 175 KB module 0.224s to 0.074s, 10k functions 8.72s to 0.741s, 10k locals 1.12s to 0.109s, and resident memory after ten large compiles 134 MB to 61 MB, with no growth across repeated compiles. Code objects, ASTs and syntax-error reporting are unchanged.
- `raise <variable>` in native code keeps the exception's own type. It was lowered as a plain `Exception` carrying the object's address as its message, so an exception object held in a variable never matched its own `except` clause, and the message read back as undecodable bytes.
- A parameter rebound by a `for` target, tuple unpacking, a walrus or an augmented assignment is no longer released while the caller still owns it. Only plain assignment counted as rebinding a parameter, so the other binding forms released a borrowed argument.
