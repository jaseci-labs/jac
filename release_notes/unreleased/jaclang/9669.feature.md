- **Feature: Every static `@schedule` run is visible**: each run now logs one line naming the task, the tick it ran for, the worker (`host:pid`) and its duration, at `INFO` when it succeeds and `ERROR` with its error when it fails, and a tick a worker does not run is logged at `DEBUG` with the reason. With monitoring on, `/metrics` adds `<namespace>_scheduled_runs_total`, `<namespace>_scheduled_run_duration_seconds` and `<namespace>_scheduled_ticks_skipped_total` per task. Before, a healthy run left no trace and a failed one read like any failed HTTP call. A tick a shutdown refuses is reported too, with reason `stopping`, so every claimed tick ends in one named outcome. `ScheduledTask.last_run` is gone with this: nothing read it, and a run now reports itself.
