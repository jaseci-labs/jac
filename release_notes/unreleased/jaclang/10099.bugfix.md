- **Fix: assigning several client state fields at once**: in a client component, a tuple, list, star or chained assignment to `has` fields, such as `(a, b) = (b + 1, a + 1)` or `a = b = 0`, threw `ReferenceError` when it ran because the fields were written as undeclared variables. Each field is now updated through its state setter, and every value is read before any field changes, so a swap works as in Python. The same holds for every other way a field is rebound: a `for` loop target (`for a in items`), a walrus (`(a := 5)`), and every augmented operator; `a //= 2` used to compile to `a + 2` and `a %= 3` used JavaScript's remainder. Writing a field in any of these ways directly in a component body is now reported as E0082. A star before the last name, as in `(a, *mid, b) = items`, also compiled to invalid JavaScript, for plain variables too; it now unpacks as in Python.
