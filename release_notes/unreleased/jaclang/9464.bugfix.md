- **Fix: Loop-carried list headers stay in registers on the native backend**: `__list_append_<elem>` now merges the `data` pointer through a phi and stores `cap`/`data` after the grow calls, and container header accesses (`len`/`cap`/`data`) are tagged `!alias.scope` against `!noalias` element-buffer accesses with a cold branch weight on the grow edge. LLVM can promote the header fields into SSA values across append loops instead of round-tripping them through memory each iteration. Applies to dense lists, AoS (struct-element) lists, bytearray, and the inline header accesses emitted for `pop`/`insert`/`extend`/`remove`/`index`/`count`/`clear`/`sort`/`reverse`/`copy` and dict operations.
