- **Fix: multi-statement lambda hoist placement on the Python target (root rewrite)**: Multi-statement lambdas now lower correctly in *every* expression position on the Python target. The previous shared-list-and-drain-points design hoisted the first lambda whoever drained next grabbed, so it broke on compound-statement headers (`if`/`while` conditions), on a class that combined a multi-stmt-lambda decorator with a multi-stmt-lambda `has` default, on method bodies (Python private-name mangling of `__jac_lambda_`), and it shipped a shared-mutable-default footgun for compound `has` defaults. PyAST codegen now owns each lambda by its nearest enclosing function-or-module scope via a hoist-frame stack, routes decorator/default lambdas to the enclosing scope and body lambdas to the body, never places a helper inside a class body, and renames helpers to single-underscore `_jac_lambda_N` (immune to mangling). `has` defaults use a plain per-instance `field(factory=...)`. Adds regression fixtures for all five previously-broken positions.
