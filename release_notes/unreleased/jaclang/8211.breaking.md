- **Breaking: `pub` is no longer placement evidence in a project kind that has no server**: `pub` means *export* client-side and *endpoint* server-side, so it has no settled meaning until placement does. It is now read as endpoint evidence only when `[project] kind` names a kind that has a server. Kinds with a server (`web-app`, `service`, `service-mesh`, `desktop`, `mobile`, and the default when no kind is declared) are unchanged to the letter: an evidence-free `def:pub` there is still a server endpoint. In a kind whose `KindSpec.codespace` is `client` (`js-package`) `pub` is not evidence at all -- everything lands client and `pub` means export.
- **Breaking: server evidence in a serverless project kind is now `E5087`, not a silent server placement**: A `js-package` ships as an npm tarball with nothing serving `/function/<name>`, so an element placed server-side there could only fail at runtime inside a `fetch` with no route to reach. Root access, an FFI extern, an inline `::py::` block, or a Python import whose bindings are used at value level now fail the build and name the kind. Annotation-only and `import type` uses stay silent. If the code genuinely needs a server, declare a `[project] kind` that has one.
