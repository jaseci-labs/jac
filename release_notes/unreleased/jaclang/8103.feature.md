- **`jac db list`, `jac db drop` and `jac db prune`**: every database the runtime creates now records what it belongs to (owning absolute path, kind, host, pid, creation and last-use time) in a registry table in the cluster's maintenance database, written by the same code that creates the database. The sha1 in a database name is not reversible, so that record is what makes a cluster inspectable at all. `jac db list` prints every jac database with its size, kind, state and owner, and does not create the project's own database to do it. `jac db prune` reports what it would drop and drops nothing until you pass `-y`, and it never touches a database whose owning path still exists: candidates are scratch stores left by processes that are gone, and project databases whose recorded path was deleted. Databases created before owner tracking are reported and left alone; `jac db prune --empty` additionally offers up the ones that hold nothing but the system root, which is how an already-bloated cluster gets reclaimed. `jac db drop <name>` handles the rest, one database at a time, also only with `-y`.
- **Opt-in retention sweep for the shared cluster**: `[database] retention_days = <n>` in `jac.toml` (or `JAC_DB_RETENTION_DAYS`) makes a cluster start drop databases that have not been opened for that many days. It is off unless set, since the persistence design is otherwise never-delete, and it never sweeps the database being opened. Start conservative: 30 days or more, and run `jac db list` first to see what would go.
