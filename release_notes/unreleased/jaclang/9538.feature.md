- **Feature: `graph import` and per-directory arch.jac**: An `arch.jac` now closes the directory it sits in and everything below it, down to the next `arch.jac` or `jac.toml`: having the file is the whole switch, and every module under it takes its imports of the modules below it from wires. Names in the file are relative to its directory, and generated imports use the real import name derived from where the file sits (through namespace directories), so a boundary copied elsewhere still weaves correctly. A wire's consumer may name a class, function or method (`pkg.mod.Class.method`), and the generated import lands at the top of that body, so lazy imports are declared and stay lazy. Rules are optional restrictions: a provider no rule names flows anywhere under the arch.jac. Wiring that names no existing module is inert and reported as `W2084` instead of failing the build, so a distribution that leaves modules out still compiles. `jac arch init [dir]` seals a directory, `jac arch sync` adds missing wires in every arch.jac, and `--strip` leaves stdlib, native-stdlib, self and bare-sibling server imports written. The jaclang package itself is sealed with `jac/jaclang/arch.jac` (plus one for `dist/fused`), and the `jac arch` command module moved to `cli/commands/architecture.jac` because `arch.jac` is a reserved file name.
