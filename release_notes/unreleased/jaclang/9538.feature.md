- **Feature: per-directory arch.jac, scoped wires and in-file seal policy**: An `arch.jac` now governs its own directory and everything below it, down to the next `arch.jac`, so a package keeps its wiring inside the package and a copied-out subtree carries its own. Names in the file are relative to its directory, and generated imports use the module's real import name, derived from the `__init__` modules above it. A file seals what it names, and a `closed;` (or `closed: core.* | web.*;`) declaration seals the rest of its subtree; an empty `arch.jac` is an open boundary whose modules keep their written imports. A wire's consumer may name a class, function or method (`pkg.mod.Class.method`), and the generated import lands at the top of that body, so lazy imports are declared and stay lazy; `E2094` now asks for the scoped wire. `jac arch init --strip` now leaves stdlib, native-stdlib and self imports written, keeps jac0 seed modules and function-level imports with a written twin untouched, writes rules that admit outside importers with `any`, and writes arch.jac atomically; `jac arch init|sync|graph` take a directory. The jaclang package itself is now sealed with `jac/jaclang/arch.jac`, and the `jac arch` command module moved to `cli/commands/architecture.jac` because `arch.jac` is a reserved file name.
