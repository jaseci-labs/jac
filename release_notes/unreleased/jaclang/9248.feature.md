- **Mobile apps provision themselves on first run; `jac setup` becomes the optional pre-provision**: `jac run --dev <app>` on a `mobile` app used to refuse with "React Native scaffold not found. Run `jac setup <app>`", and an existing scaffold with stale `node_modules` failed later inside Metro because dev never synced native deps. Every client target now has an idempotent `ensure_ready(project_dir, platform)` hook that `jac run`, `jac run --dev`, `jac build` and the target methods themselves call before dispatching. For a mobile app it writes the Expo scaffold and installs its packages on the first native run, narrated as a one-time setup ("First run: performing one-time mobile setup..."), and on later runs only re-syncs packages when the manifest or lockfile changed (the online path of the Expo dependency sync is now stamp-gated like the offline one, so a warm run no longer shells out to `bun install`). `--platform web` never touches the scaffold. Web, static and desktop targets provision inline already, so their hook is a no-op; the base implementation consults the previously unused `requires_setup` flag. The "explicit, never silent partial work" contract stands: every step is narrated, consent-gated toolchain steps (Android SDK licenses, Linux `sudo` package installs) keep their TTY prompt and non-TTY stop-with-command behavior, and under `JAC_OFFLINE=1` a missing scaffold or stale deps still fail with the `jac setup <app>` hint. `jac setup` keeps all its flags and stays the explicit way to provision ahead of time for CI images and offline preparation.
