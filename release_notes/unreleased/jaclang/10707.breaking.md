- **Breaking: a password change or reset now ends the account's other sessions, and clients must switch to the replacement token**: every token carries its account's session epoch, and a token is accepted only while that epoch is current. A password change, a password reset, the new `POST /user/logout-all` and disabling the account advance it, so every token issued before is refused from the next check on, on every worker, and can no longer renew itself through `/user/refresh-token`. **Migration:** `PUT /user/password` now ends the calling session too and answers a replacement `token`; a client must store it and use it from then on, or the user is signed out. Open WebSockets recheck the session at each heartbeat and before the messages they run, reusing a successful check for up to 5 seconds. Tokens issued before this release carry no epoch and keep working until the account's first change; second-factor login challenges started before it must be started again. A fleet service that provisions a gateway's users no longer renews their tokens: refresh at the gateway.
- **Fix: the gateway preserves credential precedence and enforces WebSocket revocation**: refusing a bearer token also removes the session cookie, so a request cannot silently switch accounts. Other cookies retain their quoting and escapes. Proxied WebSockets validate first-message and refresh tokens, recheck established sessions in both directions and while idle, and close on revocation or a failed check. Successful checks may be reused for up to 5 seconds.
