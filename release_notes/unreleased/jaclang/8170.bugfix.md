- **Fix: --scale pods boot the service module the deploy resolved, not a boot-time guess** (#8105): the deploy resolves every service's module host-side against the exact set of sources the bundle ships (explicit `[scale.microservices.services.NAME] file` > root `NAME.jac` > the unique same-named module anywhere in the tree; the implicit `main` boots the `[project] entry-point` module) and pins it in the pod's `JAC_SV_FILE`, replacing the entrypoint `find` that booted same-named strays nondeterministically. Parked, missing, or ambiguous modules now fail the deploy naming the file and the setting, `--dry-run` included and before anything is downloaded or sealed, instead of crash-looping the fleet; the entry-module guard also covers baseline exclusions, and `JAC_SV_FILE` joins the protected pod env keys (a `JAC_SV_FILE` set in a service's `env` overlay is ignored). The pack validates against the microservices config the deploy actually emits pods for, SDK deploys included, and an unparseable `jac.toml` fails the pack instead of sealing a bundle no pod can boot.
