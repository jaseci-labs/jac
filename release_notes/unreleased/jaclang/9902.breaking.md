- **Breaking: a closure the loop keeps cannot capture a local the loop assigns (`E2097`), and one handed to an opaque callee warns (`W2084`)**: a local assigned in a loop body is owned by the enclosing function, so every `lambda` or nested `def` the loop created over it shared one binding and saw the value the last iteration assigned. In a JSX `for` slot that made every per-item handler act on the last item, and nothing reported it. `jac check` now reports it in every codespace, naming the variable and the assignment. It is an error (`E2097`) when the code itself keeps the closure past its iteration: a JSX attribute, a container, field or subscript that outlives the iteration, or a `yield`. It is a warning (`W2084`) when the closure is only passed to a callee the compiler cannot see into, since that callee may run it before returning; the warning does not fail the check. Scoping is unchanged, and a type annotation is not a scoping construct, so `row_id: str = ...` in a loop body is reported exactly like `row_id = ...`. Migrate either one by binding the value through a parameter, which is bound per call: declare `def opener(row_id: str) -> Callable[[], None] { return lambda { show(row_id); }; }` outside the loop and write `onClick={opener(row_id)}` (or `handlers.append(opener(row_id))`) inside it. Not reported: a closure that cannot outlive its iteration (called on the spot, a local helper that is only called, the callback of `map` / `filter` / `sorted(key=...)` and similar, or one in a `return`), a name the loop does not assign, and the loop target itself. See [Breaking Changes](../breaking-changes.md).
