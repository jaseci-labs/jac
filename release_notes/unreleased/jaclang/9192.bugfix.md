- `POST /jobs` can create a job again: it resolved its target through `get_walkers()` / `get_functions()`, which filter out everything carrying a `schedule_spec`, so every `@schedule(trigger=ScheduleTrigger.DYNAMIC)` target answered `404` and the "no `@schedule` decorator" branch below it was unreachable. Name resolution now goes through a new `find_target`, and the HTTP-routing filter stays where the routes are built.
- Scheduled jobs are bounded per account: `[scale.scheduler] min_interval` (default 1 second) is enforced when a job is validated and again when it is handed to the scheduler, and `max_jobs_per_user` (default 25, admins exempt, `0` for unlimited) answers `429 QUOTA_EXCEEDED` at the cap. Before this, the only interval rule was "greater than zero". The cap is applied inside the job store, serialised per account, so concurrent requests cannot race past it, and a bound that is out of range is reported by config validation rather than silently disabling the limit it configures.
