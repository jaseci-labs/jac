- **`/cl/__error__` limits each client, refuses oversized reports and logs browser-extension errors below ERROR**: one page reporting in a loop, from a runtime older than #10272 or a direct client, used to get `200` for every report while one shared per-process budget silently dropped every other user's errors. Each client now gets 20 reports a minute and then `429 RATE_LIMITED` with `Retry-After`, counted in the shared database so the limit holds across every worker and replica (each worker counts on its own only when that database is unreachable). A report over 64 KiB gets `413`. A report whose stack frames all point into a browser extension is logged at INFO, tagged, instead of at ERROR. A fleet gateway applies the same per-client limit before forwarding, even with its general rate limit off; tune it with `[scale.gateway.rate_limit] client_error_rpm` (default 20, `0` turns it off). In a cluster the gateway applies it only with its ingress in `[serve.proxy] trusted`, which `jac scale deploy` does not set; otherwise it skips the limit, says so at startup, and the services limit each browser.
