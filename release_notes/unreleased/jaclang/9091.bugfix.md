- **Fix: `jac install --frozen` now fails loudly**: A stale or missing `jac.lock` row for a pure-jac dependency makes `--frozen` exit nonzero with an error, instead of printing success and exiting 0.
- **Fix: dev pure-jac deps are no longer erased**: A plain `jac install` (or any install without `-d`) keeps `[dev-dependencies.jac]` entries in `jac.lock`, the deps map, and the import path, instead of dropping them on the next lock rewrite.
- **Fix: strict version constraints**: Unrecognized constraints in `[dependencies.jac]` (`>=`, `~`, `*`, ranges) now error instead of silently matching any version, and `^0.y.z` follows caret semantics (same minor version, e.g. `^0.2.3` rejects `0.5.0`).
- **Fix: honest `--dry-run` for `jac:` specs**: `jac install jac:<url> --dry-run` no longer materializes packages into the build directory.
- **Fix: failed dependency removals roll back**: When `jac remove` cannot re-resolve the remaining pure-jac dependencies, it now restores the manifest and reports the error instead of leaving `jac.toml`, `jac.lock`, and `.jac/` inconsistent.
- **Fix: targeted `jac update` advances its closure**: `jac update <pkg>` now also refreshes the pure-jac dependencies reachable from the updated packages, so a branch-tracking transitive no longer replays its old locked commit while its requirer moves ahead; unrelated locked dependencies stay frozen.
- **Fix: concurrent store publishes keep the valid winner**: The content-addressed store hash now ignores the `.jac-origin` bookkeeping marker, so a racing publish no longer deletes a just-written store entry it mistakes for corrupt.
- **Fix: `jac why` shows direct npm dependencies**: A package that is a direct npm dependency is now reported even when jac/python dependency chains exist for the same name.
- **Fix: wheel packing and native ejection no longer abort on compiler-internal type errors**: Building a wheel that vendors the jac runtime (or ejecting a native app) compiles `jaclang`'s own sources with the native type checker; pre-existing type errors inside pass implementation files (native IR generation, ES AST generation) aborted that build. Those files now typecheck cleanly (pure narrowing fixes; no change to emitted IR or diagnostics).
