- **Fix: py2jac complex/NaN literals are shadow-proof and dispatch correctly**: folded complex literals (`1 + 2j`) and non-finite components now lower to `<alias>.complex(re, im)` / `<alias>.float('nan')` through a single collision-free `import builtins as <alias>` injected only when such a literal is folded. The alias is a fresh binding for the real builtins module, so a source `def complex` / `def float` (or even a rebind of `builtins`) can no longer change the meaning of a compiler-generated literal. Admitting `builtins` in the native stdlib set keeps these modules on the native pathway (the import is namespace-only; builtin calls lower by canonical name).
- **Fix: qualified builtin recognition uses symbol identity**: `builtins.<name>` / `import builtins as x; x.<name>` calls are now recognized as builtins only when the prefix resolves to the actual builtins module, not when a user binding merely happens to be named `builtins`. A user object bound to `builtins` is no longer misclassified and mis-dispatched by native codegen.
