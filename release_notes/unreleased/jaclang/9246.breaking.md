- **Breaking: `jac purge` is removed; `jac cache` owns the machine-wide cache**: `~/.cache/jac` grew without bound (one report: 144 GB). Five independent root resolvers had drifted apart, and apart from the compiled-module generations nothing was ever evicted: every location a fused `jac` binary ran from extracted its own 500 MB runtime under a key that folded in the executable's path, abandoned `.tmp.<pid>` extractions stayed forever, and the bootstrap bytecode, stub catalogs, kernel units, per-checkout compiler digests, app images, toolchain downloads and release binaries only ever accumulated. `jac purge` reached about a fifth of it and named two directories that no longer existed. There is now one cache authority (`jaclang.cache`): one root rule (`JAC_CACHE_HOME`, else `XDG_CACHE_HOME/jac`, else the platform default; `cache_paths.py` keeps the rule for the pre-bootstrap tier and the fused launcher carries an equivalent copy, held to it by tests), a standard `CACHEDIR.TAG` on the root, a registry of every bucket with a retention policy (unused-for-N-days with a last-use marker, entry caps, pinned for model weights, report-only for the Postgres cluster, Gradle and the Android SDK), and one best-effort sweep that every writer runs opportunistically at most once per process and once per day. `jac cache status` lists every bucket with its size and policy, `jac cache gc [--dry-run]` runs every policy now, and `jac cache purge [--bucket <name>]` clears managed buckets and refuses external ones; `jac purge` prints the replacement and exits. `JAC_CACHE_TTL_DAYS` overrides every age at once. Fused runtimes are keyed by the payload hash alone, so one payload materializes once however many paths its binary runs from, and the launcher reclaims runtimes unused for 30 days and extractions abandoned over an hour ago at the next boot, never the running one. That sweep, and any removal it makes, is best-effort: the native `shutil.rmtree` gained CPython's `ignore_errors`, checks `unlink`'s result, and names the file that could not be removed rather than its parent, so a stale runtime that will not delete no longer kills a `jac` invocation that had already succeeded (#9053, #9060). See [Breaking Changes](../breaking-changes.md).
