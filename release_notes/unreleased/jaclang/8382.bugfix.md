- **Fix: a client import of a native module builds, and a non-function can no longer cross the cl->na edge**: the compiler injects `import { __na_bind } from "@jac/wasm_host"` into the emitted client JS but never recorded that specifier in the client manifest, and the manifest is what compiles `compiled/wasm_host.js` and gates the vite alias -- so the shim was never emitted, no alias was written, and rollup failed on a bare specifier, leaving every client module that imports a native-placed module broken in production builds and unresolvable under the dev server. The na binding now registers the shim through a shared `_register_jac_virtual_import`, while the native module itself still stays out of the manifest. Registering the shim alone only moved the failure to runtime: a wasm module exports only functions, so importing a type bound it to a plain async callable that the client then constructed, dying at first render with a TypeError while `jac check` passed and the binding was recorded with an invented `() -> int` signature. Non-functions crossing the edge are now rejected with E5100, including where the name is used only as an annotation, since the `__na_bind` destructure is emitted either way. Deciding that from the import symbol was not sound -- symbols link to the native module only when it is the compilation entry, so as a dependency every name reads as unlinked and a valid function would be rejected -- so the boundary facts now resolve the native source module for the cl->na edge the way they already do for the server edge, which additionally corrects binding signatures for dependency modules that previously all recorded `() -> int`.
