- **Fix: an authenticated WebSocket target forwards its caller to nested `sv` calls** (#10450): a walker or function served over WebSocket ran as the validated user, but a `sv import` call it made sent the service bridge's bearer instead of the caller's, because only the HTTP path set the forwarded `Authorization`. The token validated at connect time (query `token` or first-frame handshake) is now forwarded as `Bearer <token>` for each message's execution, including every chunk of a streamed result, and a `refresh` frame replaces it. The previous auth context is restored after each message, whether the target succeeds, fails or is cancelled. A public WebSocket endpoint forwards no caller token, even when the client sends one.
