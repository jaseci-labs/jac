- **JacPython: much more of CPython is native Jac**: about 345,000 lines of CPython 3.14.6's C are replaced by native Jac, verified against CPython's own upstream test suites. Newly ported extension modules: `posix`, `_socket`, `_ssl`, `_hashlib`, `_asyncio`, `_sre`, `_sqlite3`, `_decimal`, `_datetime`, `_zoneinfo`, `unicodedata`, `pyexpat`, `_elementtree`, `_multibytecodec` and the six CJK codec modules, `_lzma`, `_zstd`, `time`, `select`, `mmap`, `fcntl`, `termios`, `_posixsubprocess`, `_multiprocessing`, `_posixshmem`, `_uuid`, `_lsprof`, `_abc`, `_codecs` and `_locale`. The object model is under way: `bool`, `cell`, `namespace`, capsules, sequence iterators, `enumerate`, `slice`, `range`, `complex`, generic aliases, unions, method objects, struct sequences, pickle buffers and template strings are Jac. Argument errors, calling conventions and docstrings match CPython's for every ported module, and the argument layer binds calls without per-call allocation. See [JacPython migration](../../internals/jacpython-migration.md).
- **C interop for porting C**: `ptr[T]` supports C pointer arithmetic and ordering; `glob name: T;` in a C block declares a C variable and `glob name: T = value;` defines C data (static type objects, method tables, `list[T]` arrays, including arrays laid out from a bytes literal, and `ptr(f)` function addresses); a `def` with a body in a C block defines a C function under its exact symbol and C ABI; variadic C functions are called with C's default promotions and defined with `*args: VaList`; `&mut x` lends a local's address to a C function's `ptr[T]` parameter; and a platform-variant module (`name.<os>[.<arch>].jac`) is compiled and linked as its own native unit.
- **Guaranteed tail calls**: `return tail f(args);` lowers to LLVM `musttail` on the native backend, so dispatch loops such as an evaluator run in constant stack; a call that cannot reuse the frame is `E5113` naming why.
- **Native correctness and speed**: a raise releases the locals of every frame it crosses; functions with `try` are optimized instead of compiled at -O0; module initializers run in import order; same-named classes in different modules and in the jaclang package stay distinct; `isinstance` sees subclasses defined in importing modules; nogc objects own their `str` and `bytes` fields; the ELF linker binds C data imports through the GOT and the wasm linker applies data relocations; C entry points leave any open memory region.
- **New diagnostics**: `E1145` for importing a name the source Jac module does not define (native builds, which previously lowered it to NULL), and `E1159` for writing through a scalar `&mut` parameter, which never reached the caller.
