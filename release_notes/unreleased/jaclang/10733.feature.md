- **Natively linked modules load their cached machine code instead of generating it again**: `jit_engine` already kept the optimized bitcode of a link plan on disk, but every new JIT engine still compiled that bitcode to machine code, about 1 s per engine. It now stores the compiled object beside the bitcode image, under the same key, and hands it back to the engine on the next load. Each load still gets a fresh engine with its own globals. In `jac test`, where every test file reloads its imports, a jacBuilder file importing its server module spent about 18 of its 20 s reload on that code generation.
