- **Fix: a class-form archetype is constructed through a module alias in native code**: `module.Class(...)` for a class-form archetype was taken for a runtime class value and failed to lower, so the function fell back to its Python implementation. A module-qualified class reference now constructs the class directly, as it already did for object-form archetypes.
- **The native code generator runs in the compiler kernel**: the generator, the primitive emitters and the LLVM IR builder are kernel units, and a kernel session lowers a module placed in the native codespace itself. It returns the module's LLVM IR, native interface and layout in the unit record, and the host turns that into machine code, cache sections and an engine without analysing the module. A project dependency the host has no cached unit for is lowered in the same session; a module that cannot be lowered is demoted and recompiled on the server inside the session, and the host records the verdict. `jac run` asks the kernel first for a natively placed program, so a native program is analysed once per compile and not at all on a cached run. For `examples/chess` on an M-series Mac, `jac run` drops from 2.8 s to 1.9 s on the first run and from 2.5 s to 1.1 s on later runs. A program module is no longer lowered by the generator running as Python bytecode; that generator now only builds the compiler's own native units.
- **Native generation asks the host for target facts**: the target's data layout, struct offsets, codec tables and the host OS are answered by the host through one question (`native_fact`) instead of being read from LLVM and the Python standard library inside the generator.
