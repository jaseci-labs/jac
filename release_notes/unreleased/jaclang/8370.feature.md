- **Native boot lanes for `--as binary` jabs**: `jac build --as binary` now also seals a `jac_entry`-exporting shared library alongside the standalone executable; `jac run` on such a jab first execv-s the standalone exe, falls back to dlopen-ing the entry library into the Python host (shared address space, ready for Python↔native interop), and finally to the JIT interpreter. Once the entry has started running, failures abort instead of falling back so its side effects never run twice.
- **Native: sealed native apps that call into Python now build and dispatch correctly (na->sv interop)**: `BoundaryAnalysisPass` computed `pinned_server` only for client-context callers, so a native-pinned module importing from a server-pinned provider never formed an na->sv binding -- the pin path now admits `InteropContext.NATIVE`, `native_imports` populates, and the E5093 scalar checks enforce on it automatically. The standalone-exe gate moved to the one place self-containment is actually required (`NativeLinkTarget.STANDALONE_EXE`), shared-library links warn about the symbols they leave for the loading host, and `nacompile_sealed_pair` seals such apps as the host-driven entry library alone, recording the decision in a `<lib>.interop.json` record at seal time. The jab manifest carries `native.interop` from that record (never inferred from artifact presence, so a lib-only payload built by other means keeps its execv/dlopen fast path), and `run_jab_image` is exe-first via `execv` for non-interop apps while interop apps stay host-driven through `run()` -- the only path that can resolve their na->sv callbacks.
