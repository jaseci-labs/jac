- **Client: lambda-body locals are per-invocation, so `.map()` closures capture their own item**: a name first assigned inside a lambda body was recorded by the symbol table as a local of the enclosing component function, because `is_python_scoping` predates statement-bodied lambdas and did not treat `LambdaExpr` as a variable-owning scope. The ES emitter's declare-in-owning-scope machinery then hoisted one shared `let` to component scope, so every per-item handler built in a `.map()` acted on the last item, and on main the annotated `x: any = ...` workaround had regressed too. Lambdas are now function scopes in the binding model: fresh names declare inside the lambda (branch-assigned names hoist to the lambda top, not past it), assignments to names with an enclosing binding remain closure rebinds matching nested-def semantics, and the native lowering emits the same `nonlocal`/`global` directives nested defs get, fixing the UnboundLocalError that closure-mutation lambdas previously raised natively.
