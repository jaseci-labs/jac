- **Fix: a native cycle collection no longer runs inside a destructor**: under the managed profile, dropping a large container could start a cycle collection in the middle of its destructor, while a field (released before the new value was stored) or the container's own slots still reached it. The collection traced the half-destroyed container and read and wrote the headers of elements it had already freed, corrupting the heap. Field assignment now stores the new value before releasing the old one, and a collection triggered while any destructor runs waits until the outermost release returns.
