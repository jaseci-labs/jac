- **Fix: unpacking, chained, walrus, `with` and `except` rebinds of a variable to another type are reported** (#10453): after `title = Label()`, writing a string into `title` with tuple or list unpacking, a chained assignment (`other = title = "x"`), a walrus (`title := "x"`), `with ... as title` or `except E as title` passed `jac check`, and native code then used the string as the object. These are now `E1001`, the same as `title = "x"` and a `for` target. This can flag code that passed before: the graph idiom `end = here; end ++> (end := node_a(...))` is now `E1001` ("Cannot assign node_a to Root"); give `end` the wider type it holds, `end: Root | node_a = here;`. `match` patterns are not checked yet (#10564). Unpacking an element that is not a tuple also gets the type iterating it yields, so `for [k, v] in rows` over `list[list[str]]` types `v` as `str`, and `for (a, b) in d` over a dict no longer types `b` as the dict's value type.
