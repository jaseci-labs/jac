- **Fix: a JSON `null` for a non-optional field is refused instead of stored as "None"**: Request binding had no check for `null` before its scalar branches, so a `str` walker field or function parameter stored the text `"None"`, while `int`, `float` and `bool` each failed with a different message. Every field that is not optional now answers the same 422, `null is not allowed for <type>`; a field declared `T | None` still accepts `null`.
