- **Bare generics propagate `any` through chained operations**: a value read out of a bare `dict`, `list` or `tuple` was assignable anywhere, but subscripting, attribute access, arithmetic or iterating it produced `<Unknown>`, so ordinary JSON handling like `data["main"]["temp"]` failed against any typed target while `data["name"]` was accepted. The checker held two separate representations of `any`, one built for bare generics and one loaded from the typing stub, and only recognised the second, so the two spellings `dict` and `dict[str, any]` behaved differently despite `W1036` reporting them as equivalent. Both representations are now recognised through a single predicate, so bare generics behave as the warning advertises and nested access keeps type checking instead of pushing authors toward blanket `any`.
