- **Native compilation: the module is the unit, every artifact is a link**: The native backend no longer builds one fused LLVM module per closure with its own IR-text cache, kernel-unit concatenation, regex-ordered initializers and a process-global scope flag. Every native-locked module's JIR now carries its native interface (`SEC_NIFACE`, digest-prefixed like the type interface), its relocatable object (`SEC_NOBJ`) and its bitcode (`SEC_NBITCODE`, formerly `SEC_NATIVE_OBJ`), and the native-interface digests of the units it was compiled against (`SEC_NDEPS`), each stamped with the compiler digest, codegen identity and triple, so an ordinary body edit rebuilds its unit and an interface edit rebuilds its dependents, and no bytecode compile of a unit ever disturbs its native products. Every external symbol that is not `:pub` is module-qualified (`<unit prefix>.<name>`); `:pub` symbols keep bare names, except bundled `na_stdlib` shim APIs, whose symbols remain module-qualified. One link plan (`compiler/backends/native/link_plan.jac`) walks dependencies first, compiles stale units in owned compiler sessions and settles dependency agreement in deterministic cycle-group order; it produces every artifact for `jac build --native`, native app builds, the kernel, the seal and the in-process JIT, in `objects` (incremental) or `bitcode` (whole-program, `--link-mode bitcode` / `[native] link_mode = "bitcode"`) mode; the platform linkers take `objects: list[bytes]`. The kernel comes from `resolve_kernel()`: explicit switch, sealed image record, source tree by source key (rebuilt on demand in a child process, so `zig build -Ddev` needs no kernel step), or the store parser. The OSP, format and region kernels are ordinary native units pulled by dependency edge; `runtime/region_native.jac`'s `__jac_region_*` functions and `osp_graph.jac`'s `osp_adj_pairs` are now `:pub`. Removed: the `.ir_cache`/`.ir_meta` dependency cache, `DepClibMeta`, `kernel_units.jac`, `shared_emit.jac` (`link_glue.jac` synthesizes the entry, init and C ABI wrappers), the `.nademote` sidecar (the verdict lives in the module's `SEC_PLACEMENT`), `activate_scope_lowering` and friends (`CompileOptions.native_unit`), `toolchain_native_by_policy` (`placement_facts.native_unit` / `native_only`), `_kit_site_present`, `CompileOptions.kernel_unit`, and the ES backend's use of the kernel-unit cache (now `backends/es/client_kernel_cache.jac`). JIR format 28 and native-interface format 3; sealed manifest format 9 records a package's native units and its one linked artifact with sha256, layout digest and plan digest, verified at load; a sealed app with native pins ships that artifact and runs it through a `ctypes`-backed engine. Every module cache and sealed image invalidates once.

- **Incremental development builds**: `jac build --native` reuses unchanged units and skips the final link when input and output hashes agree. Relocatable objects are emitted on demand from cached optimized bitcode. Default arguments participate in interface identity; generic bodies and compile-time inputs use the shared dependency encoding in stamped `SEC_NCTDEPS`, preserved across bytecode writes. Content keys detect preserved timestamps and annex additions or deletions. Compiler-source edits still invalidate the compiler digest; JIT and bitcode builds retain whole-program optimization.

- **JIT foreign-library binding is explicit**: Each C import binds to its declared shared library within its execution engine. Missing libraries or symbols produce compilation errors before an engine is exposed; unrelated process symbols no longer satisfy a missing import.

- JIR format 28 stores native products by their full compiler stamp. Existing JIR caches are rebuilt automatically.
