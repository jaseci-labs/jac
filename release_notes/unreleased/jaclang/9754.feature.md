- **Feature: `JAC_SYMMAP` names private functions in whole-program native builds**: native binaries carry no symbol table, so profiling one relies on the `<binary>.symmap` written when `JAC_SYMMAP` is set. Functions with LLVM `private` linkage got no symbol and were left out of that map, so a profile charged their cost to whichever named function preceded them. The compiler's refcount, release and trace helpers are private, so in a refcount-heavy program most of the time landed on an unrelated function. With `JAC_SYMMAP` set, a `--link-mode bitcode` build now gives those functions `internal` linkage before emitting, so they appear in the map under their own names. The generated code is unchanged, and builds without `JAC_SYMMAP` are not affected.
