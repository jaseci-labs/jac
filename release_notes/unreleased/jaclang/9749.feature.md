- **Performance: native refcounts stay non-atomic until the program starts a thread**: every retain and release in native code was a `lock`-prefixed atomic update, paid even by programs that never start a thread. Updates are now plain until the program starts its first thread. Every compiler-emitted spawn (`flow`, parallel `flow for`) and every C-imported `pthread_create`, `thrd_create`, `CreateThread` or `_beginthreadex` call switches them to atomic first, for the rest of the run. Native code loaded by a Python process (a shared library or a JIT engine) is atomic from the start, since any Python thread may call into it. A refcount-heavy benchmark (building and walking linked lists of objects, `jac build --native`) runs 14% faster (451 ms to 386 ms). Not detected: threads that a C library starts itself and that call back into Jac.
