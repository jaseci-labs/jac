- **A JIT'd native unit initializes itself**: an AOT image runs its module-level initializers from `main` (or `DT_INIT_ARRAY` for a shared library), but a JIT'd unit had no loader to do it and `jac_entry` is only emitted for a module with a `with entry` block, so a native library unit had no callable initializer at all. An import's module-level table was then read at its null placeholder, and `keyword.iskeyword` -- a walk over the `kwlist` table -- segfaulted the host process in both import spellings. A JIT engine now carries the ordered initializer plan for the unit it holds and runs it before it hands out any function address, with `jac_entry` exempt because it chains the same initializers itself after the GC-mode and `argv` setup that must come first.
- **A cross-module static call into a Python-side class refuses out loud**: a module whose class inherits a Python-side base is classified Python-side by the native import walk, so no struct type is registered for that class in an importing unit. The free-function crossing already ended at a terminal diagnostic, but the class-qualified form had no matching arm and fell through to a bare `return None`, dropping the call with no diagnostic at all. `Cls.method(...)` on a class the native lane did not lower now reports E5092 naming the callee, landing module-fatal at module scope and demoting only its owning function in a body.
