- **Fix: a KEDA workload idled to zero is no longer reported as degraded**: `get_runtime_status` read the generated HPA's `ScalingActive: False` as a scaler failure, but KEDA's HPA reports that whenever its target sits at zero replicas because there are no pods to compute a metric from. For a workload whose replica floor is zero that is the resting state, so every idle scale-to-zero target read `degraded`, which is the defect one verdict removed from the Deployment reintroduced one layer up from the HPA. The condition is now read by its reason: `ScalingDisabled` is the HPA stating that the target sits at zero, which is about replica count rather than scaler health, while `FailedGetExternalMetric` and `FailedGetResourceMetric` remain the genuine failures they have always been. Comparing replica counts instead would be racy, because the HPA and the Deployment are separate objects read moments apart, so just after a deploy the HPA already reports `ScalingDisabled` while the Deployment still reads its pre-idle count. The reported reason also named the wrong condition, because `Ready` was preferred whenever it carried a message, so an HPA-side failure surfaced with KEDA's success reason `ScaledObjectReady`; it now names whichever condition actually reports `False`, which fixes the message a caller sees for a real scaler failure too. Found by the real-cluster observer e2e, which recorded two spurious `inactive -> degraded` transitions during an otherwise healthy cycle and passed anyway; that e2e now asserts a healthy cycle emits no `degraded` at all, and the HPA unit test covers `ScalingActive: False` at zero replicas rather than only a genuine metric failure. Fixes #9501.
