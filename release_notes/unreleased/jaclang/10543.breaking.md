- **Breaking: the native compiler kernel does every compile, check and tool query when it is loaded**: the kernel is the `jac_kernel` JacPython extension module, reached only through `project/kernel_call.jac`, and it reads the project, parses Python, produces bytecode and drives LLVM itself; nothing calls back into the host. `JacProgram.compile`, `jac check`, the formatter, linter, language server, studio and native builds all go through it. A kit that leaves the kernel out (`JAC_KIT_OMIT=kernel`) runs the same kernel code as bytecode; a kit that should carry a kernel but has a missing, stale or unloadable one stops with an error naming `jac native build kernel`. The parse-only route, the host callback channel and the host fallbacks are removed. Tests that read the compiler's own trees run on the bytecode-hosted compiler in a kernel-less child process named by `[test] bytecode_compiler`, whose patterns now take `!` exclusions.
