- **Fix: darwin CI runs the string and bytes primitive equivalence pins, and the str pin requires the native tier**: `test-native-macos` ran the bundled-stdlib equivalence pins filtered to `shutil or path or textwrap or keyword`, so darwin ran no string-primitive equivalence at all and every `prim_str.jac` and `prim_bytes.jac` pin -- `lower`, `upper`, `startswith`, `endswith`, slicing, `join`, iteration, relational compare -- was Linux-only. The native lowering of those primitives is not platform-neutral: `str.lower()` lowers to a per-byte call to libc `tolower`, and the two link paths do not resolve that name to the same implementation, since Linux executables statically link the vendored musl while the Mach-O path binds every undefined symbol to `libSystem`, whose ctype functions are rune-locale driven. Running them was not enough on its own, because `run_with_both` swallows a native-backend failure unless the caller names `"na"` in `require`, and the `str` pin did not -- so a native tier that failed to compile or run left the pin green. The `str` pin now requires `"na"`, which it satisfies on both platforms, making it an enforced darwin guard rather than an optimistic one.
- **Fix: the native CI lanes see changes to their own definition**: `changes.native` listed the native pass sources, the native test directory, `test_prim_equivalence.jac` and the zig build files, but not `.github/workflows/ci.yml`, where the native lanes are defined. Editing what a native lane runs therefore left that lane skipped on the very pull request that changed it. `core` already listed the workflow file for this reason; `native` now does too, along with the `prim_*.jac` equivalence fixtures, whose contents decide what those pins assert.
