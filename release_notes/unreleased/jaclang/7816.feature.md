- **`jac build` honors the `[project] jac-version` pin**: the seal-producing projections (`--as jab`, `--as sealed`, `--as binary`) now seal with a jac that satisfies the project's `jac-version` spec. When the running jac is outside the pin, the build downloads the pinned release binary for the host platform (checksum-verified, cached under `~/.cache/jac/toolchains/`) and re-runs itself under it, erroring only when the pin matches no published release or the release has no binary for the host; `JAC_NO_TOOLCHAIN_FETCH=1` disables the fetch and makes any mismatch a plain error. Source distributions (`wheel`, `npm`) are not gated. Deploys already resolved the pin and seal with the pinned pod binary; build and deploy now agree.
- **Pinned pod binaries cache per version**: the deploy binary cache is keyed by the resolved version rather than by channel alone, so several pinned toolchains coexist on one machine and a re-resolved pin can no longer be served stale bytes from a channel-keyed file.
