- **A shadow-initialized construction refuses instead of coming out hollow**: a native class over a Python-side base kept its own slots in the native struct and the base's on a Python shadow beside it, and construction lowered to a `_pyb_instantiate` bridge whose result was dropped on the spot. The base's `__post_init__` then ran on that discarded shadow, where the subclass's native slots do not exist and its overrides are not on the shadow's class, so the next field read answered the slot's declared default and nothing was diagnosed. E5088 names the class and the ancestor whose initializer would run there and demotes the owning callable; a subclass with a `postinit` of its own, and a base chain carrying none, both stay legal. Genericity is how the compiler's pass chain reaches this path, not why the path is wrong -- the non-generic control fixture was equally hollow. Alongside it, `JcirGenPass.exit_import` retires the last `self.prog` read in any sealed pass onto a driver-stamped `Import.native_only_drop`, and `test_jcir_sealed_bytes.jac` is renamed to `test_jcir_bound_emitter_bytes.jac`, which is what it can actually check: the pass-serving binder retains no function pointer, so both sides of its byte comparison are the source lane.
