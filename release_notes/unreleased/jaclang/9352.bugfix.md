- **Fix: a bytes escape warns, and the warning names the escape's own line**: An invalid escape in a bytes literal was silent. The decoder handed the body straight to the runtime, so `b"\d"` and `b"\N{BULLET}"` compiled without the invalid-escape-sequence warning CPython reports. Bytes literals now carry their own valid set, the str escapes without `\u`, `\U` and `\N`, which name a code point and so are str-only, and they run through the same check the str decoder uses. The warning also named the line the literal opened on rather than the line the escape sits on, so a `\d` on the fourth line of a triple-quoted string starting on the second was reported against the second; it now names the escape's line, matching CPython 3.14 (3.12 named the opening line, so the behaviour depends on which version you compare against). The newline count runs only when a warning fires, at most once per literal, so the decode loop is unchanged for source without invalid escapes.
