- **Breaking: An `edge` declaration must name its endpoints**: `edge Foo {}` is now `E2086`. The endpoint clause was already the thing that let a traversal through an edge infer a node type instead of `any`, so leaving it off was the one place the language let an annotation be implied by silence, while `has v;` is a parse error and an untyped parameter is `E0052`. Write the node types the edge connects -- `edge Foo: Src --> Tgt {}` -- or say the widening out loud: `any --> any` keeps the old behaviour exactly, and `Node --> Node` asks for a node without naming which. An edge that inherits endpoints from a base edge needs no clause of its own.
- **Breaking: A connect or traversal that contradicts an edge's endpoints is an error**: The declaration was trusted by inference but never checked, and because archetype field access resolves by slot index a violated declaration read the wrong field instead of raising. Connecting the wrong node types is `E1136`, traversing an edge from a node it cannot start from is `E1137`. An operand that is merely more general than the declaration (a `Node` where `Profile` is declared) may still be the declared type at runtime, so it warns -- `W2081` and `W2082` -- rather than failing.
- **Edge endpoints accept a union**: An endpoint is a type position like any other, so `edge Multi: Base --> A | B {}` now parses and narrows to `list[A | B]`. Previously endpoints parsed through a narrower path than every other type position, which is why `has v: A | B` worked and the endpoint form did not.
- **Endpoint checks cover collections and bidirectional connections**: Every tuple member is checked, and bidirectional connections must satisfy both orientations of the declaration. A traversal that ends with an unconstrained hop no longer retains the previous hop's narrower result type.
