- **Scale: a pinned app's client bundle is built by the version it pinned**: `[project] jac-version` governed the pod binary, the pod base image, the admin console and the `.jab` seal, but not the client bundle, which the deploy host built with whichever jac happened to be deploying and shipped to a gateway pod that never rebuilds it. A 0.34-pinned app deployed from a 0.36 host therefore ran 0.36 client JS against a 0.34 pod, and when the two generations disagreed about module resolution the build died with an unresolved-import error naming the app's own file, reading as an app bug rather than a toolchain mismatch. `host_toolchain_path()` now resolves the pin through the same `resolve_deploy_version` the seal already uses and runs `jac install` and `jac build --client web` on that release, reusing the verified download the seal fetches anyway. `_seal_subprocess_env` becomes `release_binary_env` and also drops `JAC_DEV_SOURCE` and `JAC_NO_PRECOMPILE`, which a child jac reads back to locate the compiler's extension registry and which otherwise pointed a pinned release binary at the deploying jac's compiler (the seal had the same hole).
