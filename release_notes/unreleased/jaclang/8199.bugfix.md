- **Fix: the seal's parse parity canary reports what diverged, not both trees**: the canary that gates `libjac_native_materialize` reported an unparse mismatch by line index, and a materialized module unparses to a single line, so every failure read "fingerprints diverged at line 1" followed by the whole native text and the whole bytecode text -- a two-kilobyte single-line blob the reader had to diff by eye, truncated in the Actions web UI long before the difference. The report now gives the character offset, line and column of the first difference, every differing whitespace token up to six with both sides quoted and an eight-token window of context, and the symbol-name fingerprint comparison alongside the unparse one instead of only when the unparse already matched. For a generated-name divergence the symbol entry is the sharper signal: `Test:test__jac_gen_2` vs `Test:test__jac_gen_1` states the defect where the unparse only shows a shifted ordinal. `JAC_NA_DEBUG=1` still writes both full unparsed texts to stderr, and the seal's error line no longer interpolates the detail mid-sentence.
- **Seal parity: an ident-derivation probe bisects a divergence on the platform that fails it**: after a divergence is established, the canary parses nine one-line sources through both tiers, each a described test followed by a bare `test { }`. A description whose identifier derives must not consume a generated ordinal, so the trailing bare test must be `_jac_gen_1` on both tiers; the descriptions vary one axis each (lowercase, uppercase, digits, an embedded separator, a leading and a trailing separator, single quotes, a non-word character, and the no-identifier `"..."` case that is supposed to consume an ordinal). Whichever rows report `DIVERGED` name the step of the `_string_lit_text` and `_test_ident_from_desc` pipeline that the native tier gets wrong. The probe runs only on the failure path, so it cannot affect a passing seal.
