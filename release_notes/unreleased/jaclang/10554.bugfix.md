- **Fix: the deploy's bundle walk skips build trees instead of listing them**: `jac start --scale` lists the app's bundle sources on a background thread while the main thread fetches the pod runtime from GitHub. The walk ran `rglob("*")` over the whole project, descending into `node_modules`, `.jac/venv`, `.git` and every other build tree only to drop what it found there. On a large project that kept the thread busy long enough to starve the main thread's requests: GitHub's TLS replies sat unread for seconds until GitHub closed the connection, and the deploy failed with "Could not reach ... (Remote end closed connection without response)". The walk now prunes a build tree as soon as it reaches one, unless a path the bundle requires (`.jac/client/dist`, `.jac/admin`) can sit under it, and it returns exactly the same files and pruned-tree report as before. Nested `jac.toml` discovery prunes build trees the same way, since it also ran over the whole project on every deploy.
