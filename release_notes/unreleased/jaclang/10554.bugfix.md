- **Fix: a pinned deploy no longer fails when the admin console cannot be reached**: with `[project] jac-version` pinned, `jac start --scale` probed the optional admin console with HEAD requests on every deploy, and a single dropped connection (`Remote end closed connection without response`, a timeout, a 5xx) failed the whole deploy with "Could not prepare the 'stable' jac runtime". The pinned path now skips those probes and lets the checksum download it already needed decide: when GitHub gives no answer, the deploy continues without a staged console and the gateway builds one on its first admin request, as an unpinned deploy already did. A pin naming no published release, a console published without a checksum, and a checksum mismatch still stop the deploy. A cached console now costs one request instead of three.
