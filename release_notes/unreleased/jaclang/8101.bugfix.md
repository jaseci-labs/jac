- **Postgres boots only when a program touches the graph, and the official image runs as shipped**: `jaseci/jaclang:0.36.x` could not run `with entry { print("hello"); }`. Three causes compounded. `Session.postinit` ran `initdb` and started a server for every program, and `ExecutionContext.postinit` then read the super root out of it, so a script that touches no graph state still needed a live database; the image shipped no Postgres binaries, so the ~40MB embedded distribution was downloaded at container start (fatal in an air-gapped or registry-only cluster); and the image ran as root, where `initdb` hard-fails with `cannot be run as root`. Every stateless service on the stock image crash-looped, and the crash produced no output at all because the bundled CPython block-buffers a pipe and the process died before flushing, so `kubectl logs` came back empty. The embedded engine is now provisioned at the first store operation that actually reads or writes: `PgStore` takes the connection info `PgRuntime` can name without booting, and boots the server plus applies the schema once, under its own lock, when the first statement runs; the execution context resolves `system_root` / `user_root` / `entry_node` lazily; and `flush()` opens a transaction only when it has rows to write, so committing an untouched session costs nothing. A serving process still provisions as it starts rather than inside its first request, so no request pays for it and concurrent servers do not race to create the root row; a server whose database is unreachable now logs a warning and starts anyway instead of failing outright. The official image bakes the distribution (new `jac db fetch`, pinned via `JAC_PG_DIST`), keeps the cluster at a HOME-independent `JAC_CACHE_HOME`, and defaults to a real unprivileged account with uid 1000 so neither root nor an explicit `runAsUser: 1000` (previously `could not look up effective user ID 1000`) fails. A process that still runs as root drops privileges for the initdb/postgres subprocess to the first resolvable unprivileged account (`JAC_PG_USER`, `SUDO_USER`, then `jac` / `postgres` / `nobody`), or refuses with a message naming `JAC_PG_USER` and `JAC_DB_URL` instead of leaking `initdb`'s. `jac run` and `jac start` line-buffer stdout and stderr, so container logs survive a crash without `PYTHONUNBUFFERED=1`.
