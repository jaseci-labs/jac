- **Fix: a relative import with the wrong number of dots is E1134, not a file of that name at the project root**: when `import from .other.x { ... }` found nothing beside the importing module, the resolver dropped the dots and searched the project root, mounts and `JACPATH`, so `jac check` and the client build passed using `other/x.jac` while the server, which imports by the dots as written, failed with `No module named ...` or answered every walker call with `TARGET_UNAVAILABLE`. A relative import is now looked for only in the folder its dots name, so `jac check` and `jac run` report the mistake as E1134 and the client build fails instead of bundling the wrong file. Extra dots in a module given by a relative path, as in `jac check feat/mid.jac`, now climb past the folder the command runs in instead of stopping there.
