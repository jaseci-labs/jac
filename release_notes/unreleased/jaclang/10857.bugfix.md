- **Fix: importing a name its Jac module does not define is `E1145`, not a warning**: `import from records { Org }` where `records.jac` defines no `Org` was `W1101`, so `jac check` passed and the program failed on load with `cannot import name 'Org'`, while a native build already stopped on `E1145`. The checker now reports `E1145` when the source is a parsed `.jac` module whose names are closed (no module-level `__getattr__`, no `include`, no `globals()`/`vars()`/`exec()` call) and the import has to bind (not `import type`, comptime, or inside a `try` that catches `ImportError`). This also applies to a package whose `__init__.jac` lacks the name, and inside import cycles. A Python source, an open namespace, or a guarded import keeps the `W1101` warning.
