- **Feature: GraphMend graph-break elimination, on by default for torch code**: GraphMend rewrites, at compile time, the PyTorch 2 FX graph breaks that make TorchDynamo fall back to eager execution, so the forward pass stays a single contiguous FX graph. It detects fixable break patterns under `torch.compile` entry points (decorated functions and classes, or call-site wraps like `torch.compile(Model())`) in `.jac` and plain `.py` source alike, and applies three transforms: data-dependent validation guards lower to graph-native `torch._assert_async` with the original exception restored at an eager boundary (trap), data-dependent `if`/`else` branches are predicated into `torch.where` selections (where), and side-effecting `print` and logger calls are buffered and replayed in program order after the graph runs (defer). GraphMend is on by default: it engages per compiled module exactly for modules that import `torch` or a `torch.*` submodule, detected syntactically, so every other module compiles byte-identically to before and a module it cannot apply to never even schedules its passes. GraphMend-active compiles stay cached, with the GraphMend configuration folded into the cache key so configuration changes invalidate instead of colliding.
- **Feature: GraphMend configuration**: `[run] graphmend = false` in `jac.toml` is the off switch and the whole mode surface; absent means on, there is no CLI enable flag, and `CompileOptions(graphmend=...)` mirrors the same boolean, which every entry point that compiles code (run, serve, test, build, check, and library imports) resolves from the project config. `--graphmend-disable` / `run.graphmend_disable` skips individual transforms (`trap`, `where`, `defer`). The deferred side-effect buffers are process-global, so `[Defer]` declines under `jac serve` while `[Trap]` and `[Where]` still apply.
- **Feature: GraphMend claims imported model code**: there is no module scope to configure. A module claims itself when it imports torch and either wraps something with `torch.compile` or defines a `forward` whose class binds a torch Module base; claiming then follows that module's eager imports transitively, so a library module reached only through its importer is transformed too. The closure stops at `if TYPE_CHECKING:` imports, at the top-level package of the module that seeded it, and at `torch`, `jaclang` and the standard library. Claimed `.py` modules are routed through GraphMend by the meta importer and by a `SourceFileLoader` hook, installed only once torch enters the process so a run without torch leaves the import machinery untouched; a module the compiler cannot handle falls back to its original source rather than breaking the import.
- **Change: claiming imported code is now an explicit opt-in**: imported `.py` code is only claimed under `[run] graphmend_claim_imports = true` (default `false`); the modules the compiler is asked to compile directly stay transformed on the default. An abandoned claim (a granted claim the Jac front end cannot serve) now emits warning `W1107` naming the file and the reason, shown under `--diagnostics all`, and the `SourceFileLoader.get_code` patch is restored at program teardown instead of persisting for the life of the process.
- **Change: per-module GraphMend cache keys derive from the region closure**: a module's cache key now digests exactly the modules that can feed its compiled region (its claim chain, the entries that reach it, and the modules walked to resolve them) instead of every module loaded so far, so editing an unrelated file no longer invalidates the whole project's artifacts, keys are stable across load orders, and a guard's lowering decision is recomputed from that same closure on every compile rather than depending on which artifacts happened to be cache hits.
