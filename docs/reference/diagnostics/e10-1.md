# E1001 to E1041: values and their types

These codes are reported when a value has a type that the place using it does not take. Types are
shown as the program writes them (`int`, `list[int]`, `tuple[int, str]`, a class's name). Calls and
their arguments are in [E1050 to E1098](e10-2.md).

## E1001

```text
expected {expected}, found {actual}
```

A value of one type is given where another is wanted: a declared variable, a field or a list's
element (a `return` value is E1002). `{expected}` is the type the place takes and `{actual}` is the type of the
value. Nothing converts implicitly between unrelated types, so a `str` is never read as an `int`.

```jac
# expect: E1001
with entry {
    count: int = "three";
    print(count);
}
```

**Fix:** give a value of the declared type, convert by name (`count: int = int("3");`), or change
the declaration. See [Types](../../language/types.md).

## E1002

```text
cannot return {actual} from a function declared to return {expected}
```

A `return` gives a value that is not of the function's declared return type. `{actual}` is the
type of the value returned and `{expected}` the declared type. A bare `return;` returns `None`,
so it is refused the same way in a function whose return type does not include `None`; and a
value returned from `-> None`, or from an ability, which returns nothing, is refused too.

```jac
# expect: E1002 x3
def label(n: int) -> str {
    return n;
}

def first(xs: list[int]) -> int {
    if len(xs) == 0 {
        return;
    }
    return xs[0];
}

def log(m: str) -> None {
    return len(m);
}
```

**Fix:** return a value of the declared type (`return str(n);`), or declare the type the function
returns. Where a function may have nothing to return, say so in its type: `-> int | None`. See
[Functions](../../language/functions.md).

## E1003

```text
'{name}' returns {actual} but declares no return type: declare `-> {type}`
```

A function that declares no return type returns a value. `{name}` is the function, `{actual}`
the type of the value and `{type}` what to declare. A function without `->` returns nothing; one
that returns a value says which type, as its parameters say theirs. A lambda with a statement body
is held to this too, unless the function type it is passed as gives its result.

```jac
# expect: E1003 x2
def area(w: int, h: int) {
    return w * h;
}

with entry {
    double = lambda (x: int) {
        y = x * 2;
        return y;
    };
    print(area(2, 3), double(2));
}
```

**Fix:** declare the return type: `def area(w: int, h: int) -> int`, `lambda (x: int) -> int`. A
one-expression lambda needs none: its value is its expression's. See
[Functions](../../language/functions.md).

## E1004

```text
'{name}' is declared to return {type} but may end without returning a value
```

A function or lambda declares a return type that `None` is not part of, and some path through its
body reaches the end without a `return`. `{name}` is the function and `{type}` its declared return
type. In Python the function would return `None` there; here that is refused, because the caller
was promised a `{type}`.

```jac
# expect: E1004
def sign(n: int) -> str {
    if n > 0 {
        return "+";
    }
}
```

**Fix:** return a value on every path, or say that the function may give nothing by declaring
`-> str | None`. See [Functions](../../language/functions.md).

## E1005

```text
property {name} has no setter
```

An assignment writes a property that declares only a `getter`. `{name}` is the class and the
property, as `Circle.area`.

```jac
# expect: E1005
obj Circle {
    has r: float = 1.0;

    has area: float {
        getter {
            return 3.14 * self.r * self.r;
        }
    }
}

with entry {
    c = Circle();
    c.area = 2.0;
}
```

**Fix:** assign the field the property is computed from (`c.r = 2.0;`), or give the property a
setter:

```jac
obj Circle {
    has r: float = 1.0;

    has area: float {
        getter {
            return 3.0 * self.r * self.r;
        }
        setter(v: float) {
            self.r = (v / 3.0) ** 0.5;
        }
    }
}

with entry {
    c = Circle();
    c.area = 12.0;
    print(c.r);
}
```

```output
2.0
```

See [Fields](../../language/fields.md).

## E1010

```text
'{op}' is not supported for {type}
```

A unary operator is applied to a value whose type has no such operation. `{op}` is the operator
(`-`, `+`, `~`, `-%`) and `{type}` the operand's type. `-` and `+` take numbers, `~` and `-%` take
ints.

```jac
# expect: E1010
with entry {
    print(-"abc");
}
```

**Fix:** apply the operator to a number, or define the operator's method on the class (`__neg__`
for `-`). See [Operators](../../language/operators.md).

## E1020

```text
cannot unpack {type} into {count} targets
```

An unpacking assignment has a different number of targets than the value has items, or the value
cannot be unpacked at all. `{type}` is the value's type and `{count}` the number of targets.

```jac
# expect: E1020
with entry {
    (a, b) = (1, 2, 3);
    print(a, b);
}
```

**Fix:** write one target per item: `(a, b, c) = (1, 2, 3);`. A starred target (`(a, *rest) = ...`)
is not accepted, so take the rest with a slice instead.

## E1021

```text
cannot iterate {type}
```

A `for` loop, a comprehension or an unpacking iterates a value that is not iterable. `{type}` is
the value's type. An object is iterable when its class defines `__iter__`.

```jac
# expect: E1021
with entry {
    for x in 5 {
        print(x);
    }
}
```

**Fix:** iterate a collection or a range: `for x in range(5) { ... }`. See
[Control flow](../../language/control-flow.md).

## E1022

```text
{type} is not an iterator: it has no __next__
```

`next()` is given a value that is not an iterator, or a class's `__iter__` returns an object with
no `__next__` method. `{type}` is that value's type. A list is iterable but is not itself an
iterator, as in Python.

```jac
# expect: E1022
with entry {
    xs = [1, 2];
    print(next(xs));
}
```

**Fix:** make an iterator first: `print(next(iter(xs)));`. See
[Generators](../../language/generators.md).

## E1023

```text
{what} is not callable
```

A call's callee is not a function, a class or an object whose class defines `__call__`. `{what}` is
the callee's type, or its name in quotes when it names something with no value to call (a module,
for example).

```jac
# expect: E1023
with entry {
    n = 3;
    print(n(1));
}
```

**Fix:** call a function, or remove the parentheses if a value was meant. To multiply, write the
operator: `n * (1)`.

## E1030

```text
{owner} has no {kind} '{name}'
```

A field, method or other member is read or written that its owner does not have. `{owner}` is the
type (or `module 'm'` for a module), `{kind}` says what was looked for (`field`, `method`,
`static field`, `member`, `variable`, `attribute`) and `{name}` is the name written.

```jac
# expect: E1030
obj Point {
    has x: int = 0;
}

with entry {
    p = Point();
    print(p.y);
}
```

**Fix:** use a name the type declares, or declare the field (`has y: int = 0;`). Builtin types have
Python's methods: a list has `append`, not `push`, and a `frozenset` has none of `set`'s mutating
methods. See [Fields](../../language/fields.md) and [Methods](../../language/methods.md).

## E1036

```text
'{type}' needs type arguments
```

A generic type is named without its type arguments where a type is required. `{type}` is the bare
name: `list`, `dict`, `set`, `tuple`, `tensor`, or a class whose parameters are compile-time values.
Python accepts a bare `list` as an annotation; here a container's element type is always stated.

```jac
# expect: E1036
with entry {
    xs: list = [1, 2];
    print(xs);
}
```

**Fix:** write the arguments: `xs: list[int] = [1, 2];`. Use `list[any]` for a list that holds
values of any type. See [Types](../../language/types.md).

## E1040

```text
{type} is not subscriptable
```

A value is indexed or sliced with `[...]` and its type has no items. `{type}` is the value's type.
A bare `ptr` is one such type: it has no element type to read (see [E1199](e11-3.md)).

```jac
# expect: E1040
with entry {
    n = 5;
    print(n[0]);
}
```

**Fix:** index a list, tuple, dict, str or bytes, or define `__getitem__` on the class. See
[Collections](../../language/collections.md).

## E1041

```text
{type} is not awaitable
```

`await` is given a value that cannot be awaited. `{type}` is its type. A coroutine (what calling an
`async def` gives), an object whose class defines `__await__`, and an `any` can be awaited.

```jac
# expect: E1041
async def twice(n: int) -> int {
    return await n;
}
```

**Fix:** remove the `await` for a plain value (`return n * 2;`), or await a call to an `async`
function. See [Async](../../language/async.md).
