# E1540 to E1576: places, Shared, compile-time type functions, abilities that never run, a choice with no nodes, an undeclared import, and a C module wired whole

E1540 and E1541 report code that needs what the place it runs does not provide: a kernel, a parallel loop's threads, a space's host. E1560 to E1572 report a compile-time question about a type, or a decorator's argument, given something it does not apply to. See [What code needs from the place it runs](../../accel/requirements.md) (`jac docs requirements`) and [Compile-time evaluation](../../language/compile-time.md).

## E1540

```text
{what} needs {need}, which {place} does not provide (in {path})
```

A function, a construct or a type needs something the place its code runs in does not provide. `{what}` is what needs it, `{need}` the need (counted references, allocation, exceptions, a graph, tasks, C code...), `{place}` the place (a space's host, a kernel run for each index, a grid kernel, a parallel loop's threads) and `{path}` the function, or the chain of calls, that brings it there. A kernel runs on a device that has no allocator and no reference counts, so a list made in a kernel is refused.

```jac
# expect: E1540
import from accel { tensor, kernel }

def fill(i: int, y: tensor[f32, _]) {
    xs = [1, 2, 3];
    y[i] = 1.0;
}

with entry {
    y = tensor[f32, _](shape=4);
    kernel(fill).run(4, y);
}
```

Only native code runs C: in a cpython, node, browser or hermes space, each use of a C function,
record or global is refused where it is written (`abs() needs C code, which a cpython space does
not provide`), and a C declaration nothing uses is not.

In a browser, hermes or node space `{what}` may be a module: a stdjac module the space imports is
compiled with the space's own, so one that needs the native runtime is refused where it is imported
(`the module 'stdjac.remote' needs a graph, which a browser space does not provide`).

**Fix:** use what the place provides: in a kernel, an `array` of numbers in place of a list; in a
JavaScript space, the runtime's own module, `"@jac/runtime"`, for the classes a failed crossing
raises ([Crossings](../../apps/crossings.md#how-a-crossing-fails)).

```jac
import from accel { tensor, kernel }

def fill(i: int, y: tensor[f32, _]) {
    xs = array[f32, 3](1.0, 2.0, 3.0);
    y[i] = xs[i % 3];
}

with entry {
    y = tensor[f32, _](shape=4);
    kernel(fill).run(4, y);
    print(y[1]);
}
```

```output
2.0
```

## E1541

```text
{name} conforms to Shared, so each of its methods changes its object in one indivisible step, and '{method}' {why}
```

A class that conforms to `Shared` has a method that cannot change its object in one indivisible step. `{name}` is the class, `{method}` the method and `{why}` the reason: it `writes its fields`, or it needs something that several threads at once do not have. Several threads may call a `Shared` object's methods at the same time, so its state is held in atomics and changed through them.

```jac
# expect: E1541
obj Counter(Shared) {
    has n: int = 0;

    def bump {
        self.n += 1;
    }
}

with entry {
    print(Counter().n);
}
```

**Fix:** hold the state in an `Atomic` and change it with its methods. See [Atomics](../../language/numbers-atomics.md).

```jac
import from atomics { Atomic }

obj Counter(Shared) {
    has n: Atomic[int] = Atomic[int]();

    def bump {
        self.n.add(1);
    }
}

with entry {
    c = Counter();
    c.bump();
    print(c.n.load());
}
```

```output
1
```

## E1560

```text
isinstance() takes a class, and {what} is generic class {name} given type arguments: a value of the class is one whatever its arguments are
```

`isinstance()` is given a generic class with type arguments, as `Box[int]`. `{what}` is the argument as written and `{name}` the class. A value is an instance of the class whatever its type arguments are, and the arguments are not kept when the program runs.

```jac
# expect: E1560
obj Box[T] {
    has item: T;
}

with entry {
    b = Box[int](item=1);
    print(isinstance(b, Box[int]));
}
```

**Fix:** name the class alone: `isinstance(b, Box)`.

## E1561

```text
align({n}) on struct {name} is less than the {need} bytes its fields align to: a struct is aligned to what its fields need at least
```

`@align(n)` on a struct asks for less alignment than its fields need. `{n}` is the alignment asked for, `{name}` the struct and `{need}` what its fields need. A struct is aligned to its fields' alignment at least; `align` can only raise it.

```jac
# expect: E1561
import from jaclang.comptime { align }

@align(2)
struct Tight {
    has x: f32 = 0.0;
}

with entry {
    print(Tight().x);
}
```

**Fix:** ask for the fields' alignment or more (`@align(4)`, `@align(16)`), or drop the decorator.

## E1562

```text
{name} changes itself in '{method}', which {iface} requires: a struct as a dyn of an interface is a copy in a box, which nothing changes
```

A struct is held as a `dyn` of an interface whose methods it implements by changing itself. `{name}` is the struct, `{method}` the method and `{iface}` the interface. A `dyn` of a struct holds a copy in a box, and a change made through it would be lost.

```jac
# expect: E1562
obj Growing {
    def grow(k: float) abst;
}

struct Sprout(Growing) {
    has r: float = 1.0;

    def grow(k: float) {
        self.r *= k;
    }
}

with entry {
    g: dyn Growing = Sprout();
}
```

**Fix:** make the method return the new value instead of changing the struct, or make the type an `obj`, which is held by reference.

```jac
obj Growing {
    def grown(k: float) -> float abst;
}

struct Sprout(Growing) {
    has r: float = 1.0;

    def grown(k: float) -> float {
        return self.r * k;
    }
}

with entry {
    g: dyn Growing = Sprout();
    print(g.grown(2.0));
}
```

```output
2.0
```

## E1570

```text
{callee} takes a number type, an int or a float type, and {type} is not one
```

A compile-time function of number types, such as `bits()` or `signed()` from `jaclang.comptime`, is given a type that is not an int or float type. `{callee}` is the function and `{type}` the type given.

```jac
# expect: E1570
import from jaclang.comptime { bits }

with entry {
    print(bits(str));
}
```

**Fix:** give it a number type.

```jac
import from jaclang.comptime { bits, signed }

with entry {
    print(bits(i32), signed(u8));
}
```

```output
32 False
```

## E1572

```text
fast_math() names LLVM's fast-math flags, and {flag} is not one: {flags}
```

`@fast_math` is given a name that is not one of LLVM's fast-math flags. `{flag}` is the name and `{flags}` lists the ones there are. `"fast"`, which other compilers use for all of them, is not a flag: `@fast_math` with no arguments allows them all.

```jac
# expect: E1572
import from jaclang.comptime { fast_math }

@fast_math("fast")
def blend(x: float) -> float {
    return x * 2.0 + 1.0;
}

with entry {
    print(blend(1.0));
}
```

**Fix:** name the flags wanted, or none for all of them.

```jac
import from jaclang.comptime { fast_math }

@fast_math("contract", "reassoc")
def blend(x: float) -> float {
    return x * 2.0 + 1.0;
}

@fast_math
def blend_all(x: float) -> float {
    return x * 2.0 + 1.0;
}

with entry {
    print(blend(1.0), blend_all(1.0));
}
```

```output
3.0 3.0
```

## E1573

```text
an ability runs for a walker at a node or an edge, and '{name}' is neither: its ability never runs
```

An ability (`can ... with ... entry`) is declared in an archetype that is not a walker, a node or an edge. `{name}` is the archetype. An ability runs when a walker is at a node or an edge: a walker's for the place it is at, a node's or an edge's for the walker at it. An `obj`, a `class`, a `struct` or an `enum` is never visited and visits nothing, so an ability in one would never run.

```jac
# expect: E1573
walker Tour {}

obj Ledger {
    can note with Tour entry {
        print("noted");
    }
}
```

**Fix:** declare a method (`def note { ... }`) and call it, or make the archetype a `node` so that walkers can arrive at it. See [Abilities](../../language/abilities.md).

## E1574

```text
`visit ... by` chooses among the nodes of a list, and {type} is not a list of nodes
```

The target of a `visit ... by` is not a list of nodes. `{type}` is the type of what it was given. `visit <nodes> by <chooser>;` shows the chooser each node of a list as an option and visits the ones it picks, so the target is a list whose items are one node type: an edge reference (`[-->]`), a filtered one (`[-->][?:Stop]`) or any `list[N]`. One node offers no choice, and a list of edges is not a list of places to go.

```jac
# expect: E1574 x2
import from stdjac.by { ByChoice, ByChooser }

node Stop {}

obj First(ByChooser) {
    def choose(choice: ByChoice) -> list[int] {
        return [0];
    }
}

walker Tour {
    can at_stop with Stop entry {
        visit here by First();
        visit [edge -->] by First();
    }
}
```

**Fix:** give the nodes to choose among: `visit [-->] by First();`. To go to one node, write `visit here;` with no `by`. See [visit](../../language/visit.md#visit--by).

## E1575

```text
'{consumer}' imports {what}, and no '-->' wire declares it: {fix}
```

A file of the project in another language imports another file of the project, and `archwire.jac` has no `-->` wire that says so. `{consumer}` is the module that writes the import, `{what}` the names it takes and the module it takes them from (or the module, where the source takes it whole), and `{fix}` the wire to write.

An import between two files of a project is a wire, whatever language either is in. A Jac module writes no import of another module of its project: its `++>` wire is the import. A file in another language (Python, JavaScript, TypeScript) keeps its import in its own source, so its wire is a `-->`, which declares what the source writes, and the language's own reading of the file (CPython's, TypeScript's) holds the two to each other. It arises from a `helper.py` that holds `from words import loud` in a project whose `archwire.jac` does not hold `words --> helper { loud }`.

<!-- example: not checked: a wire is one line of a project's archwire.jac -->
```jac
graph import {
    words --> helper { loud }
    marks --> helper;
}
```

The first wire declares `from words import loud`, and the second `import marks`, which takes the module whole. The other direction is [E1147](e11-1.md#e1147): a `-->` wire that the source does not write.

**Fix:** add the wire the message gives, or remove the import. `jac fmt --fix archwire.jac` writes every such wire. An import from outside the project (the standard library, a PyPI or npm package) is no wire and is written in the file alone. See [Wiring modules](../../language/modules-wiring.md).

## E1576

```text
'{module}' is a C module of the project, whose files are its modules: {fix}
```

A wire in `archwire.jac` names, as its provider, a C module whose table the project's `jac.toml`
holds. Such a module's files are modules of the project, and what one gives is wired from it:
the source that defines a function or a variable, the file that holds a type, an enumerator or a
macro. `{module}` is the C module and `{fix}` the wires to write in the wire's place, which Clang's
reading of the module's files decides.

It arises from `shapes ++> main { point_add, shapes_sum }` where `shapes/shapes.c` defines both:

```text
archwire.jac:12:5: error[E1576]: 'shapes' is a C module of the project, whose files are its modules: write `shapes.shapes ++> main { point_add, shapes_sum }` in its place
```

and from `shapes ++> geom;`, a wire that takes one such module into another whole: the `-->` wires
between their files say what one uses of the other, and that wire is deleted.

**Fix:** write the wires the message gives. A C module with a `cmodule.toml` of its own that
`jac.toml` does not hold is a dependency, and is still wired whole. See
[C modules](../../interop/c-modules.md#wiring-c-modules).
