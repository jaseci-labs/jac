# E2089 to E2099: archwire.jac and its edge rules

These codes report a project's `archwire.jac`: a line that is not wiring, a wire or an import that no edge rule admits, a rule that is named twice, a layer that matches no module, and an import that a governed module writes for itself. See [Import wiring](../../language/modules-wiring.md) (`jac docs graph import`).

Each needs a project of several files, so the examples are not checked one by one; each was checked by hand. Unless an entry says otherwise, the project is:

```text
jac.toml       [project] name = "shop"
archwire.jac   the wiring shown in the entry
util.jac       declares now() and later()
main.jac       calls now()
```

and the `archwire.jac` that checks is:

<!-- example: not checked: an archwire is one file of a project -->
```jac
graph layers {
    layer util { util; }
    layer program { main; }
}

graph import {
    edge Util: util --> program;

    util ++> main { now }
}
```

Each entry shows its `graph import` block, under these layers unless it shows its own.

## E2089

```text
archwire.jac declares wiring only; {what} does not belong here
```

`archwire.jac` holds something other than `graph` blocks: an import, a declaration, a statement, a docstring or a comment. `{what}` says what was found. The file is the project's wiring and nothing else, so a reader sees all of it at once.

<!-- example: not checked: an archwire is one file of a project -->
```jac
import os;

graph import {
    edge Util: util --> program;

    util ++> main { now }
}
```

`jac check main.jac` reports `archwire.jac declares wiring only; an import does not belong here`. A `# comment` inside the block is reported as `a comment`.

**Fix:** delete the line. Explain the wiring in the project's documentation, not in the file.

## E2090

```text
'{provider} --> {consumer}' is not permitted by any edge rule: the provider matches the source of {rules}, and none admits the consumer
```

A module imports a package from outside the project that an edge rule names as a source, and no rule admits it into the module's layer. `{provider}` is the package, `{consumer}` the module that writes the import, and `{rules}` names the rules whose source is the package. Once a rule names a package, only the layers some rule lists may import it.

With `util.jac` and `main.jac` each writing `import os;`:

<!-- example: not checked: an archwire is one file of a project -->
```jac
graph import {
    edge Util: util --> program;
    edge Files: os --> util;

    util ++> main { now }
}
```

reports `'os --> main' is not permitted by any edge rule: the provider matches the source of rule 'Files', and none admits the consumer`.

**Fix:** add the layer to the rule's targets, if the import is intended: `edge Files: os --> util | program;`. Otherwise remove the import.

## E2091

```text
'{name}' is not admitted across '{provider} --> {consumer}' by {rules}
```

A wire carries a name that the edge rule admitting it does not list. `{name}` is the name, `{provider}` and `{consumer}` the wire's modules and `{rules}` the rule. A rule with a payload admits only the names in it.

<!-- example: not checked: an archwire is one file of a project -->
```jac
graph import {
    edge Util: util --> program { now }

    util ++> main { now, later }
}
```

With `main.jac` calling `now()` and `later()`, this reports `'later' is not admitted across 'util --> main' by rule 'Util'`.

**Fix:** list the name in the rule (`edge Util: util --> program { now, later }`), or drop the rule's payload to admit every name.

## E2092

```text
edge rule '{name}' is declared more than once
```

Two edge rules have the same name. `{name}` is the name. A rule's name identifies it in other diagnostics, so each is unique.

<!-- example: not checked: an archwire is one file of a project -->
```jac
graph import {
    edge Util: util --> program;
    edge Util: util --> program { now }

    util ++> main { now }
}
```

**Fix:** delete the duplicate, or rename one of the rules.

## E2093

```text
archwire.jac has syntax errors, so the wiring of the modules it governs may be incomplete
```

`archwire.jac` has a syntax error. The error itself is reported beside this one, with its own code. The wires that parsed still apply, so the modules the file governs may report missing names that the broken lines would have wired; this code says why. It is reported once, for the archwire, not once for each module.

<!-- example: not checked: an archwire is one file of a project, and this one does not parse -->
```jac
graph import {
    edge Util: util --> program;

    util ++> main { now }
    util <-- main { later }
}
```

reports E2093 and `E0086 a wire is directed: write 'provider ++> consumer' or 'provider --> consumer'`.

**Fix:** fix the syntax error the other diagnostic reports.

## E2094

```text
the import of '{module}' inside '{scope}' is written in '{consumer}', which takes its imports of the modules under its archwire.jac from wires: {fix}
```

A module governed by an `archwire.jac` imports another governed module inside a function or a class. `{module}` is the module imported, `{scope}` the function or class, `{consumer}` the module that writes it and `{fix}` what to do. Imports between governed modules are wires, and a wire binds names for the whole module. (The same import written at the top of the module is E1144.)

With the `archwire.jac` holding only `edge Util: util --> program;`, and `main.jac`:

<!-- example: not checked: needs the archwire.jac of a project -->
```jac
def total -> int {
    import from util { now }
    return now();
}

with entry {
    print(total());
}
```

reports `the import of 'util' inside 'total' is written in 'main', which takes its imports of the modules under its archwire.jac from wires: jac takes no import inside a function or class; wire it into 'main' instead`.

**Fix:** delete the import and add the wire `util ++> main { now }` to the `graph import` block.

## E2097

```text
'{name}' is not a module under this archwire.jac, so {what} names nothing
```

A wire's consumer, or the package a scoped `graph import <package>` block names, is not a module under this `archwire.jac`. `{name}` is the name and `{what}` what it would have named: `this wire's import into it`, or `this graph import block`. A misspelled module or one in another directory is the usual cause.

<!-- example: not checked: an archwire is one file of a project -->
```jac
graph import {
    edge Util: util --> program;

    util ++> main { now }
    util ++> reports { later }
}
```

reports `'reports' is not a module under this archwire.jac, so this wire's import into it names nothing`.

**Fix:** name a module that exists, by its path from the `archwire.jac`'s directory (`app/view.jac` is `app.view`), or create it.

## E2098

```text
{owner}: {what} matches no module
```

A pattern of a layer, or a pattern or the entry of a space, matches no module. `{owner}` is the layer (`layer 'reports'`) or the space (`space 'api'`), and `{what}` the pattern (`pattern 'reports.*'`) or the entry (`entry 'cli'`). A pattern that matches nothing states nothing, and is usually a misspelling; a space's is found where a program of the space is loaded.

<!-- example: not checked: an archwire is one file of a project -->
```jac
graph layers {
    layer util { util; }
    layer reports { reports.*; }
    layer program { main; }
}
```

reports `layer 'reports': pattern 'reports.*' matches no module`.

**Fix:** correct the pattern, or delete the line of the layer.

## E2099

```text
'{provider} --> {consumer}' crosses from {source} into {target}, and no rule admits it; add `{rule}`
```

A wire goes between two layers and no edge rule admits it. `{provider}` and `{consumer}` are the wire's modules, `{source}` and `{target}` the two layers with no rule between them (`layer 'util'`), and `{rule}` a rule that would admit it. A wire needs a rule at [every level of the layers it crosses](../../language/modules-layers.md#a-rule-at-every-level), and each level without one is reported, with the layers of that level. Wires inside one innermost layer need no rule.

<!-- example: not checked: an archwire is one file of a project -->
```jac
graph import {
    util ++> main { now }
}
```

reports:

```text
archwire.jac:7:14: error[E2099]: 'util --> main' crosses from layer 'util' into layer 'program', and no rule admits it; add `edge Util: util --> program;`
```

**Fix:** add the rule the message gives, at the top of the block.
