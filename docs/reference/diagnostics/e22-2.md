# E2214 to E2225: plugins, libraries, jobs, module names and `pass`

These codes hold a project to how a [plugin](../../apps/plugins.md) is used: named in `jac.toml`
for the abstraction it fills, and never imported. And to how a
[library](../../toolchain/packages.md#jac-packages) is: declared by the package that imports it, one
copy of it in a program, and holding no plugin. What `[packages]` itself may hold is
[E2226 on](e22-3.md). Each needs a project of several files, so the
examples are not checked one by one; each was checked by hand.

## E2214

```text
no plugin '{name}': jac.toml's [packages] declares none of that name, and jac ships none
```

`jac.toml` binds an abstraction to a plugin that the project's `[packages]` table does not declare
and that is not one jac ships. `{name}` is the plugin named.

```toml
[store]
plugin = "postgres"
```

reports, at that line of `jac.toml`:

```text
jac.toml:2:1: error[E2214]: no plugin 'postgres': jac.toml's [packages] declares none of that name, and jac ships none
```

**Fix:** declare the plugin by where its package is, `[packages] postgres = { path = "../postgres" }`,
or name one of jac's own.

A space's `ui` and `bundler` plugins are named the same way and refused the same way:
`[spaces.site.ui]` `plugin = "svelte"`, with no such plugin declared, is this error at that line
([UI plugins and bundlers](../../apps/ui-bindings.md)).

## E2215

```text
plugin '{name}' fills `{fills}`, and jac.toml binds it to `{abstraction}`
```

A plugin is listed for an abstraction other than the one its manifest says it fills. `{name}` is
the plugin, `{fills}` what it fills and `{abstraction}` the table it is listed in.

```toml
[auth]
plugin = "sqlite"
```

reports `plugin 'sqlite' fills `store`, and jac.toml binds it to `auth``.

So does a space's `ui` table that names a bundler: `[spaces.site.ui]` `plugin = "vite"` reports
`plugin 'vite' fills `bundler`, and jac.toml binds it to `ui``.

**Fix:** list the plugin under the abstraction it fills.

## E2216

```text
{kind} '{name}' {problem}
```

A package `jac.toml` declares cannot be used as it is. `{kind}` is `package`, or `plugin` for one
a binding names, `{name}` the package and `{problem}` what is wrong:

- no `jac.toml` is at the path `[packages]` gives;
- its `[project]` says no `kind`, `"library"` or `"plugin"`, or names it otherwise than the
  declaration does;
- a binding names a package that is no plugin;
- a plugin's `[plugin]` table lacks `fills`, lacks `class` for an abstraction picked as a
  program starts, or lacks `interface_ver`, the version of the interface it was written for;
- its `class` is not `<plugin>.<module>.<Class>`, or names a module the package does not have;
- a plugin that fills `ui` or `bundler` has no `[ui]` or `[bundler]` table, which is where such a
  plugin says how it fills it:

  ```text
  jac.toml:8:1: error[E2216]: plugin 'mylib' fills `ui` and says nothing of how: its jac.toml has a [ui] table
  ```

**Fix:** correct the path in `[packages]`, or the package's own `jac.toml`
([Writing a plugin](../../apps/plugins.md#writing-a-plugin),
[Jac packages](../../toolchain/packages.md#jac-packages)).

## E2217

```text
'{name}' declares an abstraction: the abstractions are jac's own, and a project's package is a library or a plugin of one
```

A package a project declares says it is an abstraction: its `jac.toml` has `kind = "abstraction"`
or an `[abstraction]` table. `{name}` is the package. The abstractions are the language's: each
declares itself in jac's own `abstractions/` directory, a plugin fills one of them, and a package
does not add one ([The abstractions](../../apps/plugins.md#the-abstractions)).

**Fix:** remove the table, and say `kind = "library"` or `kind = "plugin"`. What a package offers
of its own is a library's API, which code imports.

## E2218

```text
'{module}' is of the plugin '{plugin}', which fills `{abstraction}`: a plugin is named in jac.toml and never imported
```

A module imports a plugin, by its name or by the path of a plugin the project declares.
`{module}` is the module imported, `{plugin}` the plugin it belongs to and `{abstraction}` what
that plugin fills. A module that imported one would name a mechanism, which is what the language
keeps out of source ([Principles](../../language/principles.md)).

<!-- example: not checked: needs a project, whose build finds jac's plugins -->
```jac
import from sqlite.store { SqliteStore }

def:pub count -> int {
    return 0;
}
```

reports:

```text
svc.jac:1:13: error[E2218]: 'sqlite.store' is of the plugin 'sqlite', which fills `store`: a plugin is named in jac.toml and never imported
```

**Fix:** delete the import, use the abstraction (`root`), and bind the plugin in `jac.toml`.

## E2219

```text
'{module}' is of the library '{library}', which {package} does not declare: a module imports the libraries its own jac.toml declares, so declare it there, in [packages]
```

A module imports a library that is in the program only because another package declares it.
`{module}` is the module imported, `{library}` its library and `{package}` the package the
importing module belongs to: the project, a library or a plugin. What a dependency brought is not
its user's to import: the dependency may stop using it.

Here the project declares `shapes`, and `shapes` declares `units`:

<!-- example: not checked: needs a project and two libraries beside it -->
```jac
import from units.conv { doubled }
import from shapes.area { square }

with entry {
    print(square(doubled(3)));
}
```

reports:

```text
main.jac:1:13: error[E2219]: 'units.conv' is of the library 'units', which the project does not declare: a module imports the libraries its own jac.toml declares, so declare it there, in [packages]
```

**Fix:** declare the library in the importing package's own `jac.toml`, from the same place the
other package declares it:

```toml
[packages]
shapes = { path = "../shapes" }
units = { path = "../units" }
```

## E2220

```text
{kind} '{name}' is {copy} in this program, and {package} asks for {asked}: a program holds one copy of a package
```

A declaration of a package does not hold of the copy the program holds. It names another place
(another directory, another repository or another revision), or it asks for a version that the
copy's does not satisfy. `{kind}` is `library` or `plugin`, `{name}` the package, `{copy}` the
program's copy (where it is, and its version where a version was asked for), `{package}` the
package whose declaration this is and `{asked}` what it asks for. The copy is the one the project
declares, and otherwise the one the first package to declare it does. A class belongs to its
module, so two copies of a library would be two types of every class it has.

```toml
[packages]
shapes = { path = "../shapes" }
units = { path = "../units2" }
```

reports, where `shapes` declares `units = { path = "../units" }`, at that line of the library's
`jac.toml`:

```text
../shapes/jac.toml:6:1: error[E2220]: library 'units' is the directory '../units2' in this program, and the library 'shapes' asks for the directory '../units': a program holds one copy of a package
```

**Fix:** declare it from one place in both.

A version that does not satisfy a requirement is the same error. Where the project declares
`grid = "1.5"` and `eco/jac/grid` holds version 1.4.0:

```text
jac.toml:5:1: error[E2220]: library 'grid' is version 1.4.0, installed in 'eco/jac/grid' in this program, and the project asks for version 1.5 or later, below 2.0.0: a program holds one copy of a package
```

**Fix:** install a version that satisfies every package that asks for it, or ask for the one
there is ([Versions](../../toolchain/packages.md#versions)).

## E2221

```text
{package} {what}: a library and a plugin depend on no plugin, and the project that uses them declares its plugins and binds them
```

A library's or a plugin's `[packages]` declares a plugin, or a library's `jac.toml` binds one
(`[store]`, `[spaces.<space>.store]`). `{package}` is the library or the plugin and `{what}` what
it does. A library is written against the language's abstractions, and which plugin carries one
out is decided by the project that uses the library, for the whole program
([Principles](../../language/principles.md)).

```toml
[project]
name = "shapes"
kind = "library"

[store]
plugin = "sqlite"
```

reports, where the project declares it:

```text
jac.toml:5:1: error[E2221]: the library 'shapes' has a binding, [store], in its jac.toml: a library and a plugin depend on no plugin, and the project that uses them declares its plugins and binds them
```

**Fix:** take the table, or the plugin's line, out of the package's `jac.toml`. A library's own
tests bind what they need in the `jac.toml` of a project that declares the library.

## E2222

```text
'{name}' is a library {package} declares, and '{path}' in its own tree: an import would name either, so rename one
```

A package declares a library, and has a directory or a module of the same name in its own tree.
`{name}` is the name, `{package}` the package and `{path}` what its tree has.

<!-- example: not checked: needs a project with a directory named as its library -->
```jac
import from shapes.area { square }

with entry {
    print(square(3));
}
```

reports, in a project that declares `shapes` and has a directory `shapes/`:

```text
main.jac:1:13: error[E2222]: 'shapes' is a library the project declares, and 'shapes' in its own tree: an import would name either, so rename one
```

**Fix:** rename the directory, or the library.

## E2223

```text
'{name}' is a job, which space '{space}' starts with `flow` and no one calls: it is no endpoint, so what another space or a caller asks of it goes through a function of that space
```

A function marked `@job` is made an endpoint: it is tagged `:pub` or `:protect`, or `archwire.jac`
wires it to a module of another space. `{name}` is the function and `{space}` its space. A job is
started with `flow` by the space that declares it and runs apart from what started it
([Serving a space](../../apps/server.md#jobs-job)); nothing calls it, and its `note` parameter is
the runtime's to give.

Here `archwire.jac` has `front ++> client { halve }`, and `client` is of another space:

<!-- example: not checked: needs a project of two spaces and the wire between them -->
```jac
import from stdjac.server { JobNote, job }

@job
def halve(n: int, note: JobNote) -> int {
    return n // 2;
}
```

reports:

```text
front.jac:3:1: error[E2223]: 'halve' is a job, which space 'api' starts with `flow` and no one calls: it is no endpoint, so what another space or a caller asks of it goes through a function of that space
```

**Fix:** wire a function of the job's own space instead, which starts the job and gives what the
other space wants of it:

<!-- example: not checked: continues the project above -->
```jac
def halved(n: int) -> int {
    j = flow halve(n);
    return wait j;
}
```

## E2224

```text
'{first}' and '{second}' are both the module '{name}': a file of a project is named by its path without its extension, so rename one
```

Two files of a project would be one module. A file under an `archwire.jac` is a module named by its
path from there without its extension, whatever language it is in, so `lib/util.py` and
`lib/util.ts` are both `lib.util`, and a wire that names `lib.util` would name either. `{first}`
and `{second}` are the two files and `{name}` the module.

What is one module by design is not reported: a Jac module's files for its targets
(`host.jac`, `host.windows.jac`) and its `impl` annexes.

**Fix:** rename one of the two files. See
[Wiring modules](../../language/modules-wiring.md#declared-wires---).

## E2225

```text
Jac has no `pass` statement: leave the block empty, `{{}}`
```

A statement is the name `pass` alone, and nothing binds that name: Python's `pass`, which Jac does
not have. A block with nothing to do is empty. `pass` is no keyword, so a program may still name a
variable `pass` (`pass = 3;`), and then `pass;` is a statement of that variable, as any name is.

```jac
# expect: E2225
def todo {
    pass;
}

with entry {
    todo();
}
```

**Fix:** leave the block empty: `def todo {}`.
