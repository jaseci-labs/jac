# E0120 to E0167: parameters, assignments, patterns, spellings, layers and connects

These codes are reported for constructs that parse but are not written in the one form the
language accepts: a parameter list out of order, an assignment to something that cannot be
assigned, a pattern in a spelling Python allows and Jac does not. In a template, `{name}` is filled
in when the error is reported.

## E0120

```text
at least one parameter must precede /
```

The `/` marker in a parameter list makes the parameters before it positional-only. Here it is the
first thing in the list, so it marks nothing.

```jac
# expect: E0120
def f(/, a: int) -> int {
    return a;
}
```

**Fix:** put the positional-only parameters before the `/`, or remove it. See
[Functions](../../language/functions.md).

```jac
def f(a: int, /, b: int) -> int {
    return a + b;
}

with entry {
    print(f(1, b=2));
}
```

## E0121

```text
the {kind} parameter '{name}' cannot have a default value
```

A `*args` or `**kwargs` parameter is given `= value`. `{kind}` is `var-positional` for `*args` and
`var-keyword` for `**kwargs`; `{name}` is the parameter's name. These parameters collect whatever
arguments are left over, and are empty when there are none.

```jac
# expect: E0121
def f(*args: int = 1) -> int {
    return len(args);
}
```

**Fix:** remove the default: `def f(*args: int) -> int`. See
[Functions](../../language/functions.md).

## E0122

```text
named parameters must follow bare *
```

A bare `*` in a parameter list makes the parameters after it keyword-only. Here nothing follows it,
or what follows is `**kwargs`.

```jac
# expect: E0122
def f(a: int, *) -> int {
    return a;
}
```

**Fix:** write at least one named parameter after the `*`, or remove it. See
[Functions](../../language/functions.md).

```jac
def f(a: int, *, b: int) -> int {
    return a + b;
}

with entry {
    print(f(1, b=2));
}
```

## E0130

```text
a starred expression cannot be used here
```

`*value` is written where a single value is needed. A starred expression spreads its items into a
call's arguments or into a list, tuple or set display; on its own it is not a value.

```jac
# expect: E0130
with entry {
    xs = [1, 2];
    ys = *xs;
}
```

**Fix:** spread into a display: `ys = [*xs];` copies the list, and `ys = [*xs, 3];` extends it. See
[Collections](../../language/collections.md).

```jac
with entry {
    xs = [1, 2];
    ys = [*xs, 3];
    print(ys);
}
```

## E0140

```text
a comptime binding names one variable and gives its value
```

A `comptime` statement in a function body is not a plain `name = value`: it has no value, it uses
an augmented operator (`comptime n += 1;`), or it assigns to several targets.

```jac
# expect: E0140
with entry {
    comptime n: int;
    print(1);
}
```

**Fix:** bind one name and give its value in the same statement. See
[Compile time](../../language/compile-time.md).

```jac
with entry {
    comptime n = 4;
    print(n);
}
```

## E0141

```text
an {kind} assignment takes no annotation
```

A type annotation is written on an assignment that cannot declare a variable. `{kind}` is
`augmented` for `x: int += 1` and `unpacking` for `(a, b): tuple[int, int] = ...`.

```jac
# expect: E0141
with entry {
    x = 1;
    x: int += 1;
}
```

**Fix:** annotate the variable where it is first assigned, and leave the annotation off the
augmented or unpacking assignment. See [Variables](../../language/variables.md).

```jac
with entry {
    x: int = 1;
    x += 1;
    print(x);
}
```

## E0142

```text
cannot assign to this
```

The left side of an assignment is not something that can hold a value: a literal, a call, an
arithmetic expression. An assignment's target is a name, an attribute (`a.b`), an item (`a[i]`) or
an unpacking of those.

```jac
# expect: E0142
with entry {
    x = 1;
    x + 1 = 2;
}
```

**Fix:** assign to a name, an attribute or an item. If a comparison was meant, write `==`. See
[Variables](../../language/variables.md).

## E0143

```text
f-string: invalid conversion character '{char}'
```

A replacement field in an f-string has `!` followed by `{char}`, which is not a conversion. The
conversions are `!r`, `!s` and `!a`, in lower case.

```jac
# expect: E0143
with entry {
    x = 1;
    print(f"{x!S}");
}
```

**Fix:** use `!r`, `!s` or `!a`, or remove the conversion. See
[Strings](../../language/strings.md).

```jac
with entry {
    x = 1;
    print(f"{x!s}");
}
```

## E0150

```text
`raise from` needs an exception to raise
```

A `raise` statement has a `from` clause and no exception before it. `from` names the cause of the
exception being raised, so there has to be one.

```jac
# expect: E0150
with entry {
    raise from ValueError("x");
}
```

**Fix:** name the exception to raise before `from`, or write `raise;` alone to raise the current
exception again. See [Exceptions](../../language/exceptions.md).

```jac
with entry {
    try {
        raise ValueError("x");
    } except ValueError as e {
        raise RuntimeError("y") from e;
    }
}
```

## E0151

```text
adjacent literals cannot mix bytes and strings
```

String literals written side by side are joined into one. Here some are `str` literals and some
are `bytes` literals (`b"..."`), which have no common type.

```jac
# expect: E0151
with entry {
    x = "a" b"b";
}
```

**Fix:** give every literal the same kind: `"a" "b"` or `b"a" b"b"`. See
[Strings](../../language/strings.md).

```jac
with entry {
    x = b"a" b"b";
    print(x);
}
```

## E0152

```text
a switch has one default
```

A `switch` statement has two `default:` clauses. The error points at the second.

```jac
# expect: E0152
with entry {
    switch 1 {
        default:
            print("a");
        default:
            print("b");
    }
}
```

**Fix:** keep one `default:` and turn the other into a `case`. See
[Control flow](../../language/control-flow.md).

```jac
with entry {
    switch 1 {
        case 1:
            print("a");
        default:
            print("b");
    }
}
```

## E0153

```text
a pattern value is a literal or a dotted name
```

A `case` pattern compares against something that is computed: a negated name (`case -x:`), an
f-string, or another expression. A value pattern is a number, a string, `True`, `False`, `None`,
or a dotted name such as `Color.RED`; a bare name is a capture, not a value.

```jac
# expect: E0153
with entry {
    x = 1;
    match 3 {
        case -x:
            print("neg");
    }
}
```

**Fix:** capture the value and compare it in a guard. See
[Pattern matching](../../language/pattern-matching.md).

```jac
with entry {
    x = 1;
    match -1 {
        case n if n == -x:
            print("neg");
    }
}
```

## E0154

```text
a sequence pattern has one starred name
```

A sequence pattern has two starred names, as in `case [*a, *b]`. A starred name takes the items the
other names leave, and with two of them the split is not determined.

```jac
# expect: E0154
with entry {
    match [1, 2, 3] {
        case [*a, *b]:
            print(a, b);
    }
}
```

**Fix:** keep one starred name. See [Pattern matching](../../language/pattern-matching.md).

```jac
with entry {
    match [1, 2, 3] {
        case [first, *rest]:
            print(first, rest);
    }
}
```

## E0155

```text
a sequence pattern is written in brackets: `case [a, b]`
```

A sequence pattern is written in parentheses, as Python also allows: `case (a, b):`. Jac has one
spelling for it, with brackets, at the top of a pattern and nested inside one. Parentheses around
one pattern are not a sequence: `case (a):` groups `a`, as in Python. `case ():` and `case (*a):`
are sequences, and refused the same way.

```jac
# expect: E0155
with entry {
    match [1, 2] {
        case (a, b):
            print(a + b);
    }
}
```

**Fix:** write the pattern in brackets. It matches lists and tuples alike. See
[Pattern matching](../../language/pattern-matching.md).

```jac
with entry {
    match [1, 2] {
        case [a, b]:
            print(a + b);
    }
}
```

## E0156

```text
a semantic string is given with '=': `sem x = "..."`
```

A `sem` declaration uses `is` between its target and its string, the older Jac spelling.

```jac
# expect: E0156
def f -> int {
    return 1;
}

sem f is "Returns one.";
```

**Fix:** write `=`. See [by and sem](../../language/by-and-sem.md).

```jac
def f -> int {
    return 1;
}

sem f = "Returns one.";
```

## E0157

```text
'{name}' needs no backtick here
```

A backtick escapes the keyword `{name}` in a place that takes any word as it stands: an attribute
after `.`, a part of a module path, or `init`, `postinit`, `entry` or `exit` as the target of an
`impl` or `sem`. The escape is needed only where a name is bound, such as a field's or a
parameter's declaration.

```jac
# expect: E0157
obj Box {
    has `type: int = 0;
}

with entry {
    print(Box().`type);
}
```

**Fix:** remove the backtick where the error points. See
[Lexical structure](../../language/lexical-structure.md).

```jac
obj Box {
    has `type: int = 0;
}

with entry {
    print(Box().type);
}
```

## E0158

```text
a function's modifiers come in the order `comptime override static|class async def`
```

The modifiers before `def` or `can` are in another order: `async` is written before `override`,
`static` or `class`. Each modifier is optional, and those present keep this order.

```jac
# expect: E0158
obj Job {
    async static def make -> int;
}
```

**Fix:** put `async` last, directly before `def`. See [Methods](../../language/methods.md).

```jac
obj Job {
    static async def make -> int {
        return 1;
    }
}
```

## E0159

```text
a function returns its value with `return ...;`
```

A body's last statement is an expression with no `;` after it, in a function that returns a value.
Being last does not make an expression the function's value: only `return` gives one. The same
holds for the last expression of a lambda's body of several statements.

```jac
# expect: E0159
def ten -> int {
    5 + 5
}

with entry {
    print(ten());
}
```

**Fix:** return it. `jac fmt --fix` writes the `return`. See [Functions](../../language/functions.md).

```jac
def ten -> int {
    return 5 + 5;
}

with entry {
    print(ten());
}
```

```output
10
```

## E0160

```text
a lambda whose one statement only computes a value gives that value, with no ';'
```

A lambda's body is one expression statement, with its `;`, and the expression does nothing but
compute a value: a name, a literal, an operator on them. As a statement it would drop that value,
and the lambda would give nothing. A lambda of one expression gives that expression as its value,
and it is written as the expression alone. A statement that does something, such as a call, may
end in `;`: `lambda (m: str) { print(m); }` prints and gives nothing.

```jac
# expect: E0160
with entry {
    triple = lambda (x: int) { x * 3; };
    print(triple(4));
}
```

**Fix:** drop the `;`. `jac fmt --fix` does. See [Functions](../../language/functions.md).

```jac
with entry {
    triple = lambda (x: int) { x * 3 };
    print(triple(4));
}
```

```output
12
```

## E0161

```text
a yield is parenthesized only where it is part of a larger expression
```

A `yield` is in parentheses where it needs none: as a statement, as the value of an assignment, or
as an f-string's field. Parentheses are for a yield inside a larger expression, where Python
requires them: `(yield x) + 1`, `f((yield x))`.

```jac
# expect: E0161 x2
def steps -> Iterator[int] {
    got: any = (yield 1);
    (yield 2);
    print(got);
}

with entry {
    print(list(steps()));
}
```

**Fix:** drop the parentheses. `jac fmt --fix` does. See [Generators](../../language/generators.md).

```jac
def steps -> Iterator[int] {
    got: any = yield 1;
    yield 2;
    print(got);
}

with entry {
    print(list(steps()));
}
```

```output
None
[1, 2]
```

## E0162

```text
a string's prefix is written in lower case, 'r' before 'b': '{prefix}'
```

A string's prefix has an upper-case letter, or `b` before `r`. `{prefix}` is the prefix to
write: `r`, `b` or `rb`.

```jac
# expect: E0162 x2
with entry {
    print(R"C:\new", br"\d+");
}
```

**Fix:** write the prefix `{prefix}` names. `jac fmt --fix` does. See [Strings](../../language/strings.md).

```jac
with entry {
    print(r"C:\new", rb"\d+");
}
```

```output
C:\new b'\\d+'
```

## E0163

```text
a number's base prefix and exponent are written in lower case: '{number}'
```

A number has an upper-case base prefix (`0X`, `0B`, `0O`) or an upper-case exponent (`1E3`).
`{number}` is the number as it is to be written. Hexadecimal digits may be in either case.

```jac
# expect: E0163 x2
with entry {
    print(0XFF, 1E3);
}
```

**Fix:** write the number `{number}` names. `jac fmt --fix` does. See [Numbers](../../language/numbers.md).

```jac
with entry {
    print(0xFF, 1e3);
}
```

```output
255 1000.0
```

## E0164

```text
expected a layer in a graph layers block, found '{found}'
```

A `graph layers` block holds something that is not a layer. `{found}` is what is there. The block holds `layer <name> { ... }` declarations, each with an optional docstring before it, and nothing else. See [Layers](../../language/modules-layers.md).

<!-- example: not checked: a graph layers block is valid only in a file named archwire.jac -->
```jac
graph layers {
    7;
}
```

reports:

```text
archwire.jac:2:5: error[E0164]: expected a layer in a graph layers block, found '7'
```

**Fix:** declare a layer there, or delete the line.

## E0165

```text
expected a layer or module patterns in a layer, found '{found}'
```

A layer holds something that is neither a layer nor a line of module patterns. `{found}` is what is there. A layer holds layers and lines such as `core.clock | app.*;`.

<!-- example: not checked: a graph layers block is valid only in a file named archwire.jac -->
```jac
graph layers {
    layer base { ?; }
}
```

reports:

```text
archwire.jac:2:18: error[E0165]: expected a layer or module patterns in a layer, found '?'
```

**Fix:** name the layer's modules, each line ended with `;`.

## E0166

```text
a docstring here describes {what}, and '{found}' follows it
```

A docstring in `archwire.jac` is not followed by what it could describe. `{what}` is what a docstring describes at that place: a layer in a `graph layers` block or a layer, an edge rule in a `graph import` block, a space or an app in a `graph spaces` block. `{found}` is what follows it instead. A wire, an `auth` line and a crossing's protocol take no docstring. See [Docstrings](../../language/modules-wiring.md#docstrings).

<!-- example: not checked: a graph import block is valid only in a file named archwire.jac -->
```jac
graph import {
    """Describes a wire."""
    util ++> main { now }
}
```

reports:

```text
archwire.jac:3:5: error[E0166]: a docstring here describes an edge rule, and 'util' follows it
```

**Fix:** move the docstring to the rule it is about, or delete it.

## E0167

```text
a typed connect is written `{opening}{edge}{closing}`
```

A connect names its edge's type between the colons of a typed operator, and this one is written
with the untyped operator around the colons: `a ++>:Knows:++> b`. `{opening}` and `{closing}` are
the typed operator's halves for the direction written (`+>:` and `:+>` for `++>`, `<+:` and `:<+`
for `<++`, `<+:` and `:+>` for `<++>`), and `{edge}` is what was written between the colons. The
statement is read as the typed connect it names, so nothing after it is reported for it.

```jac
# expect: E0167
node Person {
    has name: str;
}

edge Knows: Person --> Person {}

with entry {
    a = Person(name="ann");
    b = Person(name="bob");
    a ++>:Knows:++> b;
}
```

reports:

```text
a typed connect is written `+>:Knows:+>`
```

**Fix:** write the typed operator: `a +>:Knows:+> b`. `jac fmt --fix` does. See
[Connecting](../../language/connecting.md) (`jac docs connect`).
