# E2119 to E2200: statements, async functions, overrides, walks, compile-time names, sems and initialization order

These codes report a statement written where it means nothing (a bare `raise` outside an `except`, `super` outside a method), a step of zero, a class that extends a Python class and something else, what an `async` function may contain, and what an override must keep of the method it overrides. See [Exceptions](../../language/exceptions.md), [Async](../../language/async.md) (`jac docs async`) and [Inheritance](../../language/inheritance.md).

## E2119

```text
range() arg 3 must not be zero
```

`range()` is given a step of literal `0`. A step of zero never reaches the end; Python raises `ValueError` for it when the program runs, and here the literal is refused.

```jac
# expect: E2119
with entry {
    for i in range(0, 10, 0) {
        print(i);
    }
}
```

**Fix:** give a step other than zero: `range(0, 10, 2)`, or `range(10, 0, -1)` to count down.

## E2125

```text
a bare raise belongs in an except clause
```

A bare `raise`, with no exception after it, is written outside an `except` clause. A bare `raise` raises again the exception being handled, so it means something only while one is.

```jac
# expect: E2125
def fail {
    raise;
}

with entry {
    fail();
}
```

**Fix:** raise an exception (`raise ValueError("bad input");`), or move the bare `raise` into the `except` clause it re-raises from.

```jac
def fail {
    try {
        print(1 // 0);
    } except ZeroDivisionError {
        print("logged");
        raise;
    }
}

with entry {
    try {
        fail();
    } except ZeroDivisionError {
        print("caught");
    }
}
```

```output
logged
caught
```

## E2127

```text
super belongs in a method
```

`super` is used outside a method. `super` reaches the base class's version of a method, so it needs the class the method belongs to.

```jac
# expect: E2127
def show {
    super.init();
}

with entry {
    show();
}
```

**Fix:** use `super` in a method of a class that has a base.

```jac
obj Base {
    def name -> str {
        return "base";
    }
}

obj Sub(Base) {
    override def name -> str {
        return "sub of " + super.name();
    }
}

with entry {
    print(Sub().name());
}
```

```output
sub of base
```

## E2191

```text
{name} derives from a Python class and so from nothing else
```

An archetype derives from a Python class and from something else as well. `{name}` is the archetype. A Jac class that extends a Python class is laid out as that Python class's subclass, which cannot also hold a Jac base's layout. See [Python](../../interop/python.md).

```jac
# expect: E2191
import from ast { NodeVisitor }

obj Named {
    has name: str = "";
}

obj Counter(NodeVisitor, Named) {
    has hits: int = 0;
}

with entry {
    print(1);
}
```

**Fix:** derive from the Python class alone, and write the other base's fields in the class itself.

```jac
import from ast { NodeVisitor }

obj Counter(NodeVisitor) {
    has name: str = "",
        hits: int = 0;
}

with entry {
    print(1);
}
```

## E2192

```text
'{what}' outside an async function
```

`async with` or `async for` (a statement, or a clause of a comprehension) is written in a function that is not `async`. `{what}` is the construct. Each step of it awaits, and only an `async` function can await.

```jac
# expect: E2192
obj Quiet {
    async def __aenter__ -> Quiet {
        return self;
    }

    async def __aexit__(t: any, e: any, tb: any) -> bool {
        return False;
    }
}

def plain {
    async with Quiet() {
        print("in");
    }
}

with entry {
    plain();
}
```

**Fix:** declare the function `async`: `async def plain { ... }`, or use a plain `with` on a context manager that is not asynchronous.

## E2193

```text
'return' with a value in an async generator
```

An async generator, an `async` function that yields, returns a value. As in Python, an async generator ends with a bare `return` or by reaching its end; what it produces, it yields.

```jac
# expect: E2193
async def items -> AsyncIterator[int] {
    yield 1;
    return 2;
}

with entry {
    print(1);
}
```

**Fix:** yield the last value and end with a bare `return;`, or none.

```jac
async def items -> AsyncIterator[int] {
    yield 1;
    yield 2;
}

with entry {
    print(1);
}
```

```output
1
```

## E2194

```text
yield in an async function needs it declared to return AsyncIterator[T]
```

An `async` function yields without declaring its return type as `AsyncIterator[T]`. The type of what an async generator yields is part of its signature, and is not inferred.

```jac
# expect: E2194
async def items {
    yield 1;
}

with entry {
    print(1);
}
```

**Fix:** declare it: `async def items -> AsyncIterator[int] { yield 1; }`. See [Generators](../../language/generators.md).

## E2195

```text
{name} has {got} type parameters and the method it overrides, {base}, {want}
```

A method that overrides another has a different number of type parameters. `{name}` is the overriding method, `{got}` its count, `{base}` the method it overrides and `{want}` that method's count. A call through the base class can give type arguments, so the override takes the same ones.

```jac
# expect: E2195
obj Base {
    def wrap[T](x: T) -> list[T] {
        return [x];
    }
}

obj Sub(Base) {
    override def wrap(x: int) -> list[int] {
        return [x, x];
    }
}

with entry {
    print(1);
}
```

**Fix:** declare the same type parameters as the base method.

```jac
obj Base {
    def wrap[T](x: T) -> list[T] {
        return [x];
    }
}

obj Sub(Base) {
    override def wrap[T](x: T) -> list[T] {
        return [x, x];
    }
}

with entry {
    b: Base = Sub();
    print(b.wrap(1));
}
```

```output
[1, 1]
```

## E2196

```text
a walker's `with exit` ability runs when its walk is over: nothing it visits would be visited
```

A `visit` is written in a walker's own `with exit` ability, the one with no trigger type. That ability runs once, after the walker's queue is empty and every exit ability at a node has run; the walk does not start again, so what it queued would never be arrived at.

```jac
# expect: E2196
node Dir {}

walker Wide {
    can finish with exit {
        visit [-->];
    }
}

with entry {
    Dir() spawn Wide();
}
```

**Fix:** visit from an ability at a node or an edge, where the walk is still going: an entry ability (`can at_dir with Dir entry`), or an exit ability there (`can leave with Dir exit`), after which the walker arrives at what it queued. See [visit](../../language/visit.md).

## E2197

```text
'{name}' is a compile-time name: its value is fixed as the program compiles, so code that runs cannot assign it
```

Code that runs assigns a name declared `comptime`: a compile-time global, a compile-time local or a `comptime` parameter. `{name}` is the name. Every use of such a name is replaced by its value as the program compiles, so there is nothing for an assignment to change. An augmented assignment (`N += 1`), a walrus (`N := 4`) and a loop's target are refused the same way.

```jac
# expect: E2197
comptime N = 3;

with entry {
    N = 4;
    print(N);
}
```

**Fix:** assign a variable of the program instead, started from the compile-time value: `n = N; n = 4;`. Inside a function, an annotated assignment declares a local of that name over a compile-time global: `N: int = 4;`. See [Compile time](../../language/compile-time.md).

## E2198

```text
a sem is written in the module that declares what it describes, and '{target}' is declared in {module}
```

A `sem` names a function, a parameter or a field that another module declares. `{target}` is the path the `sem` names and `{module}` the module that declares it. A `sem` is read where its target is declared, by a `by` call and by compile-time reflection (`fields(T)`, `params(f)`), so one written in another module would describe nothing.

```jac
# expect: E2198
import from os { getcwd }

sem getcwd = "The directory the program runs in.";

with entry {
    print(len(getcwd()) > 0);
}
```

**Fix:** write the `sem` in the module that declares its target, beside the declaration. See [by and sem](../../language/by-and-sem.md).

## E2199

```text
{name} overrides {base} with another signature: {how}
```

A method that overrides a base class's method does not take what that method takes, or does not return what it returns. `{name}` is the override, `{base}` the method it replaces and `{how}` the first difference: a parameter of another type, a parameter left out, an added parameter with no default, or another return type. A call through the base (`items: list[Base]`, then `b.show(1)`) is checked against the base's method and runs the override, so the override takes the same parameters, each of the same type.

```jac
# expect: E2199
obj Base {
    def show(x: int) -> str {
        return f"base {x}";
    }
}

obj Wide(Base) {
    override def show(x: str) -> int {
        return len(x);
    }
}
```

**Fix:** give the override the base method's parameters and return type: `override def show(x: int) -> str`. It may add parameters after them when each has a default, and may return a subclass of what the base returns. A method that does something else is another method: give it its own name. See [Inheritance](../../language/inheritance.md).

## E2200

```text
'{name}' is read here before it has its value: {where} initializes it, after this
```

The initializer of a global or of a static field reads a global or static field that is declared
below it. A module's globals and static fields are initialized in the order they are written, so
the one read has no value yet. `{name}` is the one read, and `{where}` where it is declared.

```jac
# expect: E2200
glob first: int = second + 1;
glob second: int = 2;
```

**Fix:** declare what is read first.

```jac
glob second: int = 2;
glob first: int = second + 1;

with entry {
    print(first);
}
```

```output
3
```
