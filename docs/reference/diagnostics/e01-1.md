# E0100 to E0117: tokens, compile-time values and archwire blocks

These codes are reported for text that cannot be split into tokens (an open string, an open
comment, a stray character, a bad escape), for compile-time code that cannot be evaluated or whose
assertion fails, and for malformed lines in `archwire.jac`. In a template, `{name}` is filled in
when the error is reported, and `{{` and `}}` stand for the braces `{` and `}`.

The codes about `archwire.jac` (E0113 to E0117) are reported on that file, always together with
E2093, which says once that the file has syntax errors. Their entries show the refused line instead
of a whole program; [archwire](../../apps/archwire.md) (`jac docs archwire`) describes the file.

## E0100

```text
unterminated string
```

A string literal has no closing quote. A string in `"` or `'` ends on the line it starts on; a
string in triple quotes ends at the next triple quote, and the file ended first.

```jac
# expect: E0100
with entry {
    s = "one
    ;
}
```

**Fix:** close the string on its line: `s = "one";`. For text of several lines, use triple quotes
(`"""one` ... `two"""`) or `\n` inside the string. See [Strings](../../language/strings.md).

## E0101

```text
unterminated block comment
```

A block comment opened with `#*` has no closing `*#` before the end of the file.

```jac
# expect: E0101
with entry {
    print(1);
}
#* a comment that never ends
```

**Fix:** close the comment with `*#`, or use `#` for a comment that ends with its line. See
[Lexical structure](../../language/lexical-structure.md).

```jac
with entry {
    print(1);
}
#* a block comment *#
```

## E0102

```text
unterminated f-string
```

An f-string has no closing quote: its line ended (or, for a triple-quoted one, the file ended)
inside its text, inside a `{...}` replacement field or inside a format spec. It arises for a line
such as `print(f"total {x});`, where the quote before `)` is missing.

**Fix:** close the f-string with the quote it opened with, and close every `{` in it with `}`:
`print(f"total {x}");`. See [Strings](../../language/strings.md).

## E0104

```text
unexpected end of file in JSX
```

The file ends inside a JSX tag or between an element's opening and closing tags. It arises when a
file's last line is, for example, `glob page = <div>hello`.

**Fix:** close the tag with `>` or `/>`, and close every element that was opened:
`<div>hello</div>`. See [Pages](../../apps/pages.md).

## E0105

```text
unexpected character '{ch}'
```

`{ch}` is a character that no Jac token starts with, such as `$`, or a backtick that is not
followed by a word.

```jac
# expect: E0105
with entry {
    total = 1 $;
}
```

**Fix:** remove the character. If it was meant as text, put it inside a string. See
[Lexical structure](../../language/lexical-structure.md).

The reference design's type filter `` [-->](`?Person) `` is this code too, for its backtick, beside
[E0048](e00-1.md#e0048) for the parenthesized filter:

```jac
# expect: E0048, E0105
node Person {
    has name: str;
}

with entry {
    root ++> Person(name="ann");
    print([p.name for p in [root -->](`?Person)]);
}
```

**Fix:** write the filter in brackets: `[root -->][?:Person]`. See
[Edge references](../../language/edge-references.md) (`jac docs edge-references`).

## E0106

```text
unexpected character in a JSX tag: '{ch}'
```

`{ch}` is a character that cannot stand between a JSX tag's `<` and `>`, where only the tag's name,
its attributes and the closing `/` are written.

```jac
# expect: E0106
glob page = <div %></div>;
```

**Fix:** remove the character, or write it as an attribute's value: a string
(`<div title="50%">`) or an expression in braces. JSX belongs in the modules of a JS space; see
[Pages](../../apps/pages.md).

## E0108

```text
cannot evaluate at compile time: {reason}
```

A compile-time value (a `comptime` binding, a `comptime if`, `for` or `assert`, a compile-time
argument) uses something the compiler does not evaluate. `{reason}` says what: a construct
(`jac does not evaluate a list comprehension`), a call of a function that is not `comptime`
(`jac cannot call 'lanes'`), or an operation that fails
(`integer division or modulo by zero`).

```jac
# expect: E0108
comptime SQUARES: list[int] = [i * i for i in [1, 2, 3]];

with entry {
    print(SQUARES);
}
```

**Fix:** write the value with constructs the compiler evaluates (literals, arithmetic, other
`comptime` values, calls of `comptime def` functions), or compute it when the program runs by
making it a `glob`. See [Compile time](../../language/compile-time.md).

```jac
comptime SQUARES = [1, 4, 9];

with entry {
    print(SQUARES);
}
```

## E0109

```text
comptime assertion failed{detail}
```

The condition of a `comptime assert` is false when the compiler evaluates it. `{detail}` is `: `
and the assertion's message when it has one, and empty otherwise.

```jac
# expect: E0109
comptime WIDTH = 8;
comptime assert WIDTH == 16, "this build needs 16 lanes";
```

**Fix:** change the values so that the condition holds, or correct the condition. The assertion
states what the code after it relies on. See [Compile time](../../language/compile-time.md).

```jac
comptime WIDTH = 16;
comptime assert WIDTH == 16, "this build needs 16 lanes";

with entry {
    print(WIDTH);
}
```

## E0110

```text
unsupported escape sequence '\N{{...}}'
```

A string names a character with Python's `\N{NAME}` escape. Jac strings have no table of character
names.

```jac
# expect: E0110
with entry {
    print("\N{BULLET}");
}
```

**Fix:** write the character itself, or its code point with `\u` and four hex digits (`\U` and
eight for code points above `FFFF`). See [Strings](../../language/strings.md).

```jac
with entry {
    print("•");
}
```

## E0111

```text
`{keyword}` requires the `for <x> in <collection>` form
```

A `flow for` or a `comptime for` is written as a counted loop
(`for i = 0 while i < n with i += 1`). `{keyword}` is `flow for` or `comptime for`. Both loop over
a collection only.

```jac
# expect: E0111
with entry {
    flow for i = 0 while i < 3 with i += 1 {
        print(i);
    }
}
```

**Fix:** loop over a range or a collection. See [Control flow](../../language/control-flow.md).

```jac
with entry {
    flow for i in range(3) {
        print(i);
    }
}
```

## E0112

```text
'\{escape}' needs {count} hex digits
```

A hex escape in a string is too short. `{escape}` is `x`, `u` or `U` and `{count}` the number of
hex digits it takes: 2 for `\x`, 4 for `\u`, 8 for `\U`.

```jac
# expect: E0112
with entry {
    print("\x4");
}
```

**Fix:** write all the digits, with leading zeros where needed: `"\x04"`. For a backslash that is
not an escape, write `\\` or use a raw string (`r"\x4"`). See
[Strings](../../language/strings.md).

## E0113

```text
an edge rule only checks imports; write 'source --> target'
```

An edge rule in `archwire.jac` uses the injecting arrow, as in `edge Util: util ++> main;`. A rule
says which modules may import from which; it delivers nothing, so it is written with `-->`.

**Fix:** write the rule with `-->`, `edge Util: util --> main;`, and deliver names with a wire,
`util ++> main { now }`. See [archwire](../../apps/archwire.md).

## E0114

```text
a grouped wire lists at least one consumer
```

A wire's bracketed group of consumers is empty, as in `util ++> []`.

**Fix:** list the consumers in the brackets, each with its payload,
`util ++> [main { now }, tools { now }]`, or remove the wire. See
[archwire](../../apps/archwire.md).

## E0115

```text
expected a space or an app in a graph spaces block, found '{found}'
```

A `graph spaces` block holds `space` declarations and `app` declarations. `{found}` is a token
that starts neither. It arises, for example, when a module is listed directly in the block
(`main;`) instead of inside a space, and for a line that names a plugin (`auth my_auth.sso;`):
which plugin carries out an abstraction is said in `jac.toml`, not in the archwire
([Plugins](../../apps/plugins.md)).

**Fix:** put module patterns inside a space, `space api: native { entry main; }`, and keep only
spaces and apps at the block's top level. See [archwire](../../apps/archwire.md).

## E0116

```text
expected entry or module patterns in a space, found '{found}'
```

A space's braces hold `entry module;` and module patterns (`util;`, `pkg.* | tools;`). `{found}`
is a token that starts neither, such as the string in `space api: native { "util"; }`.

**Fix:** write module patterns as bare dotted names, and move anything else out of the space. See
[archwire](../../apps/archwire.md).

## E0117

```text
expected run, serve or '<space> has' in an app, found '{found}'
```

An app's braces hold `run` and `serve` lines, each listing spaces, and grant lines
(`<space> has <grant>;`). `{found}` is a token that starts none of them. It arises, for example,
for `app cli { entry api; }`: `entry` belongs to a space.

**Fix:** name the spaces the app runs or serves: `app cli { run api; }`. See
[archwire](../../apps/archwire.md).
