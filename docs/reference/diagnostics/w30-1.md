# W3001 to W3013: one spelling for each form

Where Jac had two spellings of one thing, jac accepts one and refuses the other under the reference design's lint code. Most of these codes are always reported, and `jac fmt --fix` rewrites each of those into the accepted spelling, all but an impl that renames its parameters (W3010). W3002, W3003 and W3008 are lint rules: they are reported where `jac.toml`'s `[check.lint]` selects them, as the groups `"style"` and `"clean"` do (and `"clean"` is what a project that names no rules selects), and `jac fmt --fix` rewrites them there. See [fmt](../../toolchain/fmt.md) and [Lint](../../toolchain/lint.md) (`jac docs lint`).

## W3001

```text
a static method is declared `static def`; @staticmethod is not Jac
```

A method is marked `@staticmethod`. Jac writes a static method with the word `static` before `def`, and a decorator here is a compile-time call, which `staticmethod` is not.

```jac
# expect: W3001
obj Counter {
    @staticmethod
    def zero -> int {
        return 0;
    }
}

with entry {
    print(Counter.zero());
}
```

**Fix:** write `static def`. `jac fmt --fix` rewrites it.

```jac
obj Counter {
    static def zero -> int {
        return 0;
    }
}

with entry {
    print(Counter.zero());
}
```

```output
0
```

## W3002

```text
a `has` after one with the same modifiers belongs in it: `has a: A, b: B;` [combine-has]
```

A `has` statement directly follows another with the same modifiers, and could be part of it. Reported by the rule `combine-has`, which the groups `"style"` and `"clean"` select. Two statements separated by a blank line, or either one documented or with accessors, are left alone.

<!-- example: not checked: a lint rule, and the examples are checked with none selected -->
```jac
obj Point {
    has x: int = 0;
    has y: int = 0;
}

with entry {
    print(Point().x);
}
```

With this in `jac.toml`:

```toml
[check.lint]
select = ["combine-has"]
```

`jac check` reports the second `has`.

**Fix:** join them, as `jac fmt --fix` does:

```jac
obj Point {
    has x: int = 0,
        y: int = 0;
}

with entry {
    print(Point().x);
}
```

```output
0
```

## W3003

```text
a `glob` after one with the same modifiers belongs in it: `glob a = 1, b = 2;` [combine-glob]
```

A `glob` statement directly follows another with the same modifiers, and could be part of it. Reported by the rule `combine-glob`, which the groups `"style"` and `"clean"` select (`select = ["combine-glob"]` alone selects it too). The same exceptions as `combine-has` apply.

<!-- example: not checked: a lint rule, and the examples are checked with none selected -->
```jac
glob width: int = 1;
glob height: int = 2;

with entry {
    print(width * height);
}
```

**Fix:** join them, as `jac fmt --fix` does:

```jac
glob width: int = 1,
     height: int = 2;

with entry {
    print(width * height);
}
```

```output
2
```

## W3004

```text
the {what} is named '{word}', not '{name}'
```

A method is named with Python's name for a constructor, `__init__`, or the reference design's older `__post_init__`. `{what}` is `constructor` or `post-initializer`, `{word}` the name Jac uses (`init`, `postinit`) and `{name}` the name written. A method named `__init__` would never run when an object is made.

```jac
# expect: W3004
obj Account {
    has balance: int = 0;

    def __init__(balance: int) {
        self.balance = balance + 1;
    }
}

with entry {
    print(Account(5).balance);
}
```

**Fix:** name it `init` (or `postinit`). `jac fmt --fix` renames it. Python's `self` parameter
may stay, `def init(self, balance: int)`, or be left out as below: a method has `self` either way,
and lists it only to say how it takes its receiver (see [Methods](../../language/methods.md#self),
`jac docs self`).

```jac
obj Account {
    has balance: int = 0;

    def init(balance: int) {
        self.balance = balance + 1;
    }
}

with entry {
    print(Account(5).balance);
}
```

```output
6
```

## W3005

```text
empty parentheses are not written here
```

Empty parentheses are written where Jac writes none: after a function's or a method's name with no parameters (`def f()`), after `lambda`, after an archetype's or an enum's name with no bases (`obj A()`). A call still takes its parentheses: `f()`.

```jac
# expect: W3005
def ready() -> bool {
    return True;
}

with entry {
    print(ready());
}
```

**Fix:** drop them: `def ready -> bool`. `jac fmt --fix` drops them.

```jac
def ready -> bool {
    return True;
}

with entry {
    print(ready());
}
```

```output
True
```

## W3007

```text
hasattr(x, "{name}") of a value whose class has '{name}' asks only whether it is None: write `x is not None`
```

`hasattr(x, "name")` is asked of a value whose class declares that field. `{name}` is the field. The class always has the field, so the call can only be asking whether `x` is `None`, and should say so. In Python `hasattr` is a common guard for an optional value; here a value's fields are known from its type.

```jac
# expect: W3007
obj Box {
    has width: int = 1;
}

def wide(b: Box | None) -> bool {
    return hasattr(b, "width") and b.width > 2;
}

with entry {
    print(wide(None));
}
```

**Fix:** test for `None`. `jac fmt --fix` rewrites it.

```jac
obj Box {
    has width: int = 1;
}

def wide(b: Box | None) -> bool {
    return b is not None and b.width > 2;
}

with entry {
    print(wide(None));
}
```

```output
False
```

## W3008

```text
'a if a else b' is 'a or b' [simplify-ternary]
```

A conditional expression returns its own condition when it is true, `a if a else b`, which is `a or b`. Reported by the rule `simplify-ternary`, which the groups `"style"` and `"clean"` select.

<!-- example: not checked: a lint rule, and the examples are checked with none selected -->
```jac
def pick(a: int, b: int) -> int {
    return a if a else b;
}

with entry {
    print(pick(0, 2));
}
```

**Fix:** write `a or b`, as `jac fmt --fix` does:

```jac
def pick(a: int, b: int) -> int {
    return a or b;
}

with entry {
    print(pick(0, 2));
}
```

```output
2
```

## W3009

```text
`import from __future__ {{ annotations }}` does nothing in Jac
```

A module imports `annotations` from `__future__`. Python needs it to postpone the evaluation of annotations; Jac's annotations are types the compiler reads, and the import changes nothing.

```jac
# expect: W3009
import from __future__ { annotations }

with entry {
    print(1);
}
```

**Fix:** delete the import. `jac fmt --fix` deletes it.

## W3010

```text
the impl of '{name}' restates its signature differently: {difference}
```

An `impl` restates its declaration's signature differently. `{name}` is the function and `{difference}` says what differs: the parameters' names, a parameter's type or default, the return type, the type parameters, where `/` or `*` stands, or an ability's event. An impl repeats its declaration's signature exactly, so a reader of either sees the same function; it cannot rename a parameter, and it cannot leave the signature out. See [Impl](../../language/impl.md).

```jac
# expect: W3010
def scale(factor: int) -> int;

impl scale(k: int) -> int {
    return 2 * k;
}

with entry {
    print(scale(2));
}
```

**Fix:** copy the declaration's signature. `jac fmt --fix` writes it where the impl names the declaration's parameters, in their order: another type, default or return type, and a signature left out where the declaration has no parameters. It leaves an impl whose parameters are named differently for its author, since its body uses those names.

```jac
def scale(factor: int) -> int;

impl scale(factor: int) -> int {
    return 2 * factor;
}

with entry {
    print(scale(2));
}
```

```output
4
```

## W3013

```text
a ';' on its own is no statement
```

A `;` stands where there is no statement for it to end: a second `;` after a statement, a `;` alone in a block or an archetype, a `;` after a `has` with accessors or after a `for` loop's step.

```jac
# expect: W3013
with entry {
    n = 1;;
    print(n);
}
```

**Fix:** delete it. `jac fmt --fix` deletes it.
