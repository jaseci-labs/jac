# W5021: a C library the target does not have

W5021 is the reference design's warning for a C library that cannot be found, which jac reports as an error. It is reported where a program imports C functions from a library that the platform it is built for does not provide, so the same program can check on one platform and be refused on another. See [C libraries](../../interop/c-libraries.md) (`jac docs interop/c-libraries`), which lists the libraries each platform has.

## W5021

```text
the C library '{lib}' is not available on {platform}: {reason}
```

An `import from <lib> { ... }` of C declarations names a library that the target platform does not have. `{lib}` is the library, `{platform}` the target (`macOS`, `Windows`, `WASI`) and `{reason}` why it is missing there. macOS ships no OpenSSL a program may link and no `zstd`; Windows has none of `dl`, `pthread`, `bz2`, `zstd`, `ssl` and `crypto`; a `wasm32-wasi` program links only the C library and math library and imports only `wasi_*` host modules.

<!-- example: not checked: whether it is reported depends on the target platform -->
```jac
import from z {
    def zlibVersion -> ptr[u8];
}

with entry {
    print(1);
}
```

This checks on Linux, macOS and Windows, which all have zlib. `jac check --target wasm32-wasi` reports `the C library 'z' is not available on WASI: a wasm32-wasi program links only wasi-libc, and imports only wasi_* host modules`.

**Fix:** use a library the target has, put the code that needs the library in a module only the platforms that have it build (a target variant such as `net.linux.jac`), or build for another target. A library the project provides itself, imported by its dotted path from the project's root (`import from vendor.raylib { ... }`), is not refused, except on WASI.
