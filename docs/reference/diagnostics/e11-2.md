# E1150 to E1170: C data and type expressions

E1150 to E1159 and E1169 to E1170 are reported for declarations and values that cross into C:
records, opaque types, globals, variadic functions and borrows, as bound by an
`import from c { ... }` block (see [C libraries](../../interop/c-libraries.md)). E1161 to E1168
are reported where something written as a type is not one, or has the wrong arguments.

## E1150

```text
the C record {name} contains itself
```

A C record has a field of its own type, directly or through other records, so it would have no
finite size. `{name}` is the record. C refuses the same declaration.

```jac
# expect: E1150
import from c {
    obj Link {
        has value: i32,
            next: Link;
    }
}
```

**Fix:** hold a pointer to the record instead, as the C declaration does: `next: ptr[Link];`.

## E1151

```text
the opaque C type {name} has no known size, so it cannot be {use}
```

An opaque C type is used where its size is needed. A record declared without a body (`obj FILE;`)
is opaque: C never says what is in it. `{name}` is the type and `{use}` is `constructed` or
`stored or passed by value`.

```jac
# expect: E1151
import from c {
    obj FILE;
}

with entry {
    f = FILE();
}
```

**Fix:** handle the type only through a pointer, `ptr[FILE]`, which is what the C functions that
make and take it use: `def fclose(f: ptr[FILE]) -> i32;`.

## E1152

```text
{what} takes C plain data, not {type}
```

A value that C cannot hold is put where C plain data is required. `{what}` is the place (`pin()`,
`a ptr's item`, `a view`, `a C borrow parameter`, `a tensor`) and `{type}` the type given. C plain
data is a number, a `bool`, a `ptr`, or a C record that is not opaque; a Jac object, a `str` or a
`list` is not.

```jac
# expect: E1152
obj Box {
    has v: int = 0;
}

with entry {
    held = pin(Box());
}
```

**Fix:** keep data that C reads or writes in a C record, declared inside an
`import from c { ... }` block, or in numbers and pointers.

## E1153

```text
the C array '{name}' is not a list: read and write it through addressof(), a ptr to its first element
```

The name of a C array is used as a value. `{name}` is the global. `glob name: list[T] = [...];` in
an `import from c` block defines a C array in the program: C's storage, with no list around it. Its
name stands only as the argument of `addressof()`.

```jac
# expect: E1153
import from c {
    glob table: list[i32] = [1, 2, 3];
}

with entry {
    print(table[2]);
}
```

**Fix:** index the array through its address: `addressof(table)[2]`. `addressof(table)` is a
`ptr[i32]` to the first element, which reads and writes the elements in place. See
[C libraries](../../interop/c-libraries.md).

## E1154

```text
addressof() takes a C record or a C global, not {type}
```

`addressof()` is given something with no C address. `{type}` is the argument's type.
`addressof(x)` gives a `ptr` to a C record value or to a C global (a `glob` declared in an
`import from c` block).

```jac
# expect: E1154
with entry {
    n = 5;
    p = addressof(n);
}
```

**Fix:** take the address of a C record or C global. To let a C function write a number, declare
its parameter as a borrow (`def f(x: &mut i32);`) and pass `&mut n`.

## E1155

```text
the C array '{name}' is defined by a list literal
```

A C global of a `list` type is declared without a value, or with a value that is not a list
literal. `{name}` is the global. A list-typed global in an `import from c` block defines a C array
in the program, and the list literal gives its length and contents.

```jac
# expect: E1155
import from c {
    glob table: list[i32];
}
```

**Fix:** write the literal: `glob table: list[i32] = [1, 2, 3];`. The program reaches the array
through `addressof(table)`, a `ptr[i32]` to its first element. See
[C libraries](../../interop/c-libraries.md).

## E1157

```text
a C variadic argument is a C scalar, ptr, str, bytes or bytearray, not {type}
```

An argument passed in the variadic part of a C function call is not something C's `...` can carry.
`{type}` is the argument's type. Ints, floats, bools, pointers, `str`, `bytes` and `bytearray` can
be passed.

```jac
# expect: E1157
import from c {
    def printf(fmt: str, *args: any) -> i32;
}

with entry {
    printf("%d\n", [1, 2]);
}
```

**Fix:** pass each value as its own argument: `printf("%d %d\n", 1, 2);`.

## E1158

```text
the C function '{name}' {reason}
```

A C function's declaration has a parameter list C cannot have. `{name}` is the function and
`{reason}` is one of:

- `cannot take **kwargs`: C has no keyword arguments;
- `must type its variadic parameter VaList or any`: C's `...` is written `*args: any` or
  `*args: VaList`;
- `must take its variadic parameter last`.

```jac
# expect: E1158
import from c {
    def printf(fmt: str, **opts: int) -> i32;
}
```

**Fix:** declare the function as C does, with the variadic parameter last:
`def printf(fmt: str, *args: any) -> i32;`.

## E1159

```text
'{name}' is a borrowed scalar parameter: assigning it cannot reach the caller; return the new value, or take a ptr[T] to storage the caller owns
```

A Jac function takes a number, a `bool` or another value that is not a reference to an object by
`&` or `&mut`. `{name}` is the parameter. A borrow reaches the caller's object, and a scalar is
not an object: assigning the parameter would change only the function's own copy.

```jac
# expect: E1159
def bump(n: &mut int) {
    n = n + 1;
}
```

**Fix:** return the new value and let the caller assign it:

```jac
def bump(n: int) -> int {
    return n + 1;
}

with entry {
    n = 1;
    n = bump(n);
    print(n);
}
```

```output
2
```

See [Ownership](../../language/ownership.md).

## E1161

```text
an exception's cause is an exception or None, not {type}
```

The value after `from` in `raise ... from ...` is not an exception or `None`. `{type}` is its
type.

```jac
# expect: E1161
with entry {
    raise ValueError("bad input") from "the parser";
}
```

**Fix:** give the exception that caused this one (`raise ValueError("bad input") from err;` inside
`except KeyError as err`), or put the text in the message. See
[Exceptions](../../language/exceptions.md).

## E1163

```text
{what} is not a type
```

Something that is not a type is written where a type is required: after `:` in a declaration,
after `->`, or as a type argument. `{what}` describes what was written, as `an int literal`,
`a '+' expression` or `'math.pi'`.

```jac
# expect: E1163
with entry {
    n: 5 = 5;
    print(n);
}
```

**Fix:** write a type: `n: int = 5;`. A union of types is written with `|` (`int | str`). See
[Types](../../language/types.md).

## E1164

```text
'{type}' takes {expected} type argument(s), found {given}
```

A generic type or function is given the wrong number of type arguments. `{type}` is its name,
`{expected}` the number it takes and `{given}` the number written. `dict` takes two, `list` and
`set` one, and a generic class as many as it declares parameters.

```jac
# expect: E1164
def count(d: dict[str]) -> int {
    return len(d);
}
```

**Fix:** write every argument: `dict[str, int]`. See [Generics](../../language/generics.md).

## E1165

```text
the type alias '{name}' is defined by itself
```

A type alias refers to itself in its own definition. `{name}` is the alias. An alias is another
name for a type that already exists, so it cannot be used to define itself.

```jac
# expect: E1165
type Tree = list[Tree];

def depth(t: Tree) -> int {
    return 0;
}
```

**Fix:** declare a class for a recursive structure; a field may have its own class's type:
`obj Tree { has kids: list[Tree] = []; }`.

## E1166

```text
Final is only valid as the outermost type of a variable
```

`Final[T]` is written inside another type, or as a parameter's or a return type. `Final` says a
variable is never rebound, so it wraps the whole type of a variable or field and nothing else.

```jac
# expect: E1166
def total(xs: list[Final[int]]) -> int {
    return len(xs);
}
```

**Fix:** remove `Final` (`xs: list[int]`), or put it outermost on a variable:
`glob LIMIT: Final[int] = 10;`. See [Variables](../../language/variables.md).

## E1167

```text
'...' is only allowed as the second of two tuple type arguments
```

`...` appears in a tuple type anywhere but as the second of exactly two arguments.
`tuple[int, ...]` is a tuple of any number of ints; no other placement of `...` has a meaning.

```jac
# expect: E1167
with entry {
    t: tuple[..., int] = (1, 2);
    print(t);
}
```

**Fix:** write `tuple[int, ...]` for any number of ints, or list each item's type
(`tuple[int, int]`).

## E1168

```text
a type parameter's bound is a class
```

The bound of a type parameter (`T: Bound`) names something that is not a class, such as a type
alias for a union, a function or a name that does not exist. The bound says what every type used
for `T` derives from, so that the body may use the bound's fields and methods.

```jac
# expect: E1168
type Number = int | float;

def first[T: Number](xs: list[T]) -> T {
    return xs[0];
}
```

**Fix:** bound the parameter by a class, or leave it unbounded (`def first[T](xs: list[T]) -> T`)
when the body needs nothing of `T`. See [Generics](../../language/generics.md).

## E1169

```text
VaList types only the variadic parameter of a C function
```

`VaList` is used as the type of something other than the `*args` parameter of a C function
declaration. `*args: VaList` is how a C function's `...` is written; `VaList` is not a type that
values have.

```jac
# expect: E1169
def log(fmt: str, args: VaList) {
    print(fmt);
}
```

**Fix:** in a Jac function, take any number of arguments with `*args: any`. In an
`import from c` block, write the parameter with its star: `*args: VaList`.

## E1170

```text
a C global is a name with a type
```

A `glob` inside an `import from c` block is not a single name with a type. A C global is bound by
name and type, as `glob opterr: i32;`: the type says how to read the C variable, and nothing can
infer it.

```jac
# expect: E1170
import from c {
    glob errno = 0;
}
```

**Fix:** declare the type: `glob opterr: i32;` binds an existing C variable, and
`glob counter: i32 = 0;` defines one in the program.
