# E0001 to E0048: syntax

These codes are reported while a file is read: a token that is missing or out of place, a reserved
word used as a name, a statement written where it cannot stand. Each entry gives the message
template, what it means, a program that is refused with it, and what to write instead. In a
template, `{name}` is filled in when the error is reported, and `{{` and `}}` stand for the braces
`{` and `}`.

## E0001

```text
expected {expected}, found '{found}'
```

The grammar needs one particular token or construct here, and something else is written.
`{expected}` is the token in quotes (`'in'`), a choice (`'entry' or 'exit'`) or a description
(`a string`); `{found}` is the token that stands there, or `end of file`.

```jac
# expect: E0001
with entry {
    for i range(3) {
        print(i);
    }
}
```

**Fix:** write the expected token where the error points.

```jac
with entry {
    for i in range(3) {
        print(i);
    }
}
```

## E0002

```text
missing '{token}'
```

A closing bracket or a separator is not where the grammar needs it. `{token}` is `;`, `,`, `)`, `]`
or `}`. The error points at the token found in its place, so a missing `;` is reported at the start
of the next statement.

```jac
# expect: E0002
with entry {
    x = 1
    print(x);
}
```

**Fix:** add the token before the place the error points at. Here, end the assignment with `;`:
`x = 1;`. See [Lexical structure](../../language/lexical-structure.md).

## E0003

```text
expected {what} name, found '{found}'
```

A name is needed and the token there is neither a name nor a keyword. `{what}` says which name
(`an archetype`, `an enum`, `an attribute`, `a global variable`, ...); `{found}` is the token that
stands there.

```jac
# expect: E0003
obj {
    has x: int = 1;
}
```

**Fix:** give the name: `obj Point { ... }`. After a `.`, write the attribute's name.

## E0005

```text
unexpected '{token}'{context}
```

No declaration, statement or expression starts with this token. `{token}` is the token, or
`end of file`; `{context}` is empty, ` in an f-string` or ` in a format spec`.

```jac
# expect: E0005
with entry {
    x = ;
}
```

**Fix:** write the expression or statement that is missing before the token, or remove the token.
Here, give the assignment its value: `x = 0;`.

The reference design's old connect spellings, `a +:E:+> b` and its backward `a <+:E:+ b`, are this code too, each
as `unexpected ':'`:

```jac
# expect: E0005 x2
node Person {
    has name: str;
}

edge Knows: Person --> Person {}

with entry {
    a = Person(name="ann");
    b = Person(name="bob");
    a +:Knows:+> b;
    a <+:Knows:+ b;
}
```

**Fix:** write the connects as `a +>:Knows:+> b`, the edge between `+>:` and `:+>`, and
`a <+:Knows:<+ b`, the edge between `<+:` and `:<+`. See
[Connecting](../../language/connecting.md) (`jac docs connect`).

## E0013

```text
'{keyword}' is a keyword and cannot be used as {what} name
```

A reserved word is written where a name is bound. `{keyword}` is the word and `{what}` the kind of
name (`a variable`, `an ability`, `an archetype`, `a pattern`, ...). Every Jac
[keyword](../../language/lexical-structure.md#keywords) is reserved, among them the type words
(`int`, `str`, `list`, `type`, ...) and words that are everyday names elsewhere: `root`, `node`,
`edge`, `entry`, `test`, `by`, `skip`, `wait`, `spawn`. Python code that names a variable `node`
or `list` is refused.

```jac
# expect: E0013
with entry {
    node = 1;
    print(node);
}
```

**Fix:** choose another name, or escape the keyword with a backtick wherever the name is bound or
read. See [Lexical structure](../../language/lexical-structure.md).

```jac
with entry {
    `node = 1;
    print(`node);
}
```

## E0014

```text
'{name}' is not a keyword -- remove the backtick
```

A backtick escapes a keyword so that it can be used as a name. `{name}` is a word written after a
backtick that is not a keyword, so there is nothing to escape.

```jac
# expect: E0014
with entry {
    `count = 1;
}
```

**Fix:** write the name without the backtick: `count = 1;`.

## E0020

```text
an assignment expression binds a name
```

The target of `:=` is not a plain name. An assignment expression can bind a variable; it cannot
store to an item, an attribute or an unpacking.

```jac
# expect: E0020
with entry {
    xs = [0];
    if (xs[0] := 5) > 1 {
        print(xs);
    }
}
```

**Fix:** bind a name with `:=`, or assign with a statement first (`xs[0] = 5;`) and then test the
value. See [Operators](../../language/operators.md).

```jac
with entry {
    xs = [0];
    if (n := len(xs)) > 0 {
        print(n);
    }
}
```

## E0022

```text
expected '{{' after the lambda's parameters
```

A lambda's body is a block. Python's form, `lambda x: x + 1`, with a `:` and an expression, is not
Jac.

```jac
# expect: E0022
with entry {
    f = lambda x: x + 1;
    print(f(1));
}
```

**Fix:** put the parameters in parentheses with their types, give the return type, and write the
body as a block that returns. See [Functions](../../language/functions.md).

```jac
with entry {
    f = lambda (x: int) -> int { return x + 1; };
    print(f(1));
}
```

## E0026

```text
connect and disconnect operators need a right operand
```

A `del` statement's target is followed by an edge arrow. `del a --> b;` is not how an edge is
removed: `del` deletes the values it lists, and the disconnect operator is written between its two
nodes.

```jac
# expect: E0026
node N {}

with entry {
    a = N();
    b = N();
    a ++> b;
    del a --> b;
}
```

**Fix:** write the disconnect operator with a node on each side: `a del --> b;`. See
[Connecting](../../language/connecting.md).

```jac
node N {}

with entry {
    a = N();
    b = N();
    a ++> b;
    a del --> b;
    print(len([a -->]));
}
```

## E0030

```text
unexpected ';' at module level
```

A `;` stands alone between a module's declarations. The usual cause is a `;` after the closing `}`
of an archetype, a function or a `with entry` block, as C and C++ write after a class.

```jac
# expect: E0030
obj A {
    has x: int = 1;
};
```

**Fix:** remove the `;`. A declaration with a body ends at its `}`.

## E0032

```text
unexpected '{token}' -- it must follow its if, try, match or switch
```

`{token}` is `elif`, `else`, `except`, `finally` or `case`, written where a statement starts, with
no `if`, `try`, `match` or `switch` directly before it to belong to.

```jac
# expect: E0032
with entry {
    else {
        print(1);
    }
}
```

**Fix:** attach the clause to its statement: `else` and `elif` come right after the `}` of an `if`
block (or the loop or `try` they belong to), `except` and `finally` after a `try` block, and `case`
inside the braces of a `match` or `switch`. See
[Control flow](../../language/control-flow.md).

## E0033

```text
{what} must be known at compile time
```

A place that needs a compile-time value is given one that only exists when the program runs.
`{what}` names the value: a name in quotes (`'a'`), or a description such as
`a tuple slice's bounds and step` or `an int enum member's value`.

```jac
# expect: E0033
glob a = 1;

comptime b = a + 1;

with entry {
    print(b);
}
```

**Fix:** build the value from literals and other `comptime` values. Here, make `a` a compile-time
value too. See [Compile time](../../language/compile-time.md).

```jac
comptime a = 1;
comptime b = a + 1;

with entry {
    print(b);
}
```

## E0034

```text
expected 'with' after the name of a 'can' ability; use 'def' for a function
```

`can` declares an ability, which runs on an event and is written `can name with ... entry` or
`can name with ... exit`. A `can` followed by a parameter list or a return type is a function,
which older Jac also spelled `can`; here a function is declared with `def`.

```jac
# expect: E0034
obj A {
    can f -> int {
        return 1;
    }
}
```

**Fix:** declare the function with `def`. See [Functions](../../language/functions.md) and
[Abilities](../../language/abilities.md).

```jac
obj A {
    def f -> int {
        return 1;
    }
}
```

## E0044

```text
a payload lists at least one item
```

In `archwire.jac`, the braces after a wire's consumer or after an edge rule (the payload) are
empty. It arises for a wire such as `util ++> main {}`. `archwire.jac` belongs to a project, so
this error is reported on that file together with E2093.

**Fix:** list the names the wire delivers, `util ++> main { now }`, or drop the braces to wire the
module itself, `util ++> main;`. See [archwire](../../apps/archwire.md).

## E0045

```text
a mapping pattern key is a number or a string
```

A key in a mapping pattern (`case {key: pattern}`) is a name or another expression. A key is matched
by value, so it is written as a number or a string literal.

```jac
# expect: E0045
with entry {
    k = "a";
    match {"a": 1} {
        case {k: v}:
            print(v);
    }
}
```

**Fix:** write the key as a literal. See
[Pattern matching](../../language/pattern-matching.md).

```jac
with entry {
    match {"a": 1} {
        case {"a": v}:
            print(v);
    }
}
```

## E0046

```text
unexpected '{token}' in an archetype body
```

An archetype's body holds member declarations. `{token}` starts something else there, such as a
`return`, an `if` or a loop written directly between the archetype's braces.

```jac
# expect: E0046
obj A {
    has x: int = 1;

    return x;
}
```

**Fix:** move the statement into a method. See [Archetypes](../../language/archetypes.md).

```jac
obj A {
    has x: int = 1;

    def get -> int {
        return self.x;
    }
}
```

## E0047

```text
expected '{{' or 'by' for an impl body, found '{found}'
```

An `impl` gives a declaration its body, and none is written. `{found}` is the token that follows
the impl's signature, usually `;`.

```jac
# expect: E0047
obj A {
    def f -> int;
}

impl A.f -> int;
```

**Fix:** write the body as a block, or delegate it with `by`. See [impl](../../language/impl.md).

```jac
obj A {
    def f -> int;
}

impl A.f -> int {
    return 1;
}
```

## E0048

```text
the parenthesized filter '(?:...)' was removed; write '[?:...]'
```

A filter is written in parentheses after a value: `ps(?n > 1)` or `ps(?:T)`. That is the older Jac
spelling. A filter is written in brackets.

```jac
# expect: E0048
obj P {
    has n: int = 0;
}

with entry {
    ps = [P(n=1), P(n=2)];
    print(len(ps(?n > 1)));
}
```

**Fix:** use brackets: `ps[?n > 1]` filters by attribute, `ps[?:T]` by type, and `ps[?:T, n > 1]`
by both.

```jac
obj P {
    has n: int = 0;
}

with entry {
    ps = [P(n=1), P(n=2)];
    print(len(ps[?n > 1]));
}
```
