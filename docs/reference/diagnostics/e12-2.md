# E1210-E1228: spaces, UI plugins and pages

These errors belong to a project whose `archwire.jac` declares spaces: who may call a function
across spaces, which `ui` plugin a JS space is built with, what a component may hold under that
plugin, and what a page declares. They are reported when the project is checked or built (`jac check`,
`jac build <app>`, `jac emit-js <space>`).

None of them arises in a program of one file, so the entries show the lines that raise them
instead of a whole program. A space is declared in `archwire.jac`, its `ui` plugin is the one
`[spaces.<name>.ui]` names in `jac.toml`
([UI plugins and bundlers](../../apps/ui-bindings.md)), and a component is a function that
returns `JsxElement`. See [Archwire](../../apps/archwire.md) (`jac docs archwire`).

## E1210

```text
'{name}' of '{module}' is called across spaces from {host} code, so it says who may: `:pub` for anyone, `:protect` for a signed-in caller
```

Code of a space on a JS host (`browser`, `hermes` or `node`) is wired to a function or walker of
another space, and that function or walker has no access tag. `{name}` is the function or walker,
`{module}` the module that declares it and `{host}` the host of the calling space. A call from a
browser arrives from outside the app, so the callee states who may make it.

It arises for `def plain -> int` in module `svc` of a native space when `archwire.jac` wires it to
a browser space's module: `svc ++> page { plain }`.

**Fix:** tag the declaration: `def:pub plain -> int` for a function anyone may call,
`def:protect plain -> int` for one only a signed-in caller may. A walker takes the tag the same way:
`walker:pub Visit`. See [Crossings](../../apps/crossings.md) and [Access](../../language/access.md).

## E1211

```text
'{name}' is `:{tag}` in '{module}', which no space holds: an access tag says who may call across spaces
```

A function or walker is tagged `:pub` or `:protect` (`{tag}`) in a module that no space of
`archwire.jac` holds. `{name}` is the declaration and `{module}` its module. An access tag says who
may call across spaces; a module in no space is compiled into each program that uses it, and
nothing crosses to reach it.

It arises when `archwire.jac` declares `space api: native { other; }` and module `svc`, listed in
no space, declares `def:pub plain -> int`.

**Fix:** remove the tag (`def plain -> int`), or list the module in the space that is to serve it:
`space api: native { svc; other; }`. See [Crossings](../../apps/crossings.md).

## E1212

```text
app '{app}' reaches space '{space}' but doesn't run it: give its URL in jac.toml's [apps.{app}.remote]
```

An app's code calls a space the app does not run, and the build has no URL for that space.
`{app}` is the app being built and `{space}` the space it reaches. A call to a space of another app
travels over the network, and the app is built knowing where that space is.

It arises on `jac build api` when app `api` runs space `cli`, whose module calls a function of
space `api`, which app `back` runs.

**Fix:** say where the space is, in `jac.toml`:

```toml
[apps.api.remote]
api = "http://127.0.0.1:8000"
```

The environment variable `JAC_REMOTE_<SPACE>` gives another URL when the app runs. If the app
should run the space itself, add it to the app's `run` list in `archwire.jac`. See
[Archwire](../../apps/archwire.md).

## E1214

```text
the `ui` plugin '{name}' doesn't support host '{host}'
```

The space's `ui` plugin `{name}` does not run on the space's host `{host}`. Each `ui` plugin
lists the hosts it supports; `plugin = "solid"` for a `hermes` space is refused because `solid`
lists only `browser`. It is reported at the plugin's line of `jac.toml`.

```toml
[spaces.site.ui]
plugin = "react_native"
```

reports, for a `browser` space `site`:

```text
jac.toml:5:1: error[E1214]: the `ui` plugin 'react_native' doesn't support host 'browser'
```

**Fix:** choose a plugin that supports the host (`react_native` on hermes), or declare the space
on a host the plugin supports: `space page: browser { ... }`. A name that is no plugin at all is
[E2214](e22-2.md), and a plugin that fills another abstraction (`vite`) is [E2215](e22-2.md).

## E1215

```text
`has` in a function belongs at the top of its body, not inside a block
```

A `has` statement in a function declares state, and it is written inside a block: an `if`, a loop,
a `try`. State is declared once for each use of the component, so it stands at the top level of the
function's body, never under a condition.

It arises for `if n > 0 { has a: int = 0; }` in a component.

**Fix:** move the `has` to the top of the function's body and put the condition on its use:
`has a: int = 0;` first, then `if n > 0 { ... }` reading `a`.

## E1216

```text
a statement in a component's body runs an unknown number of times: put it in an effect
```

A component's body holds a statement that does something, such as `print(n);` or another call for
its effect. A component's body is setup and derived values; a UI library runs it as often as it
likes, so a statement there would run an unknown number of times.

**Fix:** put the statement in an effect, an ability of the component that runs when it is mounted
or when what it lists changes:

- `can with entry { print(n); }` runs once, when the component is first shown.
- `can with [count] entry { print(count); }` runs again whenever `count` changes.

## E1217

```text
'{name}' is state, and {how} changes it in place without anyone seeing: assign a new value
```

A component changes a state variable in place. `{name}` is a variable declared with `has` in the
function, and `{how}` is the method called on it (`append`, `pop`, `update`, ...) or `assignment`,
for a write to one of its items or fields (`xs[0] = 1`). The UI is redrawn when state is assigned,
and a change inside the value is not an assignment.

It arises for `has xs: list[int] = [];` followed by `xs.append(1)` in a handler.

**Fix:** assign a new value built from the old one: `xs = xs + [1];`, `d = {**d, "k": 1};`.

## E1218

```text
the `ui` plugin '{name}' has no model for `has` and effects in a function: use its library's functions
```

A function declares state (`has`) or an effect (`can with entry`), and the space's `ui` plugin
`{name}` has the model `none`: it does not say what state and effects become in its library. Under
such a plugin JSX passes through and the library's functions are ordinary imports.

**Fix:** call the library's own functions for state and effects, imported from its package, or
choose a plugin with a model (`react`, `preact`, `react_native`, `solid`) in `jac.toml`'s
`[spaces.<space>.ui]`.

## E1219

```text
'{package}' belongs to the `ui` plugin '{owner}', and this space uses '{name}'
```

A module imports an npm package that belongs to another `ui` plugin than the one its space is
built with. `{package}` is the package, `{owner}` a plugin that owns it and `{name}` the space's
plugin. Importing `"react"` in a space built with `solid` is refused: two UI libraries in one
space do not share state.

**Fix:** use the space's own library. State and effects need no import at all: write `has` and
`can with entry` in the component and the plugin supplies its library's functions. To use the
other library, name its plugin for the space in `jac.toml`: `[spaces.<space>.ui]`
`plugin = "react"`.

## E1220

```text
text directly in <{tag}> isn't shown under the `ui` plugin '{name}': put it in a text element
```

JSX puts text directly inside an element that does not show text under the space's `ui` plugin.
`{tag}` is the element and `{name}` the plugin. Under `react_native`, `<View>words</View>` is
refused: only a text element draws text.

**Fix:** wrap the text in the library's text element: `<View><Text>words</Text></View>`.

## E1221

```text
<{tag}> isn't an element under the `ui` plugin '{name}', which has no lowercase tags
```

JSX uses a lowercase tag, `{tag}`, under a `ui` plugin that has no such elements. `{name}` is the
plugin. Lowercase tags are HTML elements, which exist in a browser; `<div />` under `react_native`
names nothing.

**Fix:** use the library's components, imported from its package: `<View />` in place of
`<div />`, `<Text>` in place of `<span>`.

## E1222

```text
a component's body runs once under this space's `ui` plugin, so it can't hold {what}
```

Under a fine-grained `ui` plugin (`solid`), a component's body runs once, and what it returns is
kept current as state changes. The body therefore cannot decide anything from state as it runs.
`{what}` is the statement refused:

| `{what}` | Written |
|---|---|
| ``a `return` before the end`` | a `return` that is not the body's last statement |
| ``a `return` inside a block`` | `if a > 0 { return <b />; }` |
| `a block reading state` | an `if`, loop or `match` in the body that reads state or a parameter |

**Fix:** end the body with one `return`, and move the choice into it or into a derived value:
`return <b>{"yes" if a > 0 else "no"}</b>;`, or `label = "yes" if a > 0 else "no";` before the
`return`.

## E1223

```text
a function holding state returns a typed object built with keywords, whose fields stay current
```

Under a fine-grained `ui` plugin (`solid`), a function that is not a component declares state
(`has`) or an effect, and does not end by returning an object built with keyword arguments. Such a
function shares state between components; what it returns is a typed object whose fields stay
current as the state changes. Returning the state's value itself (`return a;`) would hand back a
copy that never changes.

**Fix:** declare a class for what the function gives, and return it built with keywords as the
last statement: with `obj Tally { has a: int; }`, write `def use_tally -> Tally` ending in
`return Tally(a=a);`.

## E1224

```text
'{name}' follows state, and is assigned more than once: give each value its own name
```

Under a fine-grained `ui` plugin, a local computed from state follows that state: it is
recomputed whenever the state changes. `{name}` is such a local that is assigned more than once,
or a parameter of the component that the body assigns. A name that follows state has one
definition.

It arises for `b = a; b = a + 1;` where `a` is state, and for `n = 2;` where `n` is a parameter.

**Fix:** give each value its own name: `b = a; c = a + 1;`. Leave parameters as the caller gave
them, and compute a new local from one: `shown = n * 2;`.

## E1225

```text
this effect reads '{name}', and its dependency list doesn't say so
```

An effect lists the state it depends on, and its body reads a state variable the list leaves out.
`{name}` is that variable. `can with [a] entry { print(b); }` runs again only when `a` changes, so
it would show an old `b`.

**Fix:** list everything the effect reads: `can with [a, b] entry { print(b); }`. In React this
mistake is a stale value at run time; here it is refused.

What a function the effect makes reads is not the effect's: a lambda given to a timer runs later,
and reads the state as the component last showed it. `can with [a] entry { setInterval(lambda {
ticks = ticks + 1; }, 1000); }` lists `a` alone, and does not start again each time `ticks`
changes.

## E1226

```text
'{host}' is not a host: a space runs on native, wasm, browser, hermes, node or cpython
```

A space is declared on a host that does not exist. `{host}` is the word after the colon in
`space <name>: <host> { ... }`. The hosts are `native`, `wasm`, `browser`, `hermes`, `node` and
`cpython`.

It arises for `space api: nosuch { svc; }` in `archwire.jac`.

**Fix:** name one of the six hosts: `space api: native { svc; }`. See
[Archwire](../../apps/archwire.md).

## E1227

```text
'{module}' is a page, and declares no `{name}` function
```

A module below `pages/` in a browser space is a page, and it does not declare the function a page
is. `{module}` is the module and `{name}` the function wanted: `page` for a page, `layout` for
`pages/layout.jac`.

It arises when `pages/user.jac` declares only some other function.

**Fix:** declare the function: `def:pub page -> JsxPage` in a page's module,
`def:pub layout -> JsxLayout` in `pages/layout.jac`. Move a module that is not a page out of `pages/`.

## E1228

```text
a page's parameter '{name}' is a segment of its URL: a str, or `*` and str for the rest
```

A page function's parameter is not a `str`. `{name}` is the parameter. Each parameter of `page`
names a dynamic segment of the page's URL, which is text: `id: str` takes one segment, and
`*rest: str` takes all that remain. `def:pub page(id: int)` is refused, and so are keyword-only
and `**` parameters.

**Fix:** declare the parameter `str` and convert in the body: `def:pub page(id: str) -> JsxPage`
with `n = int(id);`.
