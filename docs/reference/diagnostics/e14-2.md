# E1431 to E1467: math forms, tensor views, a local's type and pointer access

These codes report an operation asked of a value whose type has no form of it: a `math` function on a float type it is not written for, a tensor view whose axes or sizes do not fit the tensor, a local bound to a second type, and a `load()` or `store()` on a `ptr` that should be an index. See [Tensors](../../accel/tensors.md), [Vectors](../../accel/vectors.md), [Variables](../../language/variables.md) and [C libraries](../../interop/c-libraries.md).

## E1431

```text
{what} has no form for {type}: math's functions take floats, and f32s where they have an f32 form ({conv} converts)
```

A `math` function is called on a narrow float it has no form for. `{what}` is the call (`math.log1p()`, or a vector's method such as `tan()`), `{type}` the argument's type and `{conv}` the conversion that makes the call valid. `math`'s functions compute on `float` (64 bits). Some have a form for `f32` as well (`exp`, `expm1`, `log`, `sin`, `cos`, `tanh`, `pow`); none has one for `f16`.

```jac
# expect: E1431
import math;

with entry {
    x: f32 = 0.5;
    print(math.log1p(x));
}
```

**Fix:** convert the argument, and convert the result back if an `f32` is wanted: `math.log1p(float(x))`. For a vector, `simd[float, 4](v).tan()`.

## E1445

```text
{what} is a bit cast of {kinds}, keeping the lanes and their width, not of {type}
```

A vector's bit cast is asked of lanes it does not apply to. `{what}` is the method (`as_float()` or `as_bits()`), `{kinds}` the vectors it takes and `{type}` the vector it was called on. `as_float()` reinterprets 32- or 64-bit int lanes as `f32` or `float`: 16 bits could be an `f16` or a `bf16`, so a 16-bit vector has no one float to become.

```jac
# expect: E1445
with entry {
    v = simd[i16, 4](1);
    print(v.as_float());
}
```

**Fix:** cast a vector of 32- or 64-bit ints (`simd[i32, 4](1).as_float()`). To convert values rather than reinterpret bits, construct the vector type from the other: `simd[f32, 4](v)`.

## E1446

```text
axis {axis} is out of range for a tensor of {rank} dimensions
```

A view operation names an axis the tensor does not have. `{axis}` is the axis written and `{rank}` the tensor's number of dimensions. Axes count from 0, and a negative axis counts from the last (`-1`), so a tensor of 2 dimensions has axes -2 to 1.

```jac
# expect: E1446
import from accel { tensor }

with entry {
    m = tensor[f32, 2, 3](fill=1.0);
    print(m.transpose(0, 2));
}
```

**Fix:** name axes within the tensor's rank: `m.transpose(1, 0)`.

## E1447

```text
axis {axis} is repeated in transpose's axes
```

`transpose()` is given the same axis twice. `{axis}` is the repeated axis. A transpose's arguments are a permutation: each axis of the tensor once.

```jac
# expect: E1447
import from accel { tensor }

with entry {
    m = tensor[f32, 2, 3](fill=1.0);
    print(m.transpose(1, 1));
}
```

**Fix:** list every axis once (`m.transpose(1, 0)`), or pass no arguments to reverse them (`m.transpose()`).

## E1448

```text
cannot reshape a tensor of {count} elements into shape {shape}
```

`reshape()` asks for a shape that holds another number of elements than the tensor has. `{count}` is the tensor's element count and `{shape}` the shape asked for. The check runs when both are known at compile time.

```jac
# expect: E1448
import from accel { tensor }

with entry {
    m = tensor[f32, 2, 3](fill=1.0);
    print(m.reshape(4, 2));
}
```

**Fix:** ask for a shape with the same count (`m.reshape(3, 2)`), or write `-1` for one dimension and let the others decide it (`m.reshape(-1, 2)`).

## E1449

```text
a reshape's dimensions are sizes, and one -1 at most for what the others leave, not {dims}
```

`reshape()` is given a negative size other than a single `-1`. `{dims}` is the shape as written. `-1` stands for "whatever the other dimensions leave", which only one dimension can be.

```jac
# expect: E1449
import from accel { tensor }

with entry {
    m = tensor[f32, 2, 3](fill=1.0);
    print(m.reshape(-1, -1));
}
```

**Fix:** state all dimensions but one: `m.reshape(-1, 2)`.

## E1450

```text
{what}: dimension {axis} of {size} does not divide by {by}
```

A tensor is divided into parts that do not fit it evenly. `{what}` is the operation (`split()`, `blocks()`), `{axis}` the dimension, `{size}` its size and `{by}` the number of parts or the block's extent. Every part has the same shape, so the size must divide.

```jac
# expect: E1450
import from accel { tensor }

with entry {
    m = tensor[f32, 2, 3](fill=1.0);
    print(m.split(4));
}
```

**Fix:** divide by a number the dimension is a multiple of: `m.split(2)` gives two parts of one row each, and `m.split(3, axis=1)` three of one column each.

## E1451

```text
a slice's step is not zero
```

A slice of a tensor is written with a step of 0, as in `m[::0]`. A step of 0 selects nothing and never advances; Python raises `ValueError` for it when the program runs, and here it is refused when the step is a literal.

```jac
# expect: E1451
import from accel { tensor }

with entry {
    m = tensor[f32, 2, 3](fill=1.0);
    print(m[::0]);
}
```

**Fix:** use a step other than zero: `m[::2]` for every second row, `m[::-1]` for the rows in reverse.

## E1452

```text
'{name}' is {type}, as its first binding made it, and is bound here to {found}: a local has one type, so {remedy}
```

A local is bound to a value of another type than its first binding gave it. `{name}` is the local, `{type}` the type it has, `{found}` the type of the new value and `{remedy}` what to write. In Python and in the reference design a name can hold an int and later a str; here a local has one type, wherever the second binding is: an assignment, a branch, a loop target, an unpacking, a `:=`, a `with ... as`, or after a `del`. An int local does not become a float either.

```jac
# expect: E1452
with entry {
    x = 1;
    x = "one";
    print(x);
}
```

**Fix:** declare the type where the local is first bound, as the message says: the type that takes both values, or their union. Or use a second name.

```jac
with entry {
    x: int | str = 1;
    x = "one";
    print(x);
    v: float = 1;
    v = 2.5;
    print(v);
}
```

```output
one
2.5
```

## E1453

```text
'{name}' is a local already: `except ... as {name}` binds a name of the clause's own, which Python unbinds when the clause ends
```

An `except ... as` clause names a local the function already has. `{name}` is the name. The clause binds a name of its own and Python unbinds it when the clause ends, which would delete the earlier local.

```jac
# expect: E1453
with entry {
    e = 1;
    try {
        print(e);
    } except ValueError as e {
        print("caught");
    }
}
```

**Fix:** give the exception a name nothing else uses: `except ValueError as err`. See [Exceptions](../../language/exceptions.md).

## E1454

```text
'{name}' is declared a local here, after line {line} used {outer} of that name: a name is one variable in a function, so declare the local before its first use, or give it another name
```

An annotation declares a local of a name the function has already used as an outer variable. `{name}` is the name, `{line}` the line of that first use, and `{outer}` is `the global` or `the enclosing function's local`. An unannotated assignment or a read of a name that a global or an enclosing function has is that outer variable; an annotation makes a new local. Both in one function would make the name two variables, one above the annotation and one below.

```jac
# expect: E1454
glob count = 0;

def tally {
    count = 4;
    count: int = 9;
    print(count);
}
```

**Fix:** declare the local before the function's first use of the name, so that every use of it is the local, or give the local a name of its own. See [Variables](../../language/variables.md#scope).

## E1465

```text
an access's alignment is a compile-time power of two, at most 2**32, not {found}
```

The `align=` of a pointer's `load()`, `store()` or `vector()` is not a power of two from 1 to 2**32. `{found}` is the value written. The alignment is a compile-time int: it tells the processor what address boundary the access may assume.

```jac
# expect: E1465
import from c {
    def calloc(n: int, size: int) -> ptr[u8];
}

with entry {
    f = ptr[f32](calloc(4, 4));
    print(f.load(0, align=3));
}
```

**Fix:** give a power of two the memory really has: `f.load(0, align=4)`.

## E1466

```text
{what} with no align, volatile or nontemporal reaches memory as indexing the ptr does: write {index}
```

A pointer's `load()` or `store()` is called with none of `align=`, `volatile=` or `nontemporal=`. `{what}` is the call and `{index}` the form to write instead. Without a keyword the access is exactly what indexing does, and there is one spelling for it.

```jac
# expect: E1466
import from c {
    def calloc(n: int, size: int) -> ptr[u8];
}

with entry {
    f = ptr[f32](calloc(4, 4));
    f.store(0, 1.0);
}
```

**Fix:** index the pointer: `f[0] = 1.0;` to write and `f[0]` to read. Keep `load()` and `store()` for an access that states its alignment or is volatile or nontemporal: `f.store(0, 1.0, align=4);`.

## E1467

```text
{what} reads or writes a number, a bool or a pointer, not {type}: a C record or a struct is reached in place, through p[i]
```

A pointer's `load()` or `store()` is asked to move a whole C record or struct. `{what}` is the call and `{type}` the pointer's element type. These calls move one number, bool or pointer; a record is not copied out, it is reached where it lies.

```jac
# expect: E1467
import from c {
    obj Pair {
        has a: i32,
            b: f32;
    }

    def calloc(n: int, size: int) -> ptr[u8];
}

with entry {
    pairs = ptr[Pair](calloc(2, 8));
    print(pairs.load(0, align=4));
}
```

**Fix:** index the pointer and read or write the record's fields in place: `pairs[0].a`.
