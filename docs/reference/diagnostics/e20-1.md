# E2009 to E2088: declarations, impls and misplaced statements

These codes report a module's declarations that do not fit together: an `impl` with no declaration or a second body, a type, base or trigger that names nothing, a name declared twice, a function with no body anywhere. The rest report a statement written outside the only place it means something: walker statements outside abilities, `await` outside an async function, a `graph import` outside `archwire.jac`. See [Impl](../../language/impl.md) (`jac docs impl`), [Functions](../../language/functions.md) and [Abilities](../../language/abilities.md).

## E2009

```text
impl of '{name}' matches no declaration
```

An `impl` names a function or a method that is not declared. `{name}` is the name the impl gives, with its class for a method (`Counter.reset`). An impl supplies the body of a declaration; it does not declare anything. A misspelled name is the usual cause.

```jac
# expect: E2009
def twice(x: int) -> int;

impl twise(x: int) -> int {
    return 2 * x;
}

with entry {
    print(1);
}
```

**Fix:** name the declaration exactly, or declare the function first (in its class, for a method).

```jac
def twice(x: int) -> int;

impl twice(x: int) -> int {
    return 2 * x;
}

with entry {
    print(twice(4));
}
```

```output
8
```

## E2016

```text
impl of '{name}', whose declaration has a body
```

An `impl` is written for a function whose declaration already has a body. `{name}` is the function. A function has one body: either inline in its declaration, or in an impl of a declaration that ends in `;`.

```jac
# expect: E2016
def twice(x: int) -> int {
    return 2 * x;
}

impl twice(x: int) -> int {
    return x + x;
}

with entry {
    print(twice(1));
}
```

**Fix:** keep one body. To keep the impl, end the declaration with `;`: `def twice(x: int) -> int;`.

## E2017

```text
'{name}' has an impl already
```

A second `impl` is written for the same declaration. `{name}` is the function.

```jac
# expect: E2017
def twice(x: int) -> int;

impl twice(x: int) -> int {
    return 2 * x;
}

impl twice(x: int) -> int {
    return x + x;
}

with entry {
    print(twice(1));
}
```

**Fix:** delete one of them. Look in the module's annexes too (`main.impl.jac`, `impl/main.impl.jac`), which hold impls of the same module.

## E2018

```text
unknown {what} '{name}'
```

A type names a class that is not declared or imported, or a `sem` names nothing it could describe. `{what}` says where the name stands (`type`, `base`, `node` for an edge's endpoint, `trigger type` for an ability's `with X entry`, `sem target` for a `sem` that names no function, parameter or field) and `{name}` is the name.

```jac
# expect: E2018
def area(s: Shape) -> float {
    return 0.0;
}

with entry {
    print(1);
}
```

**Fix:** declare the class, import it, or correct the spelling.

The reference design's ability trigger `` with `root entry `` is this code too, as `unknown trigger type 'root'`: a trigger is a type, and the root node's type is `Root`.

```jac
# expect: E2018
walker Hello {
    can start with `root entry {
        print("at root");
    }
}

with entry {
    root spawn Hello();
}
```

**Fix:** name the type: `can start with Root entry`. See [Coming from the reference design](../../start/coming-from-the-reference-design.md).

## E2036

```text
'{name}' is already declared
```

A module declares the same name twice: two functions, two classes, a global and a function. `{name}` is the name. In Python a later `def` replaces an earlier one, and some languages overload a name by its parameter types; here a module's name has one declaration.

```jac
# expect: E2036
def twice(x: int) -> int {
    return 2 * x;
}

def twice(x: float) -> float {
    return 2.0 * x;
}

with entry {
    print(twice(1));
}
```

**Fix:** give each declaration its own name, or write one generic function (`def twice[T: Number](x: T) -> T`).

```jac
def twice(x: int) -> int {
    return 2 * x;
}

def twice_float(x: float) -> float {
    return 2.0 * x;
}

with entry {
    print(twice(1), twice_float(1.0));
}
```

```output
2 2.0
```

## E2083

```text
visit, report, skip and disengage belong in abilities
```

`visit`, `report`, `skip` or `disengage` is written in a function or a method rather than in an ability (a `can ... with X entry` of a walker or a node). These statements steer a walker as it moves through the graph, so they have a meaning only while a walker is visiting. See [Walker control](../../language/walker-control.md).

```jac
# expect: E2083
def stop {
    disengage;
}

with entry {
    stop();
}
```

**Fix:** write the statement in an ability.

```jac
walker Tour {
    can stop with Root entry {
        print("at root");
        disengage;
    }
}

with entry {
    root spawn Tour();
}
```

```output
at root
```

## E2084

```text
an expression statement ends with ';'
```

A block's last statement is an expression with no `;` after it, in a function that returns
nothing. Every statement ends with `;`, the last one in a block too. Where the function returns a
value, the same expression is [E0159](e01-2.md): a value is returned with `return`.

```jac
# expect: E2084
def show(x: int) {
    print(x)
}

with entry {
    show(1);
}
```

**Fix:** end it with `;`. `jac fmt --fix` does. See
[Lexical structure](../../language/lexical-structure.md).

```jac
def show(x: int) {
    print(x);
}

with entry {
    show(1);
}
```

```output
1
```

## E2085

```text
'await' is only valid inside an 'async' function or ability
```

`await` is written in a function or an ability that is not `async`. Only an `async` function can wait for another task. See [Async](../../language/async.md).

```jac
# expect: E2085
async def fetch -> int {
    return 1;
}

def total -> int {
    return await fetch();
}

with entry {
    print(1);
}
```

**Fix:** declare the function `async`: `async def total -> int { return await fetch(); }`.

## E2086

```text
edge '{name}' must name its endpoints: edge {name}: A --> B
```

An edge archetype is declared without its endpoints. `{name}` is the edge. In the reference design an edge connects any two nodes; here an edge names the node types it goes from and to, as `edge Road: City --> City`, so that the program knows what is at each end. See [Edges](../../language/edges.md).

```jac
# expect: E2086
edge Road {
    has km: int = 0;
}

with entry {
    print(1);
}
```

**Fix:** name the endpoints, with `|` between several node types on one side.

```jac
node City {
    has name: str = "";
}

edge Road: City --> City {
    has km: int = 0;
}

with entry {
    print(1);
}
```

```output
1
```

## E2087

```text
'{name}' has no body
```

A function or a method is declared with `;` in place of a body, and no `impl` gives it one: not in the module, nor in its annexes. `{name}` is the function. A declaration without a body is valid only as an abstract method (`abst`) or a C function.

```jac
# expect: E2087
def twice(x: int) -> int;

with entry {
    print(twice(1));
}
```

**Fix:** write the body in the declaration, or an `impl twice(x: int) -> int { ... }` in the module or its annex.

## E2088

```text
'graph {section}' is only valid in a file named archwire.jac
```

A `graph import`, `graph layers` or `graph spaces` block is written in a module that is not named `archwire.jac`. `{section}` is `import`, `layers` or `spaces`. Those blocks describe a whole project, and a project has them in one file at its root. See [Import wiring](../../language/modules-wiring.md) and [The archwire's spaces](../../apps/archwire.md).

```jac
# expect: E2088
graph import {
    util ++> main { now }
}

with entry {
    print(1);
}
```

**Fix:** move the block into `archwire.jac` beside the project's `jac.toml`, or write an ordinary `import from util { now }` in the module.
