# E2226 on: a package's `[packages]`, its version and what it was written for

These codes hold a `jac.toml` to the one table a package declares its packages in, and to what a
version is ([Jac packages](../../toolchain/packages.md#jac-packages)). Each needs a project of several
files, so the examples are not checked one by one; each was checked by hand.

## E2226

```text
jac.toml's [{table}] is no table of a package's: a package declares the packages it uses, libraries and plugins alike, in [packages]
```

A `jac.toml` has a `[libraries]` or a `[plugins]` table. `{table}` is the one it has. A package's
packages are declared in one table, `[packages]`, and which kind each is its own `jac.toml` says.

```toml
[project]
name = "shop"

[libraries]
shapes = { path = "../shapes" }
```

reports, at the table:

```text
jac.toml:4:1: error[E2226]: jac.toml's [libraries] is no table of a package's: a package declares the packages it uses, libraries and plugins alike, in [packages]
```

**Fix:** name the table `[packages]`, and move a `[plugins]` table's lines into it.

## E2227

```text
the plugin '{name}' is declared and never used: no binding names it and no abstraction lists it, so bind it or take it out of [packages]
```

A project's `[packages]` declares a plugin that nothing uses. `{name}` is the plugin. A plugin is
used where `plugin = "<name>"` names it or a table `[<abstraction>.<name>]` lists it, for the
project or for a space, or where the `ui` plugin a space is built with names it as its bundler.
`[packages]` does not say which of its packages are plugins, so one that is declared is one that
is used.

```toml
[project]
name = "shop"

[packages]
jsonstore = { path = "../jsonstore" }
```

reports, at that line:

```text
jac.toml:5:1: error[E2227]: the plugin 'jsonstore' is declared and never used: no binding names it and no abstraction lists it, so bind it or take it out of [packages]
```

**Fix:** list the plugin under the abstraction it fills, `[store.jsonstore]`, or take its line
out.

## E2228

```text
{what} is '{text}', which is not {form}
```

A `jac.toml` writes a version, or a requirement of one, that is not one. `{what}` is what was
written, `{text}` its text and `{form}` the form it has to have.

- A package's `[project] version` is a version as [Semantic Versioning](https://semver.org) has
  it: three numbers, `MAJOR.MINOR.PATCH`, none with a leading zero, and after them an optional
  pre-release (`-rc.1`) and build (`+linux`).
- A package's `[project] jac` is the least version of jac it builds with, in the form of a
  requirement: `"0.4"` or `"0.4.1"`.
- A string in `[packages]` is a requirement: one, two or three of those numbers, the least
  version asked for, and after three an optional pre-release. There is no operator and no range
  ([Versions](../../toolchain/packages.md#versions)).

```toml
[project]
name = "shapes"
kind = "library"
version = "0.1"
```

reports, at that line:

```text
jac.toml:4:1: error[E2228]: the version of the library 'shapes' is '0.1', which is not a version, `MAJOR.MINOR.PATCH` as Semantic Versioning has it
```

**Fix:** write all three numbers, `version = "0.1.0"`.

```toml
[packages]
grid = "^1.2"
```

reports:

```text
jac.toml:5:1: error[E2228]: [packages] grid is '^1.2', which is not a version requirement, `"1"`, `"1.2"` or `"1.2.3"`: the least version asked for
```

**Fix:** write the least version, `grid = "1.2"`, which is what `^1.2` means elsewhere. A place
is a table: `grid = { path = "../grid" }`.

## E2229

```text
{package} needs jac {wanted} or later, and this is jac {have}
```

A package's `[project] jac` names a later jac than the one that is building it. `{package}`
is the package (the project, a library or a plugin), `{wanted}` the least version it says it
builds with and `{have}` this jac's. The key is a least version and no more. It is reported at
the package's own `jac.toml`, since it is the package and not its user that says it.

```toml
[project]
name = "cells"
kind = "library"
version = "0.3.2"
jac = "0.5"
```

reports, under jac 0.4.2:

```text
eco/jac/cells/jac.toml:5:1: error[E2229]: the library 'cells' needs jac 0.5.0 or later, and this is jac 0.4.2
```

**Fix:** build with that jac or a later one, or use a version of the package that this jac
builds. A jac built from source has no version of its own to compare, and refuses none.

## E2230

```text
the plugin '{name}' was written for version {written} of `{abstraction}`'s interface, and this jac's is version {number}: use a version of the plugin that was written for it
```

A plugin's `[plugin] interface_ver` is not the version of its abstraction's interface in this
jac. `{name}` is the plugin, `{written}` the version it says, `{abstraction}` what it fills and
`{number}` this jac's. An interface's version goes up when it changes so that a plugin written
for it would not survive, so a plugin for another version is not asked whether its class
conforms: it would not, in ways that say less than this
([The abstractions](../../apps/plugins.md#the-abstractions)). It is reported where the project
declares the plugin, or at its binding for a plugin jac ships.

```toml
[project]
name = "postgres"
kind = "plugin"
version = "0.4.1"

[plugin]
fills = "store"
interface_ver = 2
class = "postgres.store.PostgresStore"
```

reports, in a project that declares it, under a jac whose `store` interface is at version 1:

```text
jac.toml:5:1: error[E2230]: the plugin 'postgres' was written for version 2 of `store`'s interface, and this jac's is version 1: use a version of the plugin that was written for it
```

**Fix:** use a version of the plugin written for this jac's interface, or the jac the
plugin was written for. A plugin that says no `interface_ver` is E2216.

## E2231

```text
{whose} would be given its settings by the environment variable {variable}, which jac reads for itself: rename it
```

`archwire.jac` declares an app or a space whose name forms an environment variable that jac or a
program's runtime reads for itself. `{whose}` is the app or the space and `{variable}` the
variable. An app's own settings are given where it runs by `JAC_<NAME>` variables
(`JAC_<APP>_LISTEN`, `JAC_REMOTE_<SPACE>`), and jac's own variables have the same prefix, so a
name that would make the two one variable is refused
([Environment variables](../environment.md#names-an-app-may-not-take)).

<!-- example: not checked: an archwire is one file of a project -->
```jac
graph spaces {
    space api: native { entry svc; }

    app dev { run api; }
}
```

reports, at the app:

```text
archwire.jac:4:5: error[E2231]: app 'dev' would be given its settings by the environment variable JAC_DEV_LISTEN, which jac reads for itself: rename it
```

**Fix:** name the app or the space otherwise.

## E2232

```text
{package} imports '{module}': {may} `common.contract`, the libraries its own jac.toml declares and the standard library, and nothing else of jac's
```

A module of a plugin imports something of jac's that a plugin may not: a module of stdjac, or
the contract of an abstraction the plugin does not fill. `{package}` is the plugin, `{module}`
what it imports, and `{may}` what one of its kind imports. A plugin is written against its
abstraction's contract alone (`store.contract` for a plugin of `store`) and against
`common.contract`, which every plugin may use. What it needs of the program that runs it, it is
given: its `open` is handed the program as a `Host`
([What a plugin imports](../../apps/plugins.md#what-a-plugin-imports)). So a plugin and the
program above it meet at the contract, and one may change without the other.

A library a plugin declares is held to the same: a plugin does not reach stdjac through one. Its
`{package}` is the library and the plugin that uses it, and it imports no abstraction's contract
but `common.contract`.

<!-- example: not checked: a plugin is a package of its own, which a project binds -->
```jac
import os;
import from stdjac.plan { data_dir }
import from store.contract { Row, Store }
```

reports, in the `store` plugin `jsonstore`:

```text
store.jac:2:13: error[E2232]: the plugin 'jsonstore' imports 'stdjac.plan': a plugin of `store` imports `store.contract`, `common.contract`, the libraries its own jac.toml declares and the standard library, and nothing else of jac's
```

**Fix:** take what the import gave from the contract, or from the host the plugin's `open` is
given: `host.data_dir()` in place of `stdjac.plan`'s `data_dir()`.
