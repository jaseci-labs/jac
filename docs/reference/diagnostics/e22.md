# E2201 to E2213: layers, and what an edge rule says

These codes hold a project's `archwire.jac` to what the project is: every module in exactly one [layer](../../language/modules-layers.md), no two layers taking from each other, and every [edge rule](../../language/modules-wiring.md#edge-rules) saying only what the wires do.

Each needs a project of several files, so the examples are not checked one by one; each was checked by hand. Unless an entry says otherwise, the project is:

```text
jac.toml         [project] name = "shop"
archwire.jac     the wiring shown in the entry
core/clock.jac   declares now()
core/util.jac    declares tick()
app/view.jac     declares show()
main.jac         calls now()
```

An entry that shows only a `graph import` block is under these layers:

<!-- example: not checked: an archwire is one file of a project -->
```jac
graph layers {
    layer clock { core.clock; }
    layer util { core.util; }
    layer views { app.view; }
    layer program { main; }
}
```

## E2201

```text
'{module}' is in no layer: every module archwire.jac governs is in exactly one
```

`{module}` is in none of the layers `archwire.jac` declares. It is reported for a module a wire names and for a module a build loads; `jac arch` reports it for every module `archwire.jac` names.

<!-- example: not checked: an archwire is one file of a project -->
```jac
graph layers {
    layer base { core.clock; }
    layer top { main; }
}

graph import {
    edge Base: base --> top;

    core.clock ++> app.view | main { now }
}
```

reports:

```text
archwire.jac:9:20: error[E2201]: 'app.view' is in no layer: every module archwire.jac governs is in exactly one
```

**Fix:** name the module in the layer it belongs to.

## E2202

```text
'{module}' is in layer '{first}' and in layer '{second}': a module is in exactly one
```

Two layers' patterns match the same module. `{module}` is the module, or the pattern, they share. A more specific pattern does not win over a wider one: `core.*` in one layer and `core.clock` in another is `core.clock` in both.

<!-- example: not checked: an archwire is one file of a project -->
```jac
graph layers {
    layer base { core.clock; }
    layer wide { core.*; }
    layer top { main | app.view; }
}
```

reports:

```text
archwire.jac:3:18: error[E2202]: 'core.clock' is in layer 'base' and in layer 'wide': a module is in exactly one
```

**Fix:** name each module in one layer. A layer that takes the rest of a package names the rest.

## E2203

```text
layer '{name}' holds no module and no layer
```

A layer is declared with nothing in it.

<!-- example: not checked: an archwire is one file of a project -->
```jac
graph layers {
    layer base { core.*; }
    layer hollow {}
    layer top { main | app.view; }
}
```

reports `layer 'hollow' holds no module and no layer`.

**Fix:** name what the layer holds, or delete it.

## E2204

```text
layers take from each other in a cycle: {path}
```

Wires go round a cycle of layers. `{path}` is the cycle, a step for each pair of layers with one wire that makes it: `mid --> low (core.util --> core.base)`. The layers inside one layer are held to this among themselves, and so are a layer's own modules and the layers it holds. The top-level packages of a project that declares no layers are not.

<!-- example: not checked: an archwire is one file of a project -->
```jac
graph layers {
    layer low { core.clock; }
    layer high { core.util | main | app.view; }
}

graph import {
    edge Up: low --> high;
    edge Down: high --> low;

    core.clock ++> main { now }
    core.util ++> core.clock { tick }
}
```

reports:

```text
archwire.jac:11:19: error[E2204]: layers take from each other in a cycle: low --> high (core.clock --> main); high --> low (core.util --> core.clock)
```

**Fix:** move the module that is in the wrong layer, or what it needs into a layer both may take from.

## E2205

```text
edge rule '{name}' admits nothing the project imports: no wire and no import is one it names
```

No wire, and no import written in a module, is one the rule admits. A rule over wires is judged in every build. A rule whose source is imported in modules' own text is judged when every module of the layers it targets was loaded, and by `jac arch`.

<!-- example: not checked: an archwire is one file of a project -->
```jac
graph import {
    edge Clock: clock --> program;
    edge Views: clock --> views;

    core.clock ++> main { now }
}
```

reports `edge rule 'Views' admits nothing the project imports: no wire and no import is one it names`.

**Fix:** delete the rule, or write the wire it was for.

## E2206

```text
edge rule '{name}': no wire or import it admits matches {what}
```

The rule is used, and one of the layers it names is not. `{what}` is the layer: `source pattern 'util'` or `target pattern 'views'`.

<!-- example: not checked: an archwire is one file of a project -->
```jac
graph import {
    edge Core: clock | util --> views | program;

    core.clock ++> main { now }
}
```

reports both `source pattern 'util'` and `target pattern 'views'`.

**Fix:** delete the layer from the rule.

## E2207

```text
edge rule '{name}' lists '{item}', which no wire or import it admits carries
```

A rule with a payload lists a name that nothing it admits brings across.

<!-- example: not checked: an archwire is one file of a project -->
```jac
graph import {
    edge Clock: clock --> program { now, later }

    core.clock ++> main { now }
}
```

reports `edge rule 'Clock' lists 'later', which no wire or import it admits carries`.

**Fix:** delete the name from the payload.

## E2208

```text
{what} across '{provider} --> {consumer}' is admitted by {rules}: one rule admits each flow
```

More than one rule admits the same flow. `{what}` is `the wire`, when two rules name the two layers of one level it crosses, or `the import`, when two rules admit an import from outside into the module's layer. `{rules}` are the rules.

<!-- example: not checked: an archwire is one file of a project -->
```jac
graph import {
    edge Clock: clock --> program;
    edge Time: clock | util --> program;

    core.clock ++> main { now }
    core.util ++> main { tick }
}
```

reports:

```text
archwire.jac:11:20: error[E2208]: the wire across 'core.clock --> main' is admitted by rule 'Clock', rule 'Time': one rule admits each flow
```

**Fix:** delete the rule that says less, or take the layer out of one of them.

## E2209

```text
a docstring in archwire.jac is one line of at most {limit} characters: this one {has}
```

A docstring on a layer, an edge rule, a space or an app is too long. `{limit}` is 120 and `{has}` says how it is over: `has 138 characters` or `spans 2 lines`. It is the words in a box of the picture `jac arch` draws. See [Docstrings](../../language/modules-wiring.md#docstrings).

<!-- example: not checked: an archwire is one file of a project -->
```jac
graph import {
    """The clock feeds
    the program."""
    edge Clock: clock --> program;

    core.clock ++> main { now }
}
```

reports `a docstring in archwire.jac is one line of at most 120 characters: this one spans 2 lines`.

**Fix:** say it in one line. What needs more belongs in the module's own docstring or the project's documentation.

## E2210

```text
edge rule '{name}': {what} names modules, and a rule is between layers: the wires say which modules
```

A rule names a module or a package. `{name}` is the rule and `{what}` the pattern (`source pattern 'core.clock'`). The wires already say which module takes from which, so a rule over modules could only repeat one; a rule says which layers may. A rule in a scoped block (`graph import core { ... }`) names only modules, so it is always this error there. The source of a rule over an import from outside the project is the package, and is not reported. See [Rules between layers](../../language/modules-layers.md#rules-between-layers).

<!-- example: not checked: an archwire is one file of a project -->
```jac
graph layers {
    layer base { core.*; }
    layer top { main; }
}

graph import {
    edge Base: base --> top;
    edge Clock: core.clock --> top;

    core.clock ++> main { now }
}
```

reports:

```text
archwire.jac:8:17: error[E2210]: edge rule 'Clock': source pattern 'core.clock' names modules, and a rule is between layers: the wires say which modules
```

**Fix:** name the layer. To hold one module to a rule of its own, give it a layer of its own inside the one it is in, and state the rule between the two.

## E2211

```text
'{consumer}' imports '{package}' from outside the project, and no edge rule admits it: jac.toml's [check] imports asks a rule for each; add `{rule}`
```

A module imports something that is not a module of the project, no edge rule admits it, and the project's `jac.toml` has `imports = "ruled"` under `[check]`. `{consumer}` is the module, `{package}` what it imports and `{rule}` a rule that would admit it. See [A rule for every import from outside](../../language/modules-wiring.md#a-rule-for-every-import-from-outside).

With `jac.toml`:

```toml
[project]
name = "shop"

[check]
imports = "ruled"
```

a `main.jac` that begins `import sys;` under an `archwire.jac` with no rule over `sys` reports:

```text
main.jac:1:8: error[E2211]: 'main' imports 'sys' from outside the project, and no edge rule admits it: jac.toml's [check] imports asks a rule for each; add `edge Sys: sys --> main;`
```

**Fix:** add the rule the message gives, or take the import out of the module.

## E2212

```text
layer '{name}' holds layers and modules of its own: a layer holds one or the other, so give its modules a layer
```

A layer holds other layers and also names modules directly. A layer is a group of modules or a group of layers: a rule has then a layer to name at every level, and a picture's boxes are all of one kind. See [What a layer holds](../../language/modules-layers.md#what-a-layer-holds).

<!-- example: not checked: an archwire is one file of a project -->
```jac
graph layers {
    layer platform {
        layer time { core.clock; }

        core.host;
    }
}
```

reports `layer 'platform' holds layers and modules of its own: a layer holds one or the other, so give its modules a layer`.

**Fix:** put the modules in a layer of their own inside it: `layer machine { core.host; }`.

## E2213

```text
archwire.jac declares no layer: every module it governs is in one, so add a `graph layers` block
```

An `archwire.jac` has no `graph layers` block. It is reported once for the file, and not once for each module it governs. Every module under an `archwire.jac` is in a layer: the layers are what its edge rules name and what `jac arch` draws. See [Layers](../../language/modules-layers.md).

<!-- example: not checked: an archwire is one file of a project -->
```jac
graph import {
    core.clock ++> main { now }
}
```

reports:

```text
archwire.jac:1:1: error[E2213]: archwire.jac declares no layer: every module it governs is in one, so add a `graph layers` block
```

**Fix:** declare the layers. A project with no layering to state yet declares one that holds every module, and its wires then need no rule:

<!-- example: not checked: an archwire is one file of a project -->
```jac
graph layers {
    layer all { *; }
}

graph import {
    core.clock ++> main { now }
}
```
