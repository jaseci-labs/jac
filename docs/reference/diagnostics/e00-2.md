# E0050 to E0099: declarations and wiring

These codes cover the order of a parameter list, `break` and `continue` outside a loop, a name
given twice (a keyword argument, a member), the shape of a property, what `del` and `return tail`
accept, and the syntax of a `graph import` block. In a template, `{name}` is filled in when the
error is reported.

The codes about wires and edge rules (E0086 to E0096, E0098, E0099) are reported on a project's
`archwire.jac`, always together with E2093, which says once that the file has syntax errors. Their
entries show the refused line instead of a whole program; [archwire](../../apps/archwire.md)
(`jac docs archwire`) describes the file. In those entries, a wire is a line such as
`util ++> main { now }`, which injects the name `now` of the provider module `util` into the
consumer module `main`, and an edge rule is a line such as `edge Util: util --> main;`, which says
that the layer `main` may take from the layer `util`.

## E0050

```text
duplicate '{param}' in a parameter list
```

A parameter list has two `*` markers, two `/` markers, or two parameters of one name. `{param}` is
`*`, `/` or the name. A bare `*` and a `*args` parameter both count as the `*`, so a list has at
most one of them.

```jac
# expect: E0050 x2
def f(a: int, *, b: int, *, c: int) -> int {
    return a + b + c;
}

def g(a: int, a: int) -> int {
    return a;
}
```

**Fix:** keep one marker, and give each parameter its own name. Every parameter after the `*` is
already keyword-only: `def f(a: int, *, b: int, c: int) -> int`. See
[Functions](../../language/functions.md).

## E0051

```text
'{first}' must come before '{second}' in a parameter list
```

Two parts of a parameter list are in the wrong order. `{first}` and `{second}` are the two parts
as they should be ordered: `/` comes before `*` and before `*args`, and every parameter comes
before `**kwargs`.

```jac
# expect: E0051
def f(a: int, *, b: int, /) -> int {
    return a + b;
}
```

**Fix:** reorder the list: positional-only parameters, `/`, ordinary parameters, `*` or `*args`,
keyword-only parameters, `**kwargs`. See [Functions](../../language/functions.md).

```jac
def f(a: int, /, *, b: int) -> int {
    return a + b;
}
```

## E0052

```text
parameter '{name}' has no type annotation
```

A parameter of a `def` or a `can` is declared without a type. `{name}` is the parameter. Every
parameter of a declared function is typed, `*rest` and `**opts` included; only the receiver, when
it is written (`self`), has none, because it is its class.

```jac
# expect: E0052
def double(x) -> int {
    return x * 2;
}
```

**Fix:** write the type after the name: `def double(x: int) -> int`. A parameter that takes values
of any type is `x: any`. See [Functions](../../language/functions.md).

## E0058

```text
{keyword} outside {scope}
```

`break` or `continue` is written where there is nothing to leave or repeat. `{keyword}` is `break`
or `continue`; `{scope}` is `a loop or switch` for `break` and `a loop` for `continue`.

```jac
# expect: E0058
with entry {
    break;
}
```

**Fix:** use the statement inside a `for` or `while` loop (`break` also inside a `switch`). To
leave a function early, use `return`. See [Control flow](../../language/control-flow.md).

## E0065

```text
{callee} got multiple values for keyword argument '{name}'
```

A call passes the same keyword argument twice. `{callee}` is the function called (`f()`,
`list.sort()`) and `{name}` the keyword.

```jac
# expect: E0065
def f(**kw: int) -> int {
    return len(kw);
}

with entry {
    print(f(a=1, a=2));
}
```

**Fix:** pass each keyword once: `f(a=1, b=2)`. See [Functions](../../language/functions.md).

## E0077

```text
'{name}' is already declared in {owner}
```

Two members of one owner have the same name. `{name}` is the name and `{owner}` what holds both:
an archetype or an enum, by its name, or a `graph spaces` block for two spaces or two apps.

```jac
# expect: E0077
obj A {
    has x: int = 1;
    has x: int = 2;
}
```

**Fix:** remove one declaration or rename it. A field and a method of one archetype share a
namespace, so they need different names too. See [Fields](../../language/fields.md).

## E0080

```text
a property declaration cannot have an initializer
```

A `has` declaration with accessors (`getter`, `setter`, `deleter`) is a property: its value is
computed by the accessors, so it stores nothing and takes no `= value`.

```jac
# expect: E0080
obj A {
    has x: int = 1 {
        getter {
            return 1;
        }
    }
}
```

**Fix:** remove the initializer. If the accessors need storage, keep it in a separate field. See
[Fields](../../language/fields.md).

```jac
obj A {
    has x: int {
        getter {
            return 1;
        }
    }
}

with entry {
    print(A().x);
}
```

## E0081

```text
a property declares at least one of `getter`, `setter` or `deleter`
```

A `has` declaration is followed by braces with no accessor in them.

```jac
# expect: E0081
obj A {
    has x: int {}
}
```

**Fix:** write an accessor in the braces (`getter { return ...; }`), or drop the braces to declare
an ordinary field: `has x: int = 0;`. See [Fields](../../language/fields.md).

## E0083

```text
cannot delete {what}
```

A `del` statement names something that cannot be deleted. `{what}` says what and why:
`this expression` for a target that is not a name, an attribute or an item; `items of a 'tuple'`
for an item of a type that cannot lose one; `'total': only a local name can be deleted here` for a
global or captured name; `'f': it is not a field that can be deleted` for an attribute that is not
a deletable field.

```jac
# expect: E0083
with entry {
    t = (1, 2);
    del t[0];
}
```

**Fix:** delete a local name, or an item of a list or a dict. A tuple cannot change, so build a new
one without the item, or use a list.

```jac
with entry {
    xs = [1, 2];
    del xs[0];
    print(xs);
}
```

## E0086

```text
a wire is directed: write 'provider ++> consumer' or 'provider --> consumer'
```

A wire or an edge rule in `archwire.jac` uses an arrow that points left or both ways: `<--`,
`<-->`, `<++` or `<++>`. It arises for a line such as `util <-- main { now }`. The provider is
always written on the left and the consumer on the right.

**Fix:** put the provider first and use a forward arrow: `util ++> main { now }`. See
[archwire](../../apps/archwire.md).

## E0087

```text
a wire names one provider; patterns belong to an edge rule
```

The left side of a wire is not one module. It arises when the provider is `*`, `any`, a glob such
as `util.*`, or several modules joined with `|`, as in `util | other ++> main { now }`. Patterns
describe sets of modules, which only an edge rule takes.

**Fix:** write one wire per provider module, each naming it in full: `util ++> main { now }`. See
[archwire](../../apps/archwire.md).

## E0088

```text
a wire's consumer is a project module named in full
```

The right side of a wire is not one module's name. It arises when the consumer is `*`, `any`, a
glob such as `main.*`, or a name with `as`, as in `util ++> main.* { now }`.

**Fix:** name each consuming module in full. To wire one provider to several consumers, join them
with `|` (`util ++> main | tools { now }`) or group them in brackets
(`util ++> [main { now }, tools { now }]`). See [archwire](../../apps/archwire.md).

## E0089

```text
'as' applies to the module form of a wire; alias a name inside the payload instead
```

A wire gives its provider an alias and also lists names in a payload, as in
`util as u ++> main { now }`. The alias renames the module where the module itself is wired; a
payload delivers names, not the module, so there is nothing for the alias to name.

**Fix:** to deliver the module under another name, drop the payload: `util as u ++> main;`. To
rename a delivered name, alias it in the payload: `util ++> main { now as tick }`. See
[archwire](../../apps/archwire.md).

## E0090

```text
duplicate '{name}' in a wire payload
```

A payload lists the same name twice, as in `util ++> main { now, now }`. `{name}` is the repeated
name.

**Fix:** list each name once: `util ++> main { now }`. See [archwire](../../apps/archwire.md).

## E0091

```text
'include' takes no payload
```

An `include` wire lists names, as in `include util ++> main { now }`. An `include` wire delivers
the provider's names without listing them, so it has no payload.

**Fix:** drop the payload, `include util ++> main;`, or drop `include` and deliver only the names
listed, `util ++> main { now }`. See [archwire](../../apps/archwire.md).

## E0092

```text
an edge rule is named: 'edge Name: source --> target'
```

An edge rule has no name before its patterns, as in `edge util --> main;`. Diagnostics about a rule
refer to it by this name.

**Fix:** name the rule and follow the name with `:`: `edge Util: util --> main;`. See
[archwire](../../apps/archwire.md).

## E0093

```text
a 'graph import' scope is a dotted package name
```

What stands between `graph import` and `{` is not a package's dotted name. It arises for a string
(`graph import "app" {`), a name with `as`, or any other token.

**Fix:** write the package the block's module names are relative to, `graph import pkg {` or
`graph import pkg.sub {`, or leave the scope out: `graph import {`. See
[archwire](../../apps/archwire.md).

## E0094

```text
expected a wire ('provider --> consumer') or an edge rule, found '{found}'
```

A `graph import` block holds wires and edge rules, and `{found}` is a token that starts neither. A
common cause is a `;` after a wire that ends with a payload or a bracketed group, as in
`util ++> main { now };`.

**Fix:** remove the token. A wire with a payload ends at its `}` and a grouped wire at its `]`;
only a wire with neither, such as `util ++> main;`, ends with `;`. See
[archwire](../../apps/archwire.md).

## E0095

```text
'*' must be the only item in a payload
```

A payload lists `*` beside other names, as in `edge Util: util --> main { *, now }`. `*` already
stands for every name.

**Fix:** in an edge rule, write `{ * }` alone to admit every name, or list the names without `*`.
In a wire, list the names: a wire of `*` is refused (E5090). See
[archwire](../../apps/archwire.md).

## E0096

```text
a rule payload lists names without aliases
```

An edge rule's payload renames a name, as in `edge Util: util --> main { now as n }`. A rule's
payload lists the names the rule admits; an alias belongs to the wire that delivers the name.

**Fix:** list the bare name in the rule, `edge Util: util --> main { now }`, and alias it in the
wire, `util ++> main { now as n }`. See [archwire](../../apps/archwire.md).

## E0097

```text
`return tail` needs a function call
```

`return tail f(args);` returns by calling `f` in the current function's frame. The value after
`return tail` is not a call, or there is no value.

```jac
# expect: E0097
def f(n: int) -> int {
    return tail n;
}
```

**Fix:** follow `return tail` with a call, or write a plain `return`. See
[Functions](../../language/functions.md).

```jac
def count(n: int, acc: int) -> int {
    if n == 0 {
        return acc;
    }
    return tail count(n - 1, acc + 1);
}

with entry {
    print(count(1000000, 0));
}
```

```output
1000000
```

## E0098

```text
'any' is not a pattern: name the modules under this archwire.jac, or in an edge rule the layers
```

A pattern is written `any`: among a layer's modules, among a space's in a `graph spaces` block, or
in an edge rule, as in `edge Open: util --> any;`. Nothing in `archwire.jac` is stated of
everything by that word.

**Fix:** name what is meant. A layer and a space name modules: a module (`util`), a package's
modules (`pkg.*`), several joined with `|` (`util | tools`), or `*` for every module. An edge rule
names layers. See [Layers](../../language/modules-layers.md) and [archwire](../../apps/archwire.md).

## E0099

```text
wiring blocks are written 'graph import'; 'impl import' was removed
```

`archwire.jac` opens its wiring block with `impl import {`, the older Jac spelling.

**Fix:** write `graph import {`. See [archwire](../../apps/archwire.md).
