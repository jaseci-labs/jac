- **Fix: byLLM no longer hard-fails when a model rejects an explicitly-set `temperature`**: `by llm(temperature=...)` (or `[byllm.call_params]`) always forwarded `temperature` to the provider once the caller set it, even for models that reject it outright, e.g. `` `temperature` is deprecated for this model `` from Anthropic, or `Unsupported value: 'temperature'` from OpenAI. `litellm.drop_params` only protects models already in litellm's registry; a newly released model litellm doesn't know about yet still forwards the param and 400s at the provider, killing the turn before a single token is produced. `Model.model_call_no_stream`/`model_call_with_stream` (and their async variants) now retry once with `temperature` stripped when the provider rejects it for this reason, instead of failing the call outright. Surfaced by jaseci-labs/jacBuilder#896 (`claude-fable-5` failing every build instantly).
- **Fix: byLLM no longer silently returns a blank result when a model's content filter blocks the turn**: byLLM's own prompt formatting (an un-dedented system persona, Python-`repr()`-style arguments) could trip stricter models' content filters, e.g. `claude-fable-5`, which then returned an empty completion byLLM read as a normal (if blank) response instead of a blocked one. Prompt formatting is fixed to avoid tripping the filter, a filtered response is now retried automatically, and a still-blocked turn raises `ContentFilteredError` instead of returning silently empty.
